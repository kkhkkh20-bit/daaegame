# 다람탐정 — 이름·문장·강조 타이포그래피 규칙

작성: 2026-10-15 / 용도: 클로드 구현 전달

이 문서는 승인된 클래식 UI에 적용할 **의미와 표시 규칙**이다. 본편을 변경한 결과물이 아니다. 기존 이야기·증거·증언·제시 판정·발견 조건·시간과 경제 규칙은 유지한다. 기존 대사를 모두 다시 쓰는 작업으로 확대하지 않는다. 같은 주제에 대한 이전 시안 설명과 충돌하면 이 문서의 타이포그래피 규칙을 우선한다.

## 1. 구현 목표

플레이어가 문장을 읽는 즉시 발화자, 말/생각/관찰의 차이, 인용된 자료를 구별하게 한다. 강조를 정답 힌트로 사용하지 않는다. 모든 고유명사에 자동으로 색을 칠하거나 모든 대사를 증언으로 등록하지 않는다.

필수 산출:
1. 공통 의미 역할과 화면 표면별 색 토큰.
2. 대화·질문·기록·제시 카드·획득 알림에 동일한 이름/자료 표기.
3. 아빠 생각의 파란색과 괄호가 재열람/타이핑/백로그에서도 일관되게 유지.
4. 현재 폰트에서 지원하지 않는 굵기를 억지로 합성하지 않는 대체 규칙.

동봉 `typography-tokens.json`은 프레임워크 독립적인 명세다. CSS 설정을 Ren'Py에 그대로 붙이거나 새 전역 덮어쓰기 층을 만들라는 지시가 아니다. 최신 ROOM13_GUIDE.md와 OVERRIDE_MAP을 읽고 기존 텍스트 표시 경로에 공통 토큰을 연결한다.

## 2. 의미 역할

| 역할 | 표시 | 유의점 |
|---|---|---|
| 화자 이름표 | 대화창 왼쪽 위, 같은 폭 규칙/높이/패딩 | 아빠·다람이·NPC에 동일 규칙. 인물별 무지개색 금지 |
| 일반 대사 | 크림색, Regular, 괄호 없음 | 아빠가 입으로 말할 때도 동일 |
| 아빠의 생각 | 파란색, Regular, 문장 전체 `(...)` | 이름표는 `아빠`. 별도 얼굴/생각 배지 추가하지 않음 |
| 상황 묘사 | 차분한 밝은 회색, Regular, 이름표/괄호 없음 | 현재 시점에서 관찰 가능한 사실만. None 화자를 생각으로 자동 분류하지 않음 |
| 인물·장소의 필요한 강조 | 첫 소개/지시 대상 구별에 한정해 강조색 | 모든 등장마다 반복 강조하지 않음 |
| 증거·아이템 명칭 | `「예약 원본」`처럼 홑낫표 | 분류/목록 제목에는 명칭 자체가 구분되므로 중복 괄호 생략 가능 |
| 증언 인용 | `“그날은 혼자 들어왔어요.”` | 기본 본문색, Regular. 증언자 이름과 출처는 별도 메타데이터 |
| 짧은 외침·의성어 | strong 의미 역할 | 현재 글꼴에서는 가짜 Bold 대신 기본 굵기 유지. 긴 문장 전체에 적용하지 않음 |
| 비용·상태 | 값/상태에만 emphasis 의미 역할 | 부족/실패에만 오류색. 돈·날짜를 항상 오류색으로 만들지 않음 |

### 화자와 명칭

- 실제 인물 식별은 내부 ID로 하고 화면에는 확정된 표시 이름을 쓴다. `아빠`를 어떤 화면에서는 `다돌`, 어떤 화면에서는 `나`로 임의 변경하지 않는다. 기존 스토리에 의도된 별칭은 유지한다.
- 인물명을 아직 알지 못하는 상황에서는 기존 익명 표시를 쓴다. UI 색칠을 위해 미래에 알게 될 이름을 먼저 노출하지 않는다.
- 대화창 이름표는 말한 사람. 증언 카드의 얼굴/이름은 **그 말을 한 사람**. 중앙의 인물은 **지금 대화하는 상대**다. 이 세 정보를 혼동하지 않는다.
- 장소 이름은 기존 런타임 명칭을 쓴다. 숙소는 여관 2층의 13호실이며 ‘13층’으로 바꾸지 않는다.
- 자료명은 기록 목록/획득 알림/제시 카드/대화 인용에 같은 표시 이름을 쓴다. 조사 상태 변경이나 갱신이 아닌데 다른 이름으로 다시 등록하지 않는다.

## 3. 색은 표면에 따라 다르게

밝은 종이 위에 크림색이나 밝은 금색을 그대로 쓰면 안 된다. 의미 역할은 유지하되 렌더링 표면에 따라 다음 색을 선택한다.

| 역할 | 짙은 녹색 창 위 | 밝은 양피지 위 |
|---|---|---|
| speech / quote / strong | `#F4E7C4` | `#39432C` |
| thought | `#9DC9FF` | `#31576F` |
| narration | `#D1D6C8` | `#555943` |
| entity / emphasis | `#E5C58A` | `#6C512A` |
| metadata / subdued | `#C2C9B5` | `#625738` |
| insufficient / error | `#E4A096` | `#8A3F38` |

- 이름표 글자: `#F6DFAC`. 기존 이름표 바탕과 함께 사용한다.
- 금박 프레임 색과 본문 강조색은 다른 토큰이다. 금박의 어두운 황동색을 녹색 창 위의 작은 본문에 복사하지 않는다.
- 파란색은 생각의 의미에 집중한다. 선택 버튼, 임의의 NPC 대사, ‘중요 증언’ 전체를 생각과 같은 파란색으로 만들지 않는다.
- 생각 문장은 이름/자료가 포함되어도 **전체 파란색**을 우선한다. 생각 안의 `「자료명」`은 표기만 유지하고 금색으로 섞지 않는다.
- 표의 생각 종이색은 백로그/기록에 생각을 재현할 때 쓰는 표면별 대체색이다. 내용 유형을 바꾸는 것이 아니다.
- 반투명 창은 배경에 따라 실제 대비가 달라진다. 작은 글자는 창 전체 opacity를 줄여 흐리지 말고 토큰 색과 글자 뒤의 면을 조절한다. 일반 크기 본문/작은 메타데이터는 실제 합성 결과에서 최소 4.5:1을 목표로 확인한다.

## 4. 폰트 굵기 — 의미와 실제 지원을 분리

현재 Galmuri11은 사용 중인 파일에 별도 Medium/Thin/Bold 변형이 없다. 역할에 500/700이라는 의도가 있어도 현재 렌더링은 400으로 대체한다. `{b}`, text-stroke, 겹쳐 그리기, 브라우저의 가짜 굵기로 픽셀 획을 뭉개지 않는다.

| 의미 역할 | 실제 굵기 파일이 있을 때 | 현재 Galmuri11 |
|---|---:|---:|
| 기본 대사·설명·인용·생각 | Regular 400 | 400 |
| 이름·명칭·상태의 제한적 강조 | Medium 500 | 400 + 강조색/표기 |
| 짧은 외침·의성어 | Bold 700 | 400, 필요하면 짧게 독립 배치 |
| 타이틀/단독 큰 제목 | Bold/Black 700/900, 필요한 경우 | 별도 타이틀 폰트가 실제로 지원할 때만 사용 |
| 부가 정보 | Light 300, 충분한 크기/대비일 때만 | 400 + metadata 색 |

- Thin은 작은 도트 UI에 기본 적용하지 않는다. 가는 획으로 위계를 만들지 않는다.
- Italic은 자동 적용하지 않는다. 필요 장면을 제안하고 사용자에게 별도로 확인한다.
- 실제 굵기 변형이 있는 한국어 글꼴을 도입할 때만 역할 매핑을 바꾼다. 이를 위해 본문 데이터를 다시 수정하게 만들지 않는다.
- CSS 구현이면 `font-synthesis: none`, Ren'Py 구현이면 실제 폰트 매핑이 없는 가짜 bold/italic 옵션을 사용하지 않는다.

## 5. 강조의 양과 추리 보호

1. 대화창 하나에 보통 0~2개의 짧은 강조 구절. 2개를 억지로 채우는 할당량이 아니다.
2. 등장인물/장소는 장면의 첫 소개 또는 누구/어디를 지칭하는지 구별할 때만 강조한다. 익숙한 이름이 반복될 때는 일반색.
3. `혼자`, `두 명`, `그때`, `왼손`, 날짜/시각 등을 **정답과 관련 있다는 이유로** 자동 강조하지 않는다.
4. 빨간색은 거짓말·범인·의심스러운 증언을 표시하지 않는다. 기존 규칙상 불가능한 행동이나 잔액 부족 등 조작 상태에 사용한다.
5. 증언 인용 전체를 금색/볼드로 만들지 않는다. 발언자, 인용 부호, 출처로 구별한다.
6. 제시한 자료를 잘못 골랐다고 문장을 새 스타일로 ‘거짓’ 판정하지 않는다. 기존 반응 분기가 처리한다.
7. AI가 모든 대사를 재해석해 ‘중요 단어’를 대량 삽입하지 않는다. 필요한 장면에 작가가 명시한 의미 span만 적용한다.
8. 물어본 질문은 취소선과 차분한 색으로 표시하되 읽을 수 있어야 한다. 전체 버튼 opacity를 과도하게 낮추는 대신 subdued 글자색과 2px 취소선을 우선한다. 재열람 가능 여부는 기존 동작대로 유지한다.

## 6. 괄호·따옴표와 예시

### 일반 대사

화자: 아빠
본문: `「예약 원본」에는 다람이 이름도 적혀 있습니다.`
표시: 자료명 한 구절만 강조색. 다람이는 이미 알고 있는 인물이므로 이 문장에서 추가로 강조할 필요 없다.

화자: 경비병
본문: `제가 받은 명부에는 한 사람뿐이었어요.`
표시: 전체 일반색. ‘한 사람뿐’이 추리 재료여도 자동 강조하지 않는다.

### 생각

화자: 아빠 / 유형: thought
본문: `원본과 옮겨 쓴 명부가 다르다. 어디서 빠진 거지?`
표시: `(원본과 옮겨 쓴 명부가 다르다. 어디서 빠진 거지?)` 전체 파란색.

원문이 이미 바깥 괄호 한 쌍을 가지고 있으면 중복해서 `((...))`로 만들지 않는다. 문장 내부의 의도된 괄호나 인용까지 삭제하지 않는다. 아빠가 말한다는 이유만으로 thought로 바꾸지 않는다.

### 관찰

화자: 없음 / 유형: narration
본문: `책상 아래에 접힌 종이가 끼어 있다.`
표시: 상황 묘사색. 새로운 추리 결론이나 다음 행동 지시를 붙이지 않는다.

### 증언 카드 / 제시

제목: `까로 · 마차의 상태`
핵심 발언: `“바퀴 축에 금이 갔어.”`
출처: `1일째 · 오후 · 눈에 막힌 입구`

표시: 제목만 강조, 인용은 일반색, 출처는 metadata. 제시 중에는 카드가 유지되며 하단의 화자 이름은 실제 대사 발화자를 따른다.

### 자원

`소지금 0냥` → 숫자/단위만 제한적으로 강조. 잔액이 0이라는 이유만으로 상시 빨간색으로 만들지 않는다.
`3냥 부족` → 불가능한 구매 행동의 상태이므로 오류색. 상태가 해소되면 기본 규칙으로 돌아간다.

위 문장들은 **스타일 적용 예시**다. 이 문서만 보고 기존 스토리 대사를 교체하거나 새 증언/증거를 등록하지 않는다.

## 7. 크기·정렬·패딩 공통 토큰

기준 1280×720 논리 좌표. 이미 승인된 레이아웃 크기가 다르면 전체 UI 배율에 맞춰 조정하되 역할별 개별 임의값을 만들지 않는다.

| 요소 | 기본 크기 | 정렬 / 패딩(상 우 하 좌) |
|---|---:|---|
| 대화 본문 | 24 | 왼쪽 / 20,32,20,32 |
| 화자 이름표 | 18 | 왼쪽 / 6,16,6,16 |
| 짧은 관찰문 | 20 | 왼쪽 / 12,16,12,16 |
| 기록 제목 | 22 | 왼쪽 / 상위 카드 영역 기준 |
| 기록 본문 | 18 | 왼쪽 / 본문 영역 24,24,24,24 |
| 메타데이터 | 14 | 왼쪽 / 메타 영역 8,0,0,0 |
| 질문 선택지 | 20 | 가운데 / 10,20,10,20 |
| 버튼 문구 | 18 | 가운데 / 8,12,8,12 |

- 클래식 창의 테두리 6/8/10/12px는 별도 프레임 토큰. 테두리 때문에 글자 패딩을 두 번 더하지 않는다. 실제 content box를 기준으로 기록한다.
- 같은 역할의 텍스트는 질문/대화/기록 화면에서 같은 토큰을 참조한다. 수정 요청이 오면 공통 토큰을 바꿔 일괄 적용한다.
- 모바일은 글꼴 자체를 임의의 비정수 크기로 쪼개기보다 전체 게임 캔버스 배율과 큰 글자 옵션을 먼저 사용한다. 너무 작은 보조 문구는 대비를 높이거나 접는다.
- 큰 글자 설정에서 이름표·본문·인용을 함께 확인하고 프레임 밖 잘림이 없게 한다. 글자가 길면 줄바꿈/기존 스크롤을 사용한다.
- 선택지 목록의 덩어리는 화면 중앙. 대화창 전체도 가운데 배치하되 이름표와 대화 본문은 왼쪽 정렬. 아빠 얼굴은 추가하지 않는다.

## 8. 데이터·렌더링 연결

권장되는 개념적 입력:

```json
{
  "speaker_id": "dad",
  "text_kind": "speech",
  "segments": [
    {"text": "「예약 원본」", "role": "entity", "entity_id": "existing_record_id"},
    {"text": "에는 다람이 이름도 적혀 있습니다.", "role": "speech"}
  ]
}
```

이 필드명을 그대로 도입할 필요는 없다. 기존 thought 플래그와 텍스트 시스템을 우선 재사용한다. 자동 이름 정규식으로 원문 전체를 치환하는 방식은 피한다.

- 생각 괄호는 표시 경계에서 정확히 한 번 처리하고, 이미 포맷된 문자열을 다시 감싸지 않는다.
- 기록/백로그에는 원문과 의미 정보를 보존한다. 현재의 녹색 창 색상 태그를 그대로 저장해서 양피지 화면에 재사용하지 않는다.
- 순수 텍스트 복사/백로그 검색에는 색상 태그가 노출되지 않는다. Ren'Py 태그는 엔진의 안전한 이스케이프 규칙을 따른다. HTML `<span>`을 대사에 저장하지 않는다.
- 타이핑 속도·효과음 카운트는 **화면에 보이는 문자**를 기준으로 한다. 색상/굵기 태그를 글자 수나 음향 이벤트로 세지 않는다. 타이핑 완료 뒤 소리가 계속 나지 않게 한다.
- 줄바꿈, 빨리 넘기기, 자동 재생, 저장/로드, 백로그에서 역할이 달라지지 않아야 한다.
- 화자가 바뀌거나 생각에서 일반 대사로 돌아오면 파란색/괄호/강조가 다음 문장에 누수되지 않도록 한다.

## 9. AI 시안 같은 느낌을 줄이는 시각 기준

현재 평가는 주관적인 디자인 판단이며 이미지의 생성 여부를 판별하는 기준이 아니다. 도트 글꼴·각진 모서리·장면 중심 배치가 현재 게임에 잘 맞는다. 남은 범용 UI 느낌은 반복되는 같은 금색 틀과 공통 아이콘의 중복에서 생긴다.

- 큰 기록창은 가장 분명한 금박. 대화창은 중간 강도, 작은 HUD/안내창은 한 단계 얇고 덜 밝은 마감. 창마다 새로운 장식 문법을 만들지는 않는다.
- 모든 상자에 동일한 마모/모서리 장식을 복사해 강조하지 않는다. 마모는 큰 도트 몇 군데에만 두고 랜덤 잡티를 늘리지 않는다.
- 서로 다른 중요한 증거가 같은 봉투 그림을 공유하는 것은 임시 표현이다. 핵심 증거에는 실제 물건에 맞는 전용 아이콘이 필요하다. 단, 이 문서 작업을 이유로 이미지 제작/전체 증거 교체를 시작하지 않는다.
- 그림이 작고 빈 공간이 큰 카드는 해당 그림의 표시 크기부터 조정한다. 빈 공간을 장식선·배지·설명문으로 채우지 않는다.
- 이름·인용·설명이 같은 규칙으로 읽히는 일관성이 장식의 양보다 우선한다.

## 10. 적용 순서와 완료 기준

1. 현재 표시 경로/폰트 지원을 확인하고 공통 역할·표면별 토큰을 연결한다.
2. 먼저 일반 대사, 아빠 생각, 상황 묘사, 자료명 한 구절을 각각 한 장면에 적용한다.
3. 같은 내용을 기록/백로그/제시 카드에서 열어 색·표기가 의미대로 유지되는지 확인한다.
4. 이후 명시적으로 지정된 구절에만 강조를 확장한다. 모든 대사 문서를 일괄 리라이팅하지 않는다.

필수 확인은 변경한 표시 경로에 한정한다: 말→생각→말 전환, 괄호 중복 방지, 어두운 창/밝은 종이의 대비, 이름/자료명 일치, 질문 취소선, 글자 크게, 타이핑 효과음 종료. 기존 프로젝트의 변경 범위별 필수 검사만 수행하고 이 문서 적용 때문에 전체 14일 플레이 검증을 반복하지 않는다. 실행한 검사와 하지 않은 범위는 구분해 보고한다.

완료 시 클로드 보고에는 바뀐 파일, 적용한 역할/화면, 폰트 대체 규칙, 확인한 예시를 간단히 적는다. 본편과 디자인 시안의 적용 상태를 혼동하지 않는다.
