# 호출종 조작 후보 — 정확한 해법 미정 / 기존 예방 분기 연결 검토

기준 main `505cf8842e37628f27787bdd53024428b15b633a`(0.17.12). 최신 소스 ZIP을 읽었으며 관련 장치·예방·진엔딩·콘텐츠 파일은 이전 설계 근거와 동일했다. **문서 제안만 작성한다.** 호출종 방향과 ‘아는 사람은 첫 회차에도 직접 조작’이라는 원칙은 사용자 의도다. 13개 번호판·13번 약5초 유지와 상세 문 연동은 아직 시안이다. 이후 사용자가 의미 있는 호출 조작도 검토하므로 길게 누르기와 호출 관습형을 후보로 구분한다. 어떤 시간·횟수·순서도 확정하지 않는다. 기존 예방을 새 분기처럼 제안하지 않는다.

## 1. 후보 A — 직원 번호판을 끝걸림까지 유지하는 조작

주방의 옛 객실 호출종 판을 확대한다. 1–13 번호판을 같은 크기·재질·입력 방식으로 둔다. 짧게 누르면 해당 번호판을 살펴보고, 후보 A에서는 **13번을 누른 채 기계가 끝걸림에 닿을 때까지 유지**하면 연결된 걸쇠가 해제된다. 약5초는 입력 시안이며 세계관의 암호 숫자로 설명하지 않는다.

- 번호13은 객실 식별자다. 5는 암호가 아니라 조작에 걸리는 가상 물리 동작 시간/UX 임계값 후보다.
- 번호판을 누르는 동안 판이 조금씩 들어가고 줄의 장력이 변하며 작은 마찰음이 난다. 끝에서는 한 번 걸림 소리 후 정지한다. 중도에 손을 놓으면 복귀한다. 반복 조사 횟수·짧은 클릭 누적은 진행도를 쌓지 않는다.
- 정상 작동 중인 숨은 기계식 연동이다. 끊어진 줄·새 부품·수리를 필수 조건으로 넣지 않는다. 구체적인 감속/캠/걸림턱의 형태는 제작 승인 전까지 선택하지 않는다. 보통 번호판이 ‘5초를 센다’고 묘사하지 않는다.
- 일반 호출종은 객실에서 주방으로 신호를 보내는 장치다. 주방 번호판을 누르는 행위는 **직원이 호출 표시를 확인·복귀시키는 조작부**로 해석하는 안이 자연스럽다. 주방에서 객실을 호출하는 버튼이라고 임의 확정하지 않는다. 이 기능 설명도 신규 설정 제안이다.
- 도면의 금속 줄/걸쇠 표시, 번호판 가장자리의 깊은 마찰 흔적, 정상 복귀 조작과 다른 이동 폭이 ‘누른 채 끝까지’라는 해법을 설명하도록 한다. 도면 획득 여부를 입력 가능 여부와 연결하지 않는다. 13을 처음부터 금색·붉은색으로 특별 강조하거나 ‘비밀장치’ 툴팁을 붙이지 않는다.
- 해제 완료 후 상태는 유지된다. 화면을 닫거나 저장·불러오기해도 해제가 취소되지 않는다. 중간 입력 중 메뉴/화면 이탈/터치 취소/포커스 상실은 미완료 조작으로 복귀시키는 안을 권한다. 완료 직전 저장에 의한 이중 보상은 없어야 한다.
- 키보드는 번호판 선택 후 유지 입력, 터치는 같은 번호판을 연속 접촉하는 방식. 누르기 유지가 어려운 사용자를 위한 보조 입력은 모든 번호판에 동일하게 적용하고 정답 번호를 표시하지 않는다. 일반 조사 자동 진행이나 스킵으로 대신 풀리지 않는다.

현재 `r13_object_mechanism`은 본래 **E04 없이도** 레버와 책을 조작할 수 있다. 현재 막는 것은 주로 `secret_route_unlocked`와 장소/대상 노출 제한이다. ‘지금은 도면이 열쇠다’라고 기존 코드를 잘못 요약하지 않는다.

## 1-B. 후보 B — 의미 있는 직원 호출 조작(관습과 구조 모두 미승인)

사용자가 예로 든 ‘13번을 세 번,3번 종을 세 번’은 고민 중인 조작이지 확정 암호가 아니다. **3호와 통로를 연결하는 새 객실 설정을 해법에 맞춰 끼워 넣지 않는다.** parent가 언급한 ‘13번 표찰 세 번 / 세 번은 뒷길로라는 옛 직원 규칙’ 역시 기존 대본에서 확인되지 않은 후보다. 현재 증거와 코드에는 그 관습이 없다.

이 후보의 장점은 손님 호출과 직원의 응답·서비스 요청이라는 기능에 의미를 붙일 수 있다는 점이다. 그러나 ‘세 번이 뒷길’이라는 문장을 해법을 위해 새로 만들기만 하면 여전히 숫자 암호다. 채택하려면 다른 방의 정상 업무에서도 쓰이는 호출/수신 확인 관습과 남아 있는 표식·직원 안내·마찰 흔적이 일관되게 뒷받침되어야 한다. 도면을 안 읽어도 직접 조작은 가능하되, 처음 보는 사람은 세계 안에서 이유를 발견할 수 있어야 한다. 그런 문구나 대본을 이번 문서에서 확정하지 않는다.

**우발 해제 위험:** 손님이 객실 줄을 세 번 당기거나 직원이 번호판을 반복 확인하는 것만으로 비밀 해제가 되면 평소 업무 중 열릴 수 있다. 그러므로 손님의 호출 줄은 정상 종만 울리고, 숨은 연동은 별도의 **직원 측 정비 조작 경로**에서만 준비되도록 분리하는 방향이 필요하다. 단순히 연속 세 번을 감지한다고 쓰지 말고, 기계가 무엇을 기억하는지(래칫/걸림 상태 등), 보통 확인 동작에서는 왜 누적되지 않는지 설명할 수 있어야 한다. 이 부품·모드도 아직 설계 미정이며 새 정답 동작으로 확정하지 않는다.

| 검토 | 후보 A: 유지 조작 | 후보 B: 직원 호출 관습형 |
|---|---|---|
| 해법의 근거 | 판의 깊은 이동·마찰·금속 줄의 장력·걸림턱 | 실제로 쓰이는 직원 호출 규칙과 표식·일관된 업무 사용례 필요 |
| 현재 없는 설정 | 번호판의 깊은 이동/정비 연동, 약5초를 납득시킬 물리 형태 | 호출 횟수의 의미, 누적 기계와 일반 호출 분리. 현재 근거가 더 많이 부족함 |
| 일반 호출과 구분 | 손님의 호출 줄과 직원 판의 깊은 조작을 분리해야 함 | 손님의 반복 호출/직원의 반복 확인이 비밀 해제가 되지 않아야 함 |
| 미완료 입력 | 놓으면 복귀하는 안. 시간은 미정 | 초기화 시점·중도 취소·일반 확인 시 누적 방지 규칙이 미정 |
| 성공 이후 | 동일한 해제 준비 상태를 유지하는 연결안 | 조작만 다르고 같은 해제 준비 상태로 연결하는 안 |

두 후보를 함께 연속으로 요구하지 않는다. ‘13을5초 누르고 또 세 번’ 같은 복합 암호로 늘리지 않는다. 후보 B가 선택되면 아래의5초/연속유지 테스트는 그 후보의 입력 규칙으로 대체해야 한다. **현재 결론은 어느 쪽도 정확한 조작법으로 승인되지 않았다는 것**이다.

## 2. 13개 번호판의 공개가 모순인가

13호실 번호는 비밀이 아니다. 첫날 할머니의 방 안내와 등록 질문에 ‘13호실’이 나오고, 복도 문에도13이 적혀 있다. `mystery:door`에서 숨기는 것은 **두 번째 출입구**다. 따라서 주방 호출판에13이 있는 것 자체는 비밀통로 폭로가 아니다.

다만 현 대본이 객실1–13 전부의 배치나 총 객실 수13개를 확정한 것은 아니다. 13개 번호판을 이유로 기존 안내도에12개의 새 객실을 만들어 넣지 않는다. ‘옛13개 회선이 남아 있다’는 설명이 필요하면 추가 설정으로 검토해야 한다. 번호판이 단순 실내 소품으로 보이는 상태와 ‘13번의 특별한 연동을 직접 확인한 상태’를 분리한다. 수신표시·점등 상태로 현재 투숙객이나 주민 위치를 전지적으로 보여 주지 않는다.

## 3. 두 조작 후보에 공통인 문별 상태·양방향 통행 연결안

| 요소 | 기본/미해제 | 번호판 조작 완료 이후 | 사실/제안 구분 |
|---|---|---|---|
| 주방→세탁실 나무문 | 통상 문. 숨은 종의 전기 잠금문으로 만들지 않음 | 자동으로 열리거나 새 열쇠를 요구하지 않음 | 세탁실 존재는 현 대본. 독립 이동은 미구현 |
| 세탁실↔층간 서비스 통로 | 정확한 계단 구조·출입구 형상 미정 | 새 문을 열었다고 간주하지 않음 | 연결은 대본에 있음. 위치/구체 동선은 미승인 |
| 객실 쪽 책장 판 | 붉은 책 조작만으로는 잠긴 걸쇠가 버팀 | **붉은 책의 아래쪽을 누르고 옆으로 젖힌 다음**, 판을 밀어 통과 | 기존 레버의 해제 준비를 호출종으로 대체하는 제안. 책 조작 유지 |
| 통로 쪽 안쪽 손잡이 | 주방 상태와 독립해 객실로 열림 | 계속 수동 탈출 가능 | 기존 승인 기능 보존 |
| 복도 정문/안쪽 빗장 | 기존 문과 구조 시퀀스 | 호출종에 전혀 연동하지 않음 | 사건/구조 규칙 보존 |

**주방→13호:** 번호판 해제를 준비 → 세탁실 → 서비스 통로 → 안쪽 손잡이 → 객실. 여기서 안쪽 손잡이는 원래 독립이므로, 호출종 준비가 ‘안쪽에서 객실로 들어가기 위한 필수조건’은 아니다. 준비의 역할은 **객실에서 같은 길로 귀환할 수 있게 하는 것**이다.

**13호→주방:** 호출종 해제가 유지된 상태에서 객실 쪽 붉은 책 조작 → 책장 판을 밀고 통로 진입 → 계단을 내려 세탁실 → 주방. 번호판 조작만으로 책장이 자동 개방되거나 캐릭터가 이동하지 않는다.

**통로 안 수동 탈출:** 언제나 안쪽 손잡이로 객실 쪽으로 나올 수 있게 한다. 아래층 방향 역시 확정된 연결 안에서는 되돌아갈 수 있어야 한다. 원격 재잠금으로 사람이 끼거나 통로 안에서 저장 상태가 막히는 구조는 만들지 않는다.

중요한 미결점: 세탁실 입구/길을 이미 아는 사람이 호출종을 건너뛰고 안쪽 손잡이로 객실에 들어오는 우회는 기존 수동 해제 규칙과 양립한다. 이를 의도된 지름길로 허용할지 결정해야 한다. 이를 막기 위해 호출종이 별도의 세탁실 비밀문까지 잠근다고 자동 추가하면 새 장치가 되므로 이번에는 제안하지 않는다. 5초 조작을 모든 방향의 절대 열쇠로 만들려는 설명과 현 안쪽 손잡이는 동시에 유지될 수 없다.

해제 유지와 ‘나중에 다시 잠그기’도 별개다. 주방에서 기존 레버 OFF에 해당하는 **명시적 복귀 조작**을 남기는 안이 가능하지만, 어느 손잡이를 어떻게 복귀시키는지는 미승인이다. 짧은 조사 클릭이나 확대창 닫기로 재잠그지 않는다. 귀환 전 자동 시간초과도 넣지 않는다. 할머니가 귀환 뒤 복구했다고 단정하지 말고 기존 사건의 일괄 `False` 설정과 실제 행위를 구분한다.

첫 회차 접근 가능은 모든 장소를 지도에 미리 공개한다는 뜻이 아니다. 정상적으로 주방에 들어간 뒤 직접 조작은 처음부터 가능하되, 지도에는 이 회차에 확인한 연결만 추가한다. 기본 건물 외형에 비밀계단의 폭을 미리 비워 보이는 것도 피한다. 현행 첫날 메모/바느질 후 취침 조건을 지름길로 건너뛰어 진행이 멈추지 않는지 별도 검증이 필요하다.

## 5. 기존 예방 분기에 정상 연결되는가

**현재는 장치를 먼저 풀어도 감시 선택까지 자동 연결되지 않는다.** 기존 예방은 두 진입이 있다.

1. 짐 수령을 미루고 아이와 남기 → `father_accompanied` → 기존 `r13_prevented`. 통로 증거가 필요 없다.
2. E05 AND E18 소지일 때 보이는 ‘통로에 사람을 세우고 나비에게 동행을 부탁한다’를 선택 → `route_watched` → **동일한 기존 `r13_prevented`**.

| 구분 | 실제 의미 | 현재 구현/증명 범위 |
|---|---|---|
| E05 | 현재 통로와 출입구를 조사해 사용 가능성을 확인한 기록 | 올라오는 약45초의 조사 서술과 연결. 실제 사람을 배치했다는 뜻 아님 |
| E18 | 엄마의 미전달 경고 봉투. 여관을 경계하고 혼자 만나지 말라는 경고 | 감시할 길을 물리적으로 아는 능력과는 별개. `warning`은 3–13일, warning_location 필요, cost1 |
| 감시·나비 동행 | 플레이어가 선택해 실행을 약속하는 예방 행위 | 선택 시 route_watched. 상세 감시자 좌표/지속 시간/분 단위 감시 시뮬레이션은 없음 |
| 예방 결과 | 아이와 어르신이 함께 내려오고 사망이 발생하지 않음 | 살인·범인 입증 자료를 얻었다는 뜻은 아님. 기존 문장도 이를 명시 |

현재 E05는 감시 경로를 실제로 확인했다는 대리 조건으로 이해할 수 있다. E18은 위험을 의심할 서사 동기다. 그러나 **정답을 알고 현재 회차에서 통로까지 실제 확인한 플레이어의 방어 선택을 E18 미소지만으로 숨기는 것은 새 사용자 의도와 마찰**이 있다. 장치 개방/통행에 E18을 요구할 근거도 없다.

권고할 문서 제안은 ‘현회차에 통로가 통과 가능하다는 확인’과 ‘감시/동행을 선택하는 실제 행위’를 기준으로 기존 감시 선택을 사용할 수 있게 하고, E18은 경고의 근거·대화·후속 입증에 유지하는 것이다. 단순히 `E05 and E18`을 `E05 or E18`로 바꾸는 안은 경로를 모르는 사람도 감시하게 만들어 부정확하다. 호출종 조작만을 E05로 간주하거나 E37만으로 통로 실측을 건너뛰었다고 기록하는 것도 피한다. **소지품 게이트 및 첫날 제한 변경은 아직 설계 제안이며 코드에 적용하지 않는다.**

열어 둠/잠가 둠만으로 범행이 예방되는 새 분기는 만들지 않는다. 기존 사건 선택을 하지 않은 채 발견만 했다면 현재 엔진은 자동 예방하지 않는다. 호출종→현회차 연결 확인→기존 감시 선택이라는 연결을 명확히 하는 것이 이번 검토의 범위다.

## 6. 기존 예방 이후의 현회차 증거와 진엔딩

살인이 예방됐는데 촛대 속 핀이나 살인 당시 발자국을 자동 지급해서는 안 된다. 기존 예방 경로에는 이미 별도의 입증이 있다.

- 예방 시 살아 있는 어르신에게서 E17을 얻는다. 7일에는 `r13_prevention_hearing`으로 가며 E02 제시, 원본 대조 또는 어르신과 공개 확인을 하는 기존 선택을 사용한다.
- 8–13일 `w2_spring_proof`: E02를 근거로 우체국 원본을 확인해 E16 획득(cost1).
- E18을 놓쳤다면 기존 초롱의 후반 연락 경로가 warning_location을 다시 제공한다. `warning`은13일까지 열려 있어 현회차 봉투를 뒤늦게 받을 수 있다. 호출종 지식을 안다고 봉투 내용을 안 것으로 처리하지 않는다.
- 살아 있는 어르신에게 E16과 E18을 각각 실제 제시하면 `w2_prevented_plan` 질문이 열린다. 질문을 읽고 `prevention_witness`와 E17을 확인한다.
- `w2_plan_proof`: E16/E18/E17/prevention_witness가 필요하며 기존 예방 사건 상태에서 공개 대조한다. `premeditation_prevented_proven`과 `witness_protected`를 얻는다. **새 분기나 새 증거ID가 아니다.**
- 현재 진엔딩 E6은 F4, 엄마 원본 보호, 증인 보호, 서로 다른 시간/부하의 두 관찰, C4 또는 위 예방 입증을 요구한다. F1–F3와 생존 준비도 엔딩 판정에서 별도로 필요하다.

따라서 아는 플레이어가 탐색 시행착오를 건너뛰고 첫 회차부터 기존 예방→진엔딩 경로를 선택한다는 방향은 가능하다. 하지만 현재 day8–13 증거 행동과 day14 결말 일정 때문에 **호출종만 열어 즉시 진엔딩으로 점프하는 기능은 없다**. 날짜 진행까지 단축할지는 별도 승인 사안이다. 이전 플레이 증거를 이번 회차 자료로 복사하거나 실제 확인 없이 사실로 기록하는 방식은 사용하지 않는다.

## 7. 짧은 검증·소프트락 목록 — 유지 입력 항목은 후보 A에만 해당

- 새 저장·엔딩 이력0·E04 없음에서도 주방 도달/번호판 유지/책 조작/연결 확인이 가능한가. 첫날 장소 화이트리스트, 대상 visibility, 행동 secret_route_only를 함께 확인.
- 13번 짧은 조사 반복/다른 번호판 유지/빠른 클릭/스킵은 해제되지 않는가. 5초 미만 해제, 화면 이탈, 멀티터치, 포커스 상실은 미완료 입력을 안전하게 취소하는가.
- 해제 직후 저장→불러오기는 해제를 보존하고 보상을 중복하지 않는가. 중간 유지 상태는 완료로 복원되지 않는가.
- 주방→객실과 객실→주방을 각각 확인. 안쪽 손잡이와 하행 복귀가 잠금 때문에 막히지 않는가. 복도 빗장/구조 공구 장면을 종판이 열어 버리지 않는가.
- E04/E18 없는 조기 발견이 기존 감시 선택으로 연결되는 제안과, 위험을 막아도 살인 증거가 생기지 않는 기존 예방 흐름을 구분.
- 경고 봉투/살아 있는 증인/원본 공개 대조를13일 전에 수행할 기회가 남는가. 놓치면 지도 숨김이나 화면 고립이 아니라 기존 미입증 결과로 처리되는지 확인. 무조건 진엔딩을 자동 보장하지 않음.
- 비밀계단의 정확한 위치·치수, 세탁실 이동 장면, 호출판 부품 구조, 약5초 임계값, 명시적 재잠금 방법은 미결이다. 이 검토는 정적 코드 대조이며 새 퍼즐을 실행 검증한 것이 아니다.
