# 개발 담당 인계 · 전 주민 장면 개정 0.15.5-dev

공개 웹 런타임과 ROOM13_SOURCE_HANDOFF.zip에 적용하는 개정입니다. ALL_RESIDENT_SCENES.md에서 주민 35명+우편 접수 담당자의 전체 장면을 읽을 수 있습니다.

1. 최신 소스 ZIP의 DEV_HANDOFF_ROOM13.txt부터 확인하세요. 기존 작업 트리에 전체 스냅샷을 덮어쓰지 마세요.
2. 대본을 별도 프로젝트에 옮길 때는 apply_revision.py --project <프로젝트>로 먼저 검사하고 --write를 붙여 적용하세요. 알려진 이전 버전만 교체하며 다른 수정은 중단합니다.
3. r13_talk의 첫 부분에서 r13_notice_before_talk를 호출합니다. 관찰만 하고 떠난 것은 만남이 아닙니다. noticed:*는 해당 회차에만 저장되는 연출 플래그입니다.
4. 초면에서만 접근 선택이 나오고, 이미 만난 주민은 기존 일별 인사와 질문으로 이어집니다. 아이 부재·사건 이후·부리 상실·밤이 압박 분기를 보존하세요. 새 call의 명시적 from 라벨도 보존하세요.
5. 입구에서 부녀를 즉시 잠긴 대기소에 분리하던 연출을 함께 대기로 바꿨습니다. 대사와 UI 표시를 함께 수정했습니다. G1/G2/G3/E02, 정정 조건, 저녁까지 대기 비용은 그대로입니다.
6. 이번 버전은 전 주민의 만남 장면을 개작했습니다. 모든 조사·재판·엔딩 대사를 전면 개작한 것은 아닙니다.

최신 UI 병합: 345623c의 조사/제시/기록/옵션 통합바, 클로즈업 조사, 파노라마 및 입구의 실제 세 인물 배치를 보존했습니다. 이전 대기소 배지는 최신 UI에서 제거됐으므로 다시 추가하지 않습니다. 입구 질문 제목만 함께 대기하는 상황에 맞춰 수정합니다. 까로는 도착 장면에서 이미 만난 사람으로 기록되므로 새 초면 장면을 강제로 재생하지 않습니다. 입구의 다른 주민은 접근하기 전에 만남으로 기록하지 않습니다.

과자 도입에서 복원한 기존 그림 1장은 소스 ZIP에도 포함했습니다. r13_carriage_snack은 연출용 저장 변수이며 첫 과자 구간에서만 True, 편지 구간부터 False입니다. 최신 편지 그림을 삭제하거나 덮어쓰지 않습니다.

접근 선택은 r13_resident_approach 화면(zorder 40)을 사용합니다. 최신 파노라마 HUD 위에 띄워 접근 버튼이 지도로 클릭되는 충돌을 막습니다. 기존 전역 choice 화면을 일괄 변경하지 않습니다.
