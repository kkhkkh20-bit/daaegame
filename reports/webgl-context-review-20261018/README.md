# Public cloud Chrome graphics failure — code-side review

Parent browser task reports: public game loaded but stopped before title/gameplay; one normal UI retry produced the same error. Official downloaded log: Ren'Py8.5.3.26051504 / Emscripten3.1.67, EGL_BAD_MATCH → Could not set video mode → boot guard renderer missing. The exact loaded game build could not be established and is not inferred from the engine version. The same cloud browser also reported WebGL disabled/unavailable at https://get.webgl.org/ and https://get.webgl.org/webgl2/. These are parent-supplied browser observations, not local screenshots or independent checks performed by this execution agent. Other Codex/Claude previews are not evidence of ordinary users' successful public sessions.

Code evidence:

- `preview/room13-dev/renpy.js`: `_eglCreateContext` calls `GL.createContext(Module.canvas,EGL.contextAttributes)`. If it returns0, the wrapper sets error12297 (0x3009, EGL_BAD_MATCH). `GL.createContext` calls canvas.getContext(webgl2/webgl, attrs), returning0 when no context is returned. Default EGL alpha/depth/stencil/antialias are false and may be set by SDL config; no new app context option was added.
- SDK `renpy/display/core.py:1105` selects `gles2` for Emscripten. Desktop software fallback is excluded for Emscripten. At1264 it raises Could not set video mode after renderer initialization fails. `config.gl2=True` is not a promise of a browser software fallback.
- `renpy-pre.js:251` tracks context loss/restoration. Initial context creation failure is distinct from losing an existing context; its restoration event cannot create a missing context.
- `game/systems/room13_boot_guard.rpy` is the pre-existing0.18.79 protection. Missing renderer stops the game thread before further gameplay/autosave; the user-facing retry reloads the page. It does not retry forever or rewrite graphics settings.
- `dev/build_web.py:217` replaces the archive-fetch loader section; it does not alter the WebGL context-creation code. Current source has no diff from main e16710e7 for renpy.js, renpy-pre.js or the boot guard. Their git blob IDs there are respectively32aefebc188abecea9f58bd7048b417a4155e500,93a5c29a7cbebf698817fa52a8e745cc73f2bd2e,d8d8c9508789e6334887f67a2e13d5207a89f4e1.

Conclusion: no application regression demonstrated; independent WebGL1/2 failure strongly points to that cloud Chrome graphics environment. We did not change renderer options, weaken the guard, alter browser security settings, or force GPU flags to make the public browser pass. Existing local SDK fixture tests are separate evidence. Normal retry was exhausted; a separately available ordinary browser/environment can be tested when provided. No claim that every user/browser fails, and no diagnosis beyond the observed environment.
