# 클로드 적용 안내 — 손으로 확인하는 조사

본편에 이미 존재하는 저울·등불·포장 조사에 **그림의 변화와 손으로 확인하는 단계**를 더하는 제작 패키지다. 스토리 리뉴얼이나 새로운 유죄 판정 시스템이 아니다. 현재 파일은 독립 웹 시연이며 본편 코드는 변경하지 않았다.

## 확인 / 실행

- `index.html`을 HTTP 서버로 열면 세 장면을 직접 조작할 수 있다. 저장은 시연 전용 localStorage이며 본편 세이브와 무관하다.
- `assets/`의 7장, `asset-manifest.json`, `interaction-contract.json`을 본편 제작에 사용한다.
- 각 그림은 1672×941 전체 배경이다. 투명 오브젝트 스프라이트가 아니다. WebP는 원본 PNG에서 프로젝트 `dev/import_art.py`의 lossless export를 거쳤다. 추가 손실 압축, 블러, 필름 그레인, 세밀한 표면 노이즈를 더하지 않는다. 픽셀 표시를 유지한다.
- 상태 사이에 미세한 생성 그림 차이가 있어 완벽한 애니메이션 프레임으로 간주하면 안 된다. 짧은 정지 이미지 전환에 사용한다.

## 1. 저울 — 올려 보기와 원인 확인을 나눈다

**기존 연결:** `game/systems/room13_items.rpy`의 `use_weight_scale`. 실제 잡화점 맵의 파란 병, 흰 자루, 황동 양팔저울을 참조했다.

1. 저울을 누르면 `scale-base` 확대 화면. 오른쪽에 가게의 추, 왼쪽 접시는 비어 있고 표준 추는 탁자에 있다.
2. 표준 추를 집어 왼쪽 접시를 누르면 `scale-loaded`. 양쪽 접시가 완전히 같지 않음을 눈으로 확인한다.
3. 중앙 조정부를 누르면 `scale-pivot`. 나사 주변의 긁힌 표면을 직접 누르고 읽는다.
4. 돌아오면 이전 적재 상태가 남는다. 표준 추는 회수하고 재사용할 수 있다.

**중요:** 가게 추의 실제 질량은 검증되지 않았다. 같은 모양의 추 두 개로 기울었다는 사실만으로 저울 조작을 입증할 수 없다. 긁힘도 누가 언제 만들었는지 증명하지 않는다. 이 시연은 원인 탐색을 시작하는 관찰만 제공한다. 기존 코드의 바늘/나사 설명과 실제 맵의 양팔저울 표현을 먼저 일치시키고, 본편에서 검증된 기준이나 추가 관찰이 있어야 기존 증거 판정으로 연결한다. `loaded`만으로 조작 확정 플래그를 켜지 않는다.

## 2. 손등불 — 읽기 전에 빛을 옮긴다

**기존 연결:** `use_lantern_rear`. 여관 주방 뒷문·바닥·벽의 구조를 참조했다.

1. 뒷문 주변을 확대한다. 전체는 어둡고, 등불을 들면 커서/터치 위치 주변만 밝아진다.
2. 빛을 옮기며 문턱, 벽 밑, 계단 밑의 검은 자국을 누른다. 누른 지점의 관찰만 짧게 표시한다.
3. 벽 너머나 숨은 방을 미리 보여주지 않는다. 손등불은 길을 자동으로 찾아주는 표시기가 아니다.
4. 세 지점을 전부 클릭해야 통과하는 수집 과제로 만들지 않는다. 기존 조사 조건과 해금 시점을 유지한다. 첫날부터 비밀 통로를 노출하지 않는다.

시연에서는 진한 어둠을 사용했으나 본편은 화면 밝기 설정과 접근성을 고려해 조절한다. 중요한 자국 외에 다른 검사 지점과 범인 암시를 임의로 추가하지 않는다.

## 3. 창고 포장 — 이상한 촉감 → 봉합부 → 덮개 → 내용물

**기존 연결:** `use_knife_burlap`. 잡화점의 나무 상자·푸른 병·흰 자루를 참조했다.

1. `package-closed`: 손으로 아랫부분을 누르면 안쪽의 단단한 면을 관찰한다. 아직 보상을 주지 않는다.
2. 작업칼을 고르고 봉합부를 누르면 `package-seam`. 천 아래 나무 덮개가 보인다. 칼은 소비하지 않는다.
3. 손으로 덮개를 누르면 `package-revealed`. 안쪽 물품을 보여준다.
4. 내용물을 직접 클릭해 읽은 뒤 기존 조사 결과/증거 획득으로 연결한다. 그림을 여는 것과 내용을 확인하는 것을 구분한다.

곡식 주머니와 고기는 숨긴 식량의 시각 시안이다. 고기 그림만으로 신선도, 보관 기간, 거래 주체를 판단하는 새 설정을 만들지 않는다. 본편이 건육으로 확정되어 있으면 대사와 그림의 보관 형태를 맞춘 뒤 연결한다. 범인, 명령자, 유통 경로를 이 장면에서 자동으로 알려주지 않는다.

## 본편 연결 규칙

- `app.js`를 Ren'Py에 그대로 삽입하지 않는다. 이벤트/좌표와 이미지만 옮겨 Ren'Py screen 및 기존 store 상태로 구현한다.
- 좌표는 이미지의 좌상단을 0,0으로 한 `[x,y,width,height]`, 범위 0~1이다. 확대 뷰 크기에 곱해 클릭 영역을 배치한다. 실제 월드맵 클릭 영역과 확대 화면 클릭 영역을 혼동하지 않는다.
- 기존 도구 보유 조건, 사건 분기, 조사 가능 시점, 행동력 비용, 증거 중복 방지 규칙을 유지한다. 단계마다 시간이나 비용을 추가 차감하지 않는다.
- 물건을 잠시 내려놓거나 화면을 닫아도 재진입할 수 있어야 한다. 관찰 완료와 미완료를 구분하고 같은 보상을 반복 지급하지 않는다.
- 본편 세이브/로드/롤백과 새 회차 초기화에 상태를 포함한다. 시연의 localStorage는 구현 예시일 뿐 회차 간 해금 근거로 사용하지 않는다.
- 새 필수 증언 연결, 새 대결 정답, 새 영구 해금을 추가하지 않는다. 기존 증거 내용을 읽고 얻는 과정에 조작을 붙이는 범위다.
- 본편의 획득 팝업/좌측 상단 증거 표시/효과음이 있다면 내용 확인 후 그 경로를 재사용한다. 확대 장면 진입 자체에는 획득 효과음을 재생하지 않는다.
- 저울은 추가 물리 검증 설계가 필요하므로 마지막에 연결한다. 포장 → 등불 → 저울 순서로 연결하는 것을 권장한다.

## 확인한 범위와 한계

브라우저에서 7개 이미지 로딩, 도구별 분기, 저울 회수/재사용, 조정부 복귀, 등불 켜기/끄기, 포장 단계, 내용물 클릭, 시연 저장/초기화, 좁은 뷰포트를 확인했다. 결과는 `verification.json`에 있다.

본편의 14일 진행, 증거 판정, 세이브와 롤백은 이 작업에서 실행하지 않았다. 따라서 본편 적용 완료나 재미 검증 통과를 의미하지 않는다. 재미 확인은 같은 조사에서 텍스트만 읽는 방식과 직접 열어보는 방식을 짧게 비교해, 플레이어가 물건의 이상한 점을 자기 말로 설명하는지 관찰하면 된다.
