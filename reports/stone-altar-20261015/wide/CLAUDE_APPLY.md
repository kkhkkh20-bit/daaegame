# 클로드 적용 지침 — 공용 돌 제단 가로 맵

사용자가 승인한 돌 제단 디자인을 좌우로 확장한 **배경 아트**다. 이 문서 작성 시 본편에는 연결하지 않았다. 먼저 `ROOM13_GUIDE.md`, 최신 `CLAUDE.md`, `docs/OVERRIDE_MAP.md`를 읽고 아래 경로가 현재도 같은지 확인한다.

## 1. 어디에 적용하는가

새 장소를 중복으로 만들지 않고 기존 **`altar` / 산속 제단**의 넓은 조사 배경 후보로 사용한다.

| 목적 | 실제 소스 위치 |
|---|---|
| 그림 넣는 곳 | `experiments/renpy-ch1/game/assets/` |
| 장소 폭·배경·조사 좌표·인물 자리 | `game/assets/room13-world-layout.json`의 `altar` |
| 기존 조사 내용·획득/필요 조건 | `game/room13-content.json`의 `objects.altar` |
| 장소명과 장면 키 | `game/room13_week2_rules.rpy`의 `R13_PLACES["altar"]`, 장면 키 `r13_altar` |
| 월드 드래그·카메라·대화 배경 | `game/room13_world_camera.rpy` |
| 조사 화면의 넓은 viewport | `game/room13_screens.rpy`의 `r13_hub`, `r13_world_contents` |
| 인물 서 있는 위치·중요 물건 겹침 방지 | `game/room13_acting.rpy`의 `r13_stage_people`, layout의 `slots`·`floors`·`critical` |
| 지도에 표시하는 조건 | `game/room13_navigation.rpy`의 `r13_map_discovered`·`r13_map_nodes` |
| 기존 결말 연출 | `game/room13_week2.rpy`의 `r13_finale`, `r13_rescue`, `r13_final_hub` |

이 그림을 마을 광장의 돌이나 여관 숨은 통로 배경에 넣지 않는다. 지하 유적 화면도 아니다.

## 2. 사용자 의도와 스토리 범위

- 주민들이 알고 제사 지내는 **공용 공간**이다. 새로 발견한 비밀 제단이라고 설명하지 않는다.
- 고대문명 유적과 가깝고 돌의 양식이 이어진다. 이 그림만으로 비밀 입구, 포털, 지하 탐험, 새 증거나 사건을 추가하지 않는다.
- 주민들이 장소를 알고 있다는 설정과 플레이어가 지금 갈 수 있다는 조건은 구분한다.
- 현재 `r13_map_discovered("altar")`는 `finale_started`에 묶여 있고 `r13_finale`는 14일째에 이 장소를 사용한다. **아트 교체 작업으로 이 조건을 풀지 않는다.** 첫날부터 제단에 보내거나 엄마/결말 정보를 미리 노출하지 않는다.
- 일반 방문을 더 일찍 허용하는 기획은 별도 스토리 작업이다. 이번 변경은 날짜·경제·증거·구출/결말 분기를 그대로 유지한다.

## 3. 어떤 파일을 어떻게 연결하는가

원본 `stone-altar-wide.png`는 2172×724, 가로 3:1이다. WebP는 전달용으로 함께 들어 있다.

1. 프로젝트 `dev/import_art.py`로 원본을 `assets/room13-pixel-altar-wide-day.webp`처럼 충돌하지 않는 이름으로 넣는다.
2. `room13-world-layout.json`의 `altar`만 수정한다. 현재 값은 `width=1920`, `height=720`, `initial_x=320`, `revision=1`이며 배경은 `room13-pixel-ready-altar0177-{morning,afternoon,evening}.webp`이다.
3. 새 그림의 논리 크기는 **2160×720**, 초기 카메라는 **440**, 범위는 **0~880**이다. `width=2160`, `height=720`, `initial_x=440`으로 한다. `revision`은 작업 시점의 현재 값보다 올린다.
4. `files`의 시간대별 경로를 확인한다. 이번 파일은 **낮 전용 한 장**이다. 오전/오후는 같은 새 낮 그림을 사용해도 된다. 새 구도에 맞는 저녁 그림 없이 기존 1920폭 저녁 그림을 새 2160 좌표와 섞지 않는다. 저녁 자산이 없으면 최종 배경 교체를 미완료로 보고하고 기존 세트를 유지한다. 단순히 밤에도 밝은 낮 그림을 연결해서 완료했다고 하지 않는다.
5. 기존 `r13_world_background`가 전체 그림을 논리 폭×720으로 맞추고, `r13_camera_background`가 현재 카메라의 1280×720을 잘라 대화에 쓴다. 이 경로를 재사용한다. 첫 화면에 전체 파노라마를 축소해 넣지 않는다.
6. UI는 viewport 밖에 두어 날짜판·대화창·이동·기록 버튼이 카메라와 함께 움직이지 않게 한다. 대화를 끝냈을 때 같은 장소의 기존 카메라 위치를 유지한다.
7. 마우스/터치 드래그를 사용한다. 새 ‘좌우 둘러보기’ 바·스크롤바·화살표 버튼을 만들지 않는다. 현재 카메라 화면에는 화면 밖 인물을 가리키는 클릭형 가장자리 태그도 있으므로, 제단에 새 이동 UI를 추가하는 수단으로 사용하지 않는다. 이를 다른 장소까지 일괄 변경하는 작업으로 넓히지 않는다.

동봉 `map-layout.json`은 크기/카메라 계약이며 런타임 layout 전체를 대체하는 파일이 아니다. `status=art_only_not_integrated`도 설명용 메타데이터다. 그대로 엔진 파일에 덮어쓰지 않는다.

## 4. 조사 지점을 그림에 맞춘다

`room13_world_camera.rpy`의 init 62가 layout의 `objects` 좌표로 content의 `rect`를 덮어쓴다. 따라서 content의 rect만 고치면 적용되지 않는다. **권위 있는 새 좌표는 world-layout의 altar.objects에 쓴다.** 모든 좌표는 카메라를 빼기 전 **2160×720 월드 좌표**다.

기존 6개 ID를 보존한다. 그림 구도가 달라졌으므로 기존 1920 좌표를 1.125배 하는 방식은 쓰지 않는다.

| 기존 ID | 새 그림에서의 자리 | 처리 |
|---|---|---|
| `ledger` | 왼쪽 관리 작업대의 천으로 덮은 문서 | 책상 전체가 아닌 문서/보호 덮개에 맞춘다. 담당자 관련 열람 조건 유지 |
| `supplies` | 왼쪽 관리 공간의 장작과 통 | 장작·통이 보이는 범위. ledger와 별도 영역으로 나눈다 |
| `offerings` | 중앙 돌상 위 그릇·천·도토리 | 하나의 제물 묶음으로 취급. 그릇마다 억지로 별도 증거를 만들지 않는다 |
| `village_view` | 오른쪽 난간 너머 마을 지붕 | 하늘 전체를 클릭 영역으로 만들지 않고 전망 부분을 잡는다 |
| `approach` | 왼쪽 아래 진입 계단과 완만한 작업길 | 기존 이동/조사 동작을 보존하며 새 장소로 자동 이동시키지 않는다 |
| `valve` | **현재 새 그림에는 대응 장치가 없음** | 기존 제단의 관·연결 손잡이/밸브 전경 소품이 먼저 필요하다. 빈 돌을 눌러 밸브 대사가 나오게 하지 않는다 |

`offerings`의 기존 관찰문은 ‘난간에 매단 천’이라고 되어 있다. 새 그림의 돌상 위 그릇/천과 맞도록 **보이는 사실의 표현만** 바꿀 수 있다. 예: “제단 앞에 천과 작은 그릇들이 놓여 있다. 놓은 이유와 주인은 모양만 보고 정할 수 없다.” 증거 ID·필요 조건·보상·소유자/의미를 새로 확정하지 않는다.

작업 순서는 이미지 표시 → 보이는 물건별 새 rect 작성 → 실제 클릭 확인이다. 숫자를 먼저 복사해 물건을 그 자리에 있다고 취급하지 않는다.

## 5. 빠진 소품과 결말 장면

**이 배경만으로 기존 제단의 본편 교체는 끝나지 않는다.** 현재 결말에는 산 아래로 이어진 관, 연결 장치/손잡이, 결박·구출 상황, 관리 접근 동선이 등장한다. 새 그림은 평상시의 공용 제단을 표현한 것이다.

- 필요한 관·밸브/연결대는 원래 대사·판정에 맞는 별도 전경 레이어로 준비한다. 원형 석조 아치를 포털이나 배관 장치라고 임의 해석하지 않는다.
- 루트에 따라 쓰이는 수레·담요·연결대 등은 기존 연출/조건을 확인한 뒤 상황별 소품으로 둔다. 평상시 배경에 결말의 인질/구출 상태를 미리 그리지 않는다.
- 새 좌표 체계에 맞는 소품이 없으면 기존 그림에서 사각형을 잘라 붙여 임시 봉합하지 말고, **누락 소품과 필요한 상태를 목록으로 보고한다.** 누락된 상태에서 새 세트를 활성화하지 않는다.
- `critical`에 밸브·문서·제물 영역을 등록하고 `floors`·`slots`·`positions`를 실제 바닥에 다시 배치한다. 인물이 제단 위에 뜨거나 난간에 몸이 잘리지 않게 한다.
- 필요한 인물 수를 기존 스케줄/결말 장면에서 확인한다. 보기 좋게 채우려고 다른 주민을 새로 소환하지 않는다.

## 6. 적용 완료 기준

새 낮/저녁 구도와 필수 장치 소품이 갖춰진 뒤 다음 순서로 반영한다.

1. 새 이미지 import, altar layout 수정, revision 갱신.
2. 6개 조사 지점과 기존 인물 배치를 맞춘다. 배경·소품·클릭 영역을 같은 월드 좌표로 처리한다.
3. 처음 카메라 x=440에서 중앙 제단이 보이는지, 양 끝 x=0/880에 닿는지, 클릭/드래그가 구분되는지 확인한다.
4. 양 끝에서 물건/인물을 눌러도 엉뚱한 대상이 열리지 않는지, 대화/기록/저장·로드 이후 카메라가 유지되는지 확인한다.
5. 기존 제단 진입 조건과 14일째 제단/구출/결말 중 변경 영향을 받는 장면만 확인한다. 이 작업 때문에 전체 대사를 다시 쓰거나 14일 전 구간을 반복 검증하지 않는다.
6. 소스 검사와 빌드 후 main에 반영한다. 공개 파일은 `dev/build_web.py`로만 만든다.

최종 보고에는 바꾼 소스, 적용한 시간대, 추가 소품, 확인한 장면과 미완료 항목을 구분해 적는다. **그림 파일 준비 / 본편 연결 / 공개 배포**를 같은 완료 상태로 묶지 않는다.
