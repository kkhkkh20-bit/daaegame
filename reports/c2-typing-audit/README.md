# 기본 타이핑 소리 확인

기존 `event-audio-control.mp4`는 시간 배속이나 요약 편집이 아니라 실제 실행 연속 녹화입니다. 다만 검수 스크립트가 `preferences.text_cps=0`으로 즉시 표시를 지정했고 빠른 진행 클릭을 사용했습니다. `r13_typing_tick`은 속도 0에서 소리를 정지하므로, 그 영상에 글자 타이핑과 소리가 없는 것은 검수 설정 때문입니다.

실제 기본 속도는 34. `typing` 채널은 `sfx` 믹서에 등록돼 있고 stop_on_mute=True입니다. 기존 소스 `assets/type.wav`의 처음 25ms를 새로 보인 글자 그룹당 한 번, 비루프로 재생합니다. 이번 음악/환경음 정적은 `music`/`ambience` 채널 gain만 조절하며 typing 채널을 건드리지 않습니다. 새 소스·고음·음량 변경 없음.

공백도 기존 글자 수에 포함되는 작은 문제만 수정해 공백/탭/줄바꿈/전각공백을 클릭 계산에서 제외했습니다. 타이머는 기존 .02초 간격이고 한 번에 한 소리만 내므로 밀린 글자 수만큼 소리를 몰아서 재생하지 않습니다. 즉시완성·스킵·소리 옵션 꺼짐은 기존 중단 조건을 유지합니다.

## 실제 녹음

- [정상 속도](01-normal-typing.mp4): 핵심 대사에서 음악/환경음 gain=0인 상태로 타이핑 신호 검증. RMS 0.001986, peak 0.032600.
- [효과음 음소거](02-sfx-muted.mp4): 동일한 정적 상태에서 sfx mute 후 RMS/peak 모두 0. 사용자의 전체 효과음 mute를 무시하지 않음.
- `03-instant-text.mp4`는 즉시완성 이후 주민 반응으로 진행해 음악/환경음이 복귀하는 샘플이며 무음 시험으로 해석하지 않음.
- [원속도 핵심 대사 첫 화면](natural-core-unedited.mp4): 총 21.43초. 기본 34 속도, 핵심 대사 첫 화면을 중간 클릭 없이 18초 유지. 녹화 시작은 자료 제출 버튼 직전이며 편집·시간 압축·배속 없음. 기존 테스트 사용자 볼륨 music .37 / sfx .26 유지.

[runtime.json](runtime.json), [natural-runtime.json](natural-runtime.json), [signal.json](signal.json), [자연 속도 구간별 신호](natural-signal.json). 글자 표시 중인 3–4초 구간은 신호가 있고, 표시 완료 후 10–18초 구간은 RMS 0으로 타이핑 반복 재생이 없음을 확인했습니다. 전체 단위 테스트와 SDK lint 통과. 새 효과음 파일 전달 실패는 [별도 상태](../selected-audio-pending/README.md)에 기록했습니다. 심장/휙 적용 완료를 주장하지 않습니다.
