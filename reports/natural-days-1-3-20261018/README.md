# 새 게임부터 3일 밤까지 실제 입력 진행

게임 상태를 주입하지 않은 자연 진행이다. 새 게임부터 시작해 대화·몸/얼굴 클릭·조사·지도·자료 제시·저장/불러오기·취침을 실제 UI로 수행했다. 읽기 전용 introspection과 글자 즉시 표시 설정만 사용했다. 선택된 주요 경로를 3일 밤까지 진행했다. 모든 선택 분기와 전체 캠페인 QA 완료를 뜻하지 않는다.

- 1일: 입구 도착, 다람/경비 대화, 원본 조사 G1, 경비에게 제시하여 입장 정정 E02, 여관 숙박,13호실 M01/E03,취침. 기다리기 확인 취소 후 전체 게임 상태 동일.
- 2일: 0.19.49에서 만든 실제 저장을 통합 후보0.19.51에서 불러오기. 지도→수리점, 협동 대화, 초롱에게 M01 제시→후속 질문→J02, 우체국 세련에게 E01/M01 제시→후속 질문→J03. 우체국 저장을 최종0.19.52에서 다시 불러온 뒤 지도→13호실→취침.
- 3일: 새벽 사건과 피코 사망 분기 자연 발생. 광장 선택지에서 후불 제안을 묻고 거절. 꺼진3번 등 안·틈을 실제 조사해 L03/L04 확보. 지도→우체국→사서에게 L04→L00 제시, 경고/안전 확보 및 장작 미지원에 따른 illness 분기 확인. 13호실에서 취침 후 4일 아침 도착.

진행 차단은 발견하지 않았다. 사서 경고와 3일 밤 진행도 완료했다. 1일 저장 재회귀 후 최종 UI 재검증은 별도 미완료다. 최종 상태는 실제 저장 1쪽5번, 중간 상태는 1쪽4번에 남겼다. 기존 초기1쪽1번,2일1쪽2·3번도 보존했다.

버전 차이를 구별한다:1일0.19.49;2일 앞부분 로컬 통합 후보0.19.51;J03 뒤 저장부터최종0.19.52. 원격0.19.51 질문 발견 기능은 최종0.19.52에서 포함한다.

관찰: 구 UI에서는 입구 인물 발이 하단 버튼에 가렸으나 main 현장 단순화에서 해당 버튼들이 제거됐다. 여관 일반 토리 앉기 자세의 발/의자 접점은 추가 검토 대상이며, 이번 협동 토리 간격 수정과 다른 포즈다. 잘못된 QA 함수명(r13_world_spots) 조회 실패나 화면 페이드 직후 빈 probe는 게임 진행 오류로 분류하지 않는다.

## 종료 범위 갱신

동일한 실제 플레이를 이어 3일 사서에게 L04→L00을 순서대로 제시했다. `lt_lib_warned`, `lt_lib_safe`, 장작 지원이 없는 이번 선택의 `lt_lib_ill` 분기가 자연스럽게 적용됐다. 지도→13호실→취침과3일 밤 대사를 진행했고4일 아침에 도착했다. 따라서 새 게임부터1~3일을 지나4일 아침까지의 선택된 주요 경로를 완료했다. 모든 선택지/생존 분기를 검수한 것은 아니다.

최종 진행은 실제 저장1쪽5번. 이전1쪽1~4번도 보존했다. 진행 상태는 주입하지 않았으며3일 이후에도 배포0.19.52 클라이언트를 그대로 사용했다(회의 후보와 별도 브라우저). 다음 우선순위는 피코 생존/장작 지원 대체 분기, 여관 일반 토리 앉기 자세 접점, 회의 일반 롤백 입력 UX다.

미검증 범위: 피코 예방/생존, 나비 장작 지원 및 사서 완전 구조, 나머지 선택지와 전체 캠페인, 실제 iPhone, 기본 롤백 입력 UX. 회의 후보의 제작 대기 및 롤백 진단은 [제작 인계](../meeting-pressure-pilot/PRODUCTION-HANDOFF.md)에 분리했다.
