# 에셋 도구함 사용과 모듈 경계

다람탐정의 이미지·소리·글꼴을 등록하고, 화면 역할에 연결하는 로컬 제작 도구다. 원본 파일과 연결 정보를 분리하므로 같은 부품을 쓰는 화면들을 한 번에 바꿀 수 있다. 게임의 대사, 선택 결과, 정답 판정, 생사, 소지 자료, 이동·공개 조건은 이 도구에서 변경하지 않는다.

이 문서의 명령은 저장소 최상위에서 실행한다. 실제 게임 프로젝트는 `experiments/renpy-ch1`이다.

## 실행과 기본 사용

Python 3와 Pillow가 있는 제작 환경에서 실행한다.

```bash
python3 experiments/renpy-ch1/dev/asset_toolbox.py scan
python3 experiments/renpy-ch1/dev/asset_toolbox.py validate
python3 experiments/renpy-ch1/dev/asset_toolbox.py serve
```

브라우저에서 `http://127.0.0.1:8787/`을 연다. 다른 포트가 필요하면 `serve --port 8788`로 실행한다. 종료는 서버 터미널에서 Ctrl+C를 누른다. 서버는 로컬 주소에서만 실행한다.

1. 왼쪽에서 바꿀 역할을 선택한다. 의미가 있는 공통 역할이 파일별 역할보다 먼저 나온다. 역할 검색으로 파일명이나 버튼·글꼴 이름을 찾을 수 있다.
2. 가운데에서 현재 연결의 기본·누름·선택·비활성 상태를 확인한다. 해당 역할에 정의하지 않은 상태는 별도로 안내한다.
3. 에셋을 이름·경로·태그로 검색하거나 태그 필터로 좁힌 뒤 카드를 선택한다. 역할과 에셋 목록은 각각 최대 80개씩 표시한다.
4. 오른쪽에서 원본 크기, 렌더 정보와 그림을 확인하고 역할에 연결한다. 소리 에셋은 상세에서 재생하고 글꼴은 글자 예시로 확인한다.
5. 태그는 쉼표 또는 줄바꿈으로 구분해 편집하고 **태그 저장**을 누른다. 연결 저장과 태그 저장은 별도 동작이다.

연결을 저장하기 전에 전체 필수 상태를 검증한다. 매칭이 여러 개이거나 필요한 상태가 없으면 저장하지 않는다. 오류 안내를 보고 태그·에셋을 고쳐 다시 저장한다. 태그 저장 실패 시 편집 중인 입력은 유지한다.

새 그림을 업로드하거나 생성하는 기능은 없다. 승인된 파일을 게임의 `game/assets/` 아래에 넣고 `scan`으로 등록한다. 스캔은 기존 태그·렌더 정보와 연결을 보존하면서 파일 목록을 갱신한다. 기존 파일의 삭제나 이름 변경으로 깨진 연결을 자동으로 다른 그림에 바꾸지는 않는다. 스캔 후 `validate`를 실행한다.

## 등록 정보와 연결 규칙

두 파일은 `experiments/renpy-ch1/game/asset-toolbox/`에 있다.

| 파일 | 내용 |
| --- | --- |
| `catalog.json` | `version`, `assets`. 에셋별 `path`, `media`, `size`, `tags`, `render`, 선택적 `label`을 기록한다. |
| `bindings.json` | `version`, `bindings`. 역할별 이름, 매칭 태그, 필수 상태, 대체 상태, 묶음, 종류·크기 제약과 반영 시점을 기록한다. |

`path`는 `assets/...` 형태의 게임 상대 경로다. `media`는 `image`, `audio`, `font`로 나눈다. 이미지의 `size`는 원본 캔버스의 `[너비, 높이]`이고 소리·글꼴은 이미지 크기를 요구하지 않는다.

에셋마다 고유한 `asset:에셋ID` 태그가 붙는다. 상태 태그가 없는 파일에는 `state:basic`이 붙는다. `family:`, `kind:`, `folder:` 등은 검색과 분류에 사용하며, 연결의 `match`와 `requires`에 들어간 태그는 모두 만족해야 한다.

버튼 상태 세트는 같은 `pack:...` 태그를 공유하고 `state:basic`, `state:pressed`, `state:selected`, `state:disabled`로 구분한다. 예를 들어 `button.primary`는 `pack:button-states-v1/primary`에 연결된다. 세트의 한 카드를 선택해 연결하면 나머지 상태도 같은 pack에서 찾는다. `hover → basic`처럼 명시한 대체 규칙을 사용하며, 필수 상태 누락을 임의의 그림으로 숨기지 않는다.

한 파일만 쓰는 일반 역할은 고유 `asset:...` 태그로 연결한다. `group`이 같은 역할은 한 번의 연결 변경으로 함께 바뀐다. 변경된 모든 역할이 유효해야 저장한다. 본문 일반체와 볼드체는 `font.family` 묶음이며 각각 `regular`, `bold` 상태를 사용한다. 같은 글꼴 계열의 두 상태를 갖춘 pack으로 바꾸고 게임을 재시작한다.

## 파일 별칭과 기존 화면으로의 전파

스캔한 파일에는 `file:assets/경로` 역할이 생긴다. 이 역할을 다른 파일에 연결하면 원래 경로를 참조하는 기존 화면도 최종 연결 파일을 사용한다. 의미 역할에서 해당 파일을 사용하고 있다면 그 역할도 파일 별칭을 따라간다. 순환 연결은 오류다.

Ren’Py 어댑터는 `config.file_open_callback`에 연결해 기존 직접 경로의 파일 읽기도 매핑한다. 기존 콜백은 보존하고 중복 호출은 막는다. 파일 역할에서는 에셋에 붙은 crop·Frame을 자동으로 중첩하지 않는다. 원래 화면의 잘라내기·배치가 유지되도록 파일 자체를 교체하는 경계다.

인물 전신·클로즈업·동작, 대화 얼굴, 자료 그림은 도메인 어댑터를 거친다. 먼저 기존 규칙으로 인물·표정·자료를 고른 뒤 파일 경로만 매핑한다. 미납품 표정이나 없는 자료를 새로 만들지 않는다.

## 게임에 반영하기

일반 실행은 시작할 때 등록·연결 파일을 읽는다. 제작 중 자동 반영을 사용하려면 게임을 시작하는 프로세스에 환경변수 `R13_ASSET_TOOLBOX=1`을 지정한다. 이 모드에서는 약 0.5초마다 두 JSON 파일의 변경 시각을 확인한다. 정상 연결만 다시 읽고 에셋 표시 슬롯과 관련 캐시를 갱신한다. 오류가 있으면 기존 연결을 유지하고 알림을 표시한다.

| 역할의 `refresh` | 확인 방법 |
| --- | --- |
| `live` | 개발 모드에서 다시 읽은 뒤 현재 화면 또는 해당 화면을 다시 열어 확인한다. 공통 버튼과 일부 지도 아이콘이 해당한다. |
| `restart` | 저장 후 게임을 재시작한다. 파일별 역할 대부분과 글꼴이 해당한다. 시작 시 만들어진 표시 객체·스타일·오디오까지 자동 교체된다고 가정하지 않는다. |

도구함의 역할 설명과 저장 완료 메시지에 반영 시점이 표시된다. 폰트는 일반체·볼드체를 함께 변경해도 **재시작이 필요하다**. 일반 플레이 화면에는 도구함 UI를 넣지 않는다.

`r13_assets_assign()`은 개발·검수용 메모리 연결 변경이며 JSON 파일 저장 명령이 아니다. `r13_assets_reload()`는 디스크의 연결을 다시 읽는다. 지속되는 변경은 웹 도구함에서 저장한다.

## 크기·비율과 저장 검증

- 역할의 `media`와 다른 종류는 연결할 수 없다. `canvas_size`가 있으면 원본 캔버스 크기도 일치해야 한다.
- `crop`은 원본 안의 `[x, y, 너비, 높이]`여야 한다. 잘라낸 뒤 원본 비율을 유지하는 배율을 사용한다. 가로·세로 개별 늘림은 허용하지 않는다.
- `frame`은 `allow_frame`으로 허용한 에셋에만 사용한다. 역할의 `requires_render`와 `forbid_render`도 검증한다. 작은 버튼 상태 세트에 임의로 Frame을 추가해 늘리지 않는다.
- 큰 공통 버튼의 검증된 Frame 경로와 작은 상태 버튼의 균일 축소 경로는 별도 역할이다. 서로의 크기 문제를 다른 렌더 방식으로 우회하지 않는다.
- 미리보기는 원본 비율과 등록된 crop을 확인하는 용도다. Frame의 최종 게임 배치는 실제 게임 캡처로 확인한다.
- 서버는 허용된 `game/assets/` 경로만 제공한다. 로컬 Host, Origin, 요청 토큰을 확인하고 JSON을 검증한 뒤 임시 파일을 원자적으로 교체한다. 실패한 연결·태그 편집은 원본 JSON에 쓰지 않는다.

## 모듈별 책임

아래 경로는 `experiments/renpy-ch1/` 기준이다.

| 계층 | 파일 | 담당 범위 |
| --- | --- | --- |
| 데이터 | `game/asset-toolbox/catalog.json`, `bindings.json` | 에셋 정의와 역할 연결. 이야기 상태를 담지 않는다. |
| 순수 Python 모델 | `game/python-packages/r13_assets.py` | `Registry.resolve`, `assign`, `set_tags`, `validate`. 태그·상태·묶음·별칭·크기 검증. Ren’Py 및 HTTP에 의존하지 않는다. |
| Ren’Py 어댑터 | `game/room13_asset_toolbox.rpy` | JSON 로딩, `R13AssetSlot`, Crop·Transform·Frame 생성, 파일 별칭, 캐시 갱신, 개발 모드 자동 반영. |
| 도메인 어댑터 | `game/systems/room13_asset_domains.rpy` | 기존 인물·표정·자료 선택 결과의 파일 경로만 연결한다. |
| CLI | `dev/asset_toolbox.py` | `scan`, `validate`, `serve`. 등록·관리 진입점. |
| HTTP 서버 | `dev/asset_toolbox_server.py` | 로컬 API, 파일 제공, 요청 검증, 원자적 저장. 모델을 재사용한다. |
| 관리 UI | `dev/asset-toolbox/index.html` | 한국어 검색, 태그 필터, 역할·상태 미리보기, 연결·태그 편집. 매칭 규칙을 별도로 구현하지 않는다. |

새 화면은 의미 역할을 통해 부품을 조회하고, 공통 매칭 규칙은 순수 모델에 둔다. 화면별로 별도의 태그 검색이나 직접 JSON 쓰기를 만들지 않는다. 화면 행동·클릭 영역·잠금 조건·표정 선택·자료 ID는 해당 게임 모듈의 책임으로 유지한다.

## 검증과 인계

```bash
python3 experiments/renpy-ch1/dev/asset_toolbox.py validate
python3 -m unittest discover -s experiments/renpy-ch1/dev -p 'test_asset_toolbox*.py'
```

HTTP 회귀 테스트는 실제 모델과 작은 버튼 파일을 임시 프로젝트에 복사하고 독립 포트에서 실행한다. 사용자 JSON을 수정하지 않는다. 묶음 연결과 원자적 저장, 필수 상태 누락 거부, 태그 보존, 요청·경로 보호를 확인한다.

게임 반영은 네이티브 QA `b_asset_toolbox`와 `b_asset_file_alias`로 공통 역할·기존 직접 경로 전파와 진행 상태 불변을 확인한다. 최종 인계에는 바꾼 역할·묶음, 반영 시점, 검증 결과, 같은 장면의 캡처를 남긴다. 에셋 연결 변경을 이야기 분기 변경으로 확장하지 않는다.

## 회의 전체 화면 검토와 제작 요청 전달

도구함 위쪽의 **회의 화면 새로 캡처**는 현재 저장된 연결로 격리된 Ren’Py를 실행한다. 실제 회의 화면 캡처를 만들며, 두 번째 실행부터 이전 캡처와 새 캡처를 나란히 보여준다. 브라우저 합성 시안이 아니다. SDK와 Xvfb가 필요하고 렌더하는 동안 기다려야 한다. 아직 저장하지 않은 후보는 캡처에 반영되지 않는다.

역할을 선택하고 **선택 역할 제작 요청 ZIP**을 누르면 같은 그룹의 상태별 원본, `matching.json` 연결·크기·crop·배율·태그 계약, `usage.json` 코드 참조 위치, 제작 안내와 마지막 회의 캡처를 내려받는다. 고정 표시 크기를 알 수 없는 부품에는 임의의 수치를 만들지 않는다. `reference`의 캡처는 마지막 렌더 시점 자료이므로 변경 후에는 다시 캡처해서 전달한다.

**마지막 변경 되돌리기**는 이 도구함에서 저장한 직전 연결/태그를 한 번 복원한다. 파일 자체를 되돌리는 기능은 아니다. `previous.json`은 로컬 작업 기록으로 Git에서 제외한다. 코드 사용처는 정적 참조 검색이며 동적 경로 조합은 누락될 수 있다.
