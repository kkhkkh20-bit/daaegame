다람탐정 UI 레퍼런스와 적용 기준 — 2026-10-13

조사 범위와 확인 상태
사용자가 직접 제공한 역전재판의 조사/대화/질문/증거 제시 화면, 그리고 현재 개발판의 실제 타이틀/오프닝 스크린샷을 직접 시각 검토했다.
추가 게임은 웹 검색으로 공식 출처와 이미지 위치를 확인했다. 공식 사이트 HTML은 웹 검색 도구에서 열렸으나 이미지 열기 결과가 텍스트 <<ImageDisplayed>>만 반환되어 이 세션에서는 실제 픽셀을 확인하지 못했다. 셸에서 이미지 다운로드도 정책 프록시 403으로 차단됐다. 따라서 외부 이미지의 세밀한 색/좌표/타이포를 직접 검토했다고 주장하지 않는다. 아래 추가 레퍼런스는 열어볼 수 있는 원본 링크이며 타 게임 원화를 런타임에 복사하지 않는다.

1. 역전재판 — 플레이 구조와 시선 배치의 1차 기준
사용자 제공 스크린샷과 블로그: https://blog.naver.com/om_ozzi/224074007964
공식 작품 설명: https://news.capcomusa.com/2024/01/25/take-that-apollo-justice-ace-attorney-trilogy-is-out-now/
직접 본 요소: 인물은 중앙에 서고 대화문은 하단의 넓고 어두운 띠에 놓인다. 화자 이름은 본문보다 작은 별도 띠. 행동은 대화/조사/제시/이동의 네 갈래이며 짧은 동사와 큰 아이콘으로 고른다. 조사 대상은 배경 소품이고 화면이 UI 카드로 덮이지 않는다. 제시 장면은 증거를 작은 독립 사각형으로 보여 주므로 누구의 말과 어떤 물건을 비교하는지 읽힌다.
사용자 질문창 레퍼런스 자체는 얼굴 앞에 목록을 두지만, 최신 요청은 얼굴을 가리지 말라는 것이므로 최신 요청을 우선한다. 그대로 복제하지 않고 질문을 인물 옆 세로열에 둔다.

2. Tangle Tower — 개성 있는 인물과 대화 목록의 참고 후보
공식 SFB Games press kit: https://www.sfbgames.com/press/sheet.php?p=tangle_tower
공식 대화 스크린샷: https://sfbgames.com/press/tangle_tower/images/Shot%207.png
주제 선택 실제 스크린샷 출처: https://buried-treasure.org/2019/12/tangle-tower/
이미지: https://buried-treasure.org/wp-content/uploads/2019/12/06_tangletower.jpg
공식 자료로 확인한 사실: 손으로 그린 배경, 애니메이션 캐릭터, 용의자 대화와 단서 조사를 작품 특징으로 명시한다. 검색 이미지 설명에는 Encounter/Yourself/Yesterday/Statement 주제와 완료 표시가 나온다. 이미지 직접 검토 미완료이므로 보라색/특정 서체를 채택하는 근거로 사용하지 않는다.
우리 게임 적용 제안: 새로 열린 질문/이미 들은 질문을 작은 글자와 표식으로 구분하되 선택지는 같은 위치에 유지. 증언자의 표정과 질문이 동시에 보여야 한다. 대화 완료를 자동으로 사건 해결로 취급하지 않는다.

3. Strange Horticulture — 기록을 물건으로 읽는 화면의 참고 후보
공식 사이트: https://www.strangehorticulture.com/
공식 퍼블리셔: https://www.iceberg-games.com/strange-horticulture
공식 사이트의 시연 이미지: https://strangehorticulture.com/wp-content/uploads/2022/07/Characters.gif
공식 사이트의 수집 자료 시연: https://strangehorticulture.com/wp-content/uploads/2022/07/Plants.gif
참고 스크린샷을 수록한 리뷰: https://www.nintendolife.com/reviews/switch-eshop/strange-horticulture
이미지: https://images.nintendolife.com/screenshots/126218/900x.jpg
공식 설명에서 확인한 사실: 도감과 조사 단서를 함께 읽어 식물을 구별한다. 사진 같은 카드 관리 화면을 그대로 복제하는 대신 우리 수첩에서 물증 그림/채집 상황/증언을 자료처럼 읽게 하는 방향이 적합하다. 직접 보지 못한 장식 요소를 확정 규칙으로 삼지 않는다.

현재 스크린샷에서 확인한 문제
- 타이틀: 제목/설명/시작/이어하기/설정이 같은 거대한 베이지 패널에 들어가 있어 작품 표지보다 설정 화면처럼 읽힌다. 그림 수첩/이전 겨울 시나리오가 시작 버튼과 같은 위계로 놓인다.
- 메인 액션: 투명한 베이지 위에 얇고 어두운 글씨라 작업장 황갈색 소품과 경계가 겹친다. 마우스나 손가락이 먼저 찾아야 하는 동작이 구분되지 않는다.
- 인물: 부리의 큰 눈과 정면 아동 비율이 사실적인 공구 배경과 다르고, 상반신 표시가 지나치게 커서 얼굴/상체가 화면을 압도한다. UI만 고쳐서 해결할 수 없는 원화 비율 문제도 남는다.
- 이름/시간 HUD/액션 위치가 각각 떠 있어 가장 먼저 어디를 읽을지 불분명하다.
- 이미 읽은 대사 빨리 넘기기는 진행 대상이 아닌 설정이며, 메인 행동과 나란히 두면 플레이 목표처럼 보인다.

적용 원칙 — 1280x720 기준
1) 타이틀
전체 그림을 감상할 수 있게 두고 왼쪽 하단 또는 어두운 여백에 큰 제목과 짧은 부제. 제목은 명조, 플레이 본문은 가독성 좋은 고딕. 제목에 테두리/버튼 형태를 씌우지 않는다. 메뉴는 동일 축의 3개만: 이어하기(저장 있을 때)/처음부터/설정. 그림 수첩과 크레딧은 낮은 위계로 분리. 개발용 이전 시나리오는 설정의 작은 항목으로 이동.
2) 현장 탐색
주요 액션은 y=588 이후 하단 영역에 고정. 진한 잉크색(#192e34 등) 완전 불투명 면 + 따뜻한 흰 글씨(#fff4df). 선택 테두리만 금색. 배경과 인물에 같은 장식을 반복하지 않는다. '해 볼 일'은 '이곳에서 할 일'보다 실제 행동의 이름을 바로 보여 주는 편이 좋다. 조사와 별도 활동을 섞지 않아야 한다.
3) 인물 대화
얼굴 중심 x≈770 또는≈870, 질문 목록 x≈48~560. 선택 목록은 얼굴과 겹치지 않는 영역에 배치. 어깨/손은 조금 겹쳐도 얼굴/귀는 보호. 대화문은 하단. 큰 캐릭터와 작은 초상화를 동시에 중복 표시하지 않는다.
4) 행동과 기록 구분
버튼=어두운 단색. 물증/증언/수첩 본문=밝은 종이. 모든 것을 베이지로 만들거나 모든 것을 금테로 장식하지 않는다. 증거 선택에는 대상 얼굴, 내용 미리보기, 보여주기/취소를 분리. 선택만으로 공개되지 않음은 그대로 유지.
5) 모바일
주요 터치면 최소 높이56 game px 이상. 본문24~28px. 지나치게 많은 영문 소문자/라벨/별도 설명줄을 추가하지 않는다. 중요한 기능은 네 개 이하의 일관된 행동군으로. 비활성 항목은 단순히 흐리게만 하지 말고 눌리지 않음이 명확해야 한다.
6) 검증 절차
타이틀 → 첫 캐릭터 → 수리점 조사 → 부리 대화 메뉴 → 질문 목록 → 증거 선택/취소 → 설정 → 저장 → 재진입을 실제 브라우저에서 확인. 같은 원본 스크린샷과 변경 후를 나란히 비교. 얼굴 가림, 글자 대비, 모바일 확대/축소, 읽은 대사 옵션 위치, 첫 사용자 입력 후 메인 BGM 재생을 독립 체크.

다음 캐릭터 시안 기준
UI 개선과 별도 작업으로 유지한다. 어른은 눈 작게만 하는 문제가 아니다. 머리/몸 비율, 중심 높이, 등과 목의 자세, 옷의 무게, 직업 동작, 종별 실루엣을 먼저 나눈다. 43명을 새로 생성하기 전에 부리/까로/할머니/아빠/다람 5명 동일 배경 크기 합성으로 확정한다. 도트 복귀를 말만으로 배제하지 않는다. 배경+캐릭터+아이콘+타이포의 같은 화면에서 비교해야 한다.
