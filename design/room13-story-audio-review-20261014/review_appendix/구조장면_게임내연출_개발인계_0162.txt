구조장면 게임 내 연출 개발 인계
검토일: 2026-10-14 / 기준: 전달받은 0.16.2 소스 정적검토

확정 방향
원거리의 연기 나는 여관 → 입구의 웅성거림 → 복도 잠긴 문 주변 조사와 도구 확보 → 문 진입 → 작은 불·피 흘리는 부엉이 시신·다람이 보이지 않는 방 전체 → 침대 아래 클릭 → 아이 발견 클로즈업 → 구조 순서로 연결한다. 방 전체 화면에서는 아이를 미리 노출하지 않고, 침대 아래 클릭 후 발견 장면을 보여 준다. 문을 연 직후 구조 CG로 바로 건너뛰지 않는다. 도트 CG와 분리 레이어를 Ren’Py ATL/Screen으로 연출한다. 심장소리를 중심으로 한다. 실제 코드 변경 및 실행 검증은 하지 않았다. SDK와 대부분 원화/오디오가 없어 실행할 수 없었다.

- source.rpy:54–98: scene_fx 효과음 채널 및 loop 가능한 pulse 채널이 있다. source_pulse(True)는 타이핑음을 끄고 source-heartbeat.wav를 반복한다. source_fx는 스킵 중 효과음을 생략한다.
- 주의: source_pause_effects(:198)는 source_mode 조건이다. room13_start는 source_mode=False이므로 저장/옵션 중 심장소리 중지는 본편용으로 연결해야 한다.

- 본 소스의 .rpy에서 Movie()/movie_cutscene 호출은 발견하지 않았다. 기존 기반은 이미지 CG/ATL/효과음이다. README 및 build_web.py에 웹 배포 대상 preview/room13-dev가 명시되어 있다.

추천 구현
1) 문틀, 잠금, 문 아래 연기 등 짧은 조사 지점을 둔다. 구조를 지연시키는 복잡한 추리나 불필요한 반복 클릭은 피한다.
2) 도구 사용 선택 후 문 열기 입력을 한 번만 받는다. 대본에서는 도토가 지렛대를 받아 너울과 문을 받치므로 담당 인물/도구/행동을 임의 변경하지 않는다.
3) 도구 접점 → 잠금 고정부 파손 → 문이 방 안으로 열림 → 방 전체 확인 → 침대 아래 클릭 → 아이 발견 클로즈업 → 구조를 짧은 단계로 연결한다. 대본상 왼쪽 빗장 받이가 뜯기고 오른쪽 경첩은 남는다. 유리문이나 폭발로 바꾸지 않는다.
4) 닫힌 문/파손 문/도구/손/연기/실내/구조 CG를 필요한 수의 별도 레이어로 준비하고 정수 좌표·nearest 확대를 유지한다. 연기/진동/빛은 적게, 큰 화면 흔들림은 움직임 제한 설정을 존중한다.
5) 심장음은 pulse, 파손음은 scene_fx처럼 분리한다. 배경음과 타이핑은 낮추거나 멈추고, 구조 후 심장음을 정리한다. 음소거여도 상황을 알 수 있는 텍스트/시각 신호를 둔다.

저장/스킵/안정성
- 조사 전/도구 사용 직전/구조 후를 명확한 복귀 지점으로 설계한다. 프레임 단위 영상 재개를 약속하지 않는다. Ren’Py 저장은 상호작용 문장의 시작 상태가 기준이므로 길게 하나의 Python 루프로 묶지 않는다.
- 도구 선택, 파손, 구조 완료를 저장 가능한 상태로 분리한다. 완료 시 기존 case_state/victim_state/location 변경과 증거 지급이 중복되지 않게 한다. 이번 구상으로 사건 결과 자체가 변하는 것은 별도 게임 규칙이다.
- 스킵은 애니메이션만 생략하고 같은 최종 화면/필수 상태/후속 대사로 도착해야 한다. 재생 취소/옵션/저장/로드/롤백에서도 심장음·타이핑·화면 레이어가 남지 않게 정리한다.
- 웹은 이미지 로딩이 프레임 끊김을 일으킬 수 있다. 해당 컷의 작은 에셋을 전환 전에 준비하고 초기 배포/진행형 다운로드 규칙에 빠지지 않았는지 확인한다. 첫 사용자 입력 전 오디오는 브라우저 정책으로 차단될 수 있다.
- 실물 iOS Safari/Android Chrome, 가로 화면, 큰 글씨, 음소거, 탭 전환 복귀, 연타, 느린 네트워크, 각 단계 저장/로드와 스킵을 별도 검증해야 한다. 이번 검토에서는 수행하지 않았다.

영상 파일과의 비교
게임 내 레이어 방식은 기존 픽셀/텍스트/선택지/분기와 자연스럽게 결합하고 영상 코덱/추가 재생 확인창을 피할 수 있다. 단 레이어 수·로드·애니메이션 비용을 제한해야 한다.
미리 만든 영상은 복잡한 동작을 고정된 타이밍으로 보여 주기 좋지만 용량·브라우저 코덱·저장 복귀가 별도 문제다. 공식 웹 문서는 movie_cutscene만 지원하며 Movie 디스플레이어블을 웹 공통 기반으로 삼을 수 없다고 명시한다. iOS의 소리 있는 영상은 추가 탭을 요구할 수 있어 ‘도구 사용 후 자동 연결’에 불리하다. 따라서 이번 확정 방향에는 영상 파일을 추가할 이유가 적다.
