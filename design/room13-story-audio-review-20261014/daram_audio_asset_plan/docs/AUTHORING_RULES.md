# 다람탐정 공통 대사와 연출 작성 규칙

버전 1.0 · 2026-10-14 · 기준 소스 0.16.2 / 5e6c2c53ae067b7fc2eb9d10075320587a342f0e

이 문서는 모든 후속 대사 작성자와 게임 구현자가 함께 지킬 표현 규칙이다. 이야기의 사실, 말투, 사건 순서, 인물의 지식, 선택 결과는 원고와 게임 시스템이 결정한다. 이 규칙은 그것을 화면과 소리로 정확하게 전달한다. 현재 파일은 인수인계 제안이며 실행 중인 게임에는 아직 적용하지 않았다.

## 1. 모든 대사에 적용할 기본 계약

- 원문 `text`, 화자 ID, 대사 ID, 기존 읽음 판정·히스토리·번역 키를 보존한다. 렌더링용 강조 태그를 원문 문자열에 영구 삽입하거나, 강조 때문에 읽음 ID를 다시 계산하지 않는다.
- 대사 한 줄은 일반 발화 `spoken`, 내면 독백 `thought`, 관찰 서술 `narration` 중 하나로 명시한다. 새 작성자는 괄호만으로 독백을 판정시키지 않는다. 현행 `thought: true` 메타데이터와 호환되는 변환은 Claude가 담당한다.
- 일반 대사는 기존 화자명과 기본 대화창을 유지한다. 독백은 아래의 파란 대화창 규격으로 렌더링한다. 관찰 서술은 자동으로 독백으로 바꾸지 않는다.
- 발화하지 않은 독백을 다른 인물이 듣고 대답하지 않는다. 현장에 없거나 격리된 인물이 갑자기 반응하지 않는다. 감정 표정은 원고의 근거가 있을 때만 붙인다.
- 연출 누락의 기본값은 조용하고 읽기 쉬운 상태다. 모든 줄에 효과음·흔들림·반짝임을 붙이지 않는다.

## 2. 중요어는 빨강과 굵기로 표시한다

사용자 요구: 중요한 고유명사, 증거 이름, 추론의 핵심 단어가 눈에 들어와야 한다.

- 신규 장소·인물의 중요한 첫 소개, 실제로 언급한 증거명, 두 기록을 비교하는 핵심 수치·날짜·부정어를 작성자가 지정한다. 단순히 이름이 다시 나왔다고 매번 빨갛게 만들지 않는다.
- 기본 토큰은 `important`이며 표시색 `#FFAAAA`와 굵기 700~800을 함께 사용한다. 어두운 대화창 위의 밝은 산호색 빨강이다. 저채도·고대비 모드에서도 굵기는 유지한다.
- 한 대사 창에 핵심 1~2구간을 권장한다. 정말 필요한 경우 3구간까지 허용하되 문장 전체를 강조하지 않는다. 이는 편집 가이드이며 긴 법칙처럼 기계적으로 잘라내지 않는다.
- 조사는 가급적 제외한다. 예: `예약 원본`만 강조하고 `을`은 본문으로 둔다. 수치의 비교는 `한 분`과 `두 분`처럼 대칭으로 표시한다.
- 인물의 이름을 빨강으로 보여 주었다는 이유만으로 범인·거짓말·정답을 암시하지 않는다. 단서를 아직 읽지 않았거나 등장인물이 모르는 정보는 강조 목록에 노출하지 않는다.
- 같은 단어가 한 문장에 여러 번 나오면 `occurrence`를 명시한다. 지정 문구가 원문에 없거나 범위가 겹치면 검증 실패로 처리한다. 단순 전역 문자열 치환은 금지한다.
- 원문을 유지한 채 표시 단계에서 Ren'Py의 `{color=...}`와 `{b}`에 대응시킬 수 있다. 작성자는 색상 값을 줄마다 직접 쓰지 않고 공통 토큰을 쓴다. 기존 특수 태그·보간·중괄호·줄바꿈은 손상시키지 않는다.
- 화면, 대사 기록, 큰 글씨에서 같은 핵심어 의미를 보존한다. 기록 재열람은 효과음을 재생하지 않는다.

색만으로 정보를 구별하지 않고 굵기·문맥·필요시 텍스트 라벨을 함께 제공한다. 일반 텍스트 대비는 최소 4.5:1을 목표로 실제 합성 배경에서 확인한다. [W3C 색 사용 지침](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html), [W3C 최소 대비 지침](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

## 3. 독백은 파란 대화창으로 구별한다

현행 0.16.2는 독백 글자만 `#9DC9FF`로 바꾸며 창 배경은 일반 대사와 같다. 앞으로는 창 자체를 바꾸어야 한다.

| 역할 | 표시 제안 |
|---|---|
| 일반 대사 | 기존 `#142237` 계열 배경, 크림색 본문 유지 |
| 독백 창 | 불투명 `#164268`, 테두리 `#8CC9FF` 2px |
| 독백 본문 | 밝은 `#E8F3FF`, 일반 대사와 동일한 크기·행간 |
| 이름표 | `다돌 · 속마음`처럼 화자 이름과 독백 표기 |
| 강조어 | 같은 `important` 토큰 `#FFAAAA` + 굵게 |
| 접근성 | 색과 함께 ‘속마음’ 텍스트를 제공 |

- 기존 괄호 표기는 원문에 있으면 그대로 둔다. 새 괄호를 자동으로 중복 삽입하지 않는다.
- 독백 시작마다 별도 효과음을 내지 않는다. 타이핑 소리는 일반 대사와 같은 읽기 리듬을 따른다.
- 얼굴/포즈를 thinking으로 고정하는 기존 규칙을 보존하되, 장면 연출 메타데이터를 무시할 이유가 생기면 원고 담당과 합의한다.
- 다음 일반 대사, 선택지, 저장/불러오기, 장소 전환에서 독백 상태가 남지 않아야 한다.
- 투명도를 쓸 경우 밝은 배경 위에서도 대비를 다시 계산한다. 이 제안의 불투명 배경은 대비 변동을 줄이기 위한 시작점이다.

## 4. 타이핑은 배경음과 함께 들려야 한다

- 실제로 화면에 새로 표시된 읽을 수 있는 글자에만 반응한다. 글자 수 추정 루프나 대사 길이만큼 틀어 놓는 반복 음원은 사용하지 않는다.
- `typed_blip_a/b/c` 38ms 후보를 순서대로 순환한다. 기본 최소 간격 70ms, 최대 약 14회/초. 빠른 글자 표시 때도 못 낸 소리를 나중에 몰아 재생하지 않는다.
- 공백, 줄바꿈, 마침표·쉼표·말줄임표 자체에는 탭을 내지 않는다. 구두점의 기존 읽기 휴지기는 보존한다.
- 대사 한 줄을 즉시 완성하는 클릭, 스킵, instant text, 메뉴/수첩/기록 열기, 저장/불러오기, 화면 이탈 때 즉시 정지한다. 다음 대사가 실제로 다시 한 글자씩 나타날 때만 재개한다.
- 줄 단위로 음악을 약 6dB 낮추는 시작값을 제안한다. 매 탭마다 음악을 올렸다 내리지 않는다. 대사 중 저감 진입 120ms, 대사 종료 후 복귀 300ms. 사용자가 음악을 0으로 설정했다면 절대로 다시 켜지 않는다.
- 음악·효과음·타이핑은 별도 조절을 제공하는 방향을 권장한다. 타이핑 OFF여도 자막·핵심어·게임 판정은 동일하다.
- 숫자상 피크가 통과했다는 이유로 ‘잘 들린다’고 승인하지 않는다. 마을/탐색/밤/심문 BGM, 휴대폰 스피커, 헤드폰, 기본 볼륨/낮은 볼륨에서 실제 청음한다.

## 5. 화면 사건과 소리는 같은 의미에 연결한다

| 의미 | 이벤트 | 재생 허용 시점 |
|---|---|---|
| 새 증거/증언을 실제로 얻음 | `evidence_acquire` | 상태 반영 후 획득 카드 첫 표시 |
| 상대에게 자료를 실제로 보여 줌 | `evidence_present` | 제시 확정 후 카드 첫 표시 |
| 선택을 확정함 | `choice_confirm` | 유효한 입력 확정 한 번 |
| 선택을 취소·뒤로 가기 | `choice_cancel` | 화면을 닫는 동작 한 번 |
| 검증된 추론을 마침 | `deduction_success` | 시스템 판정 후 그 결과가 공개되는 순간 |
| 기록 사이 모순이 확인됨 | `contradiction` | 모순을 화면/대사가 공개하는 순간 |
| 긴장 전환/해제 | `suspense_rise/release` | 명시된 장면 경계 한 번 |

- 재료를 고르거나 클릭했다는 이유만으로 성공음을 내지 않는다. ‘증거 제시’는 그 증거가 정답이라는 뜻이 아니다.
- 반응 대사가 답을 밝히기 전에 정답/모순 소리를 먼저 틀어 퍼즐 해답을 누설하지 않는다.
- 여러 증거를 한 번에 받으면 첫 카드에서 한 번만 획득음을 낸다. 2.4초마다 바뀌는 카드마다 다시 울리지 않는다.
- 선택 확정 직후 증거 제시·추론 결과음이 나오면 일반 확인음을 생략한다. 하나의 행동에 2~3개 신호가 겹치지 않게 한다.
- hover, 화면 redraw, 예측 로딩, 스크롤, 기록 재열람, 불러오기 복원은 조용하다. 실제 동작을 확정하는 시스템이 이벤트를 발생시킨다.
- 반복 제한, 우선순위, 자산 파일, 시작 레벨은 `sound_events.json`을 기준으로 한다.

## 6. 기계장치는 물리적 상태를 구별한다

- `mechanism_lever_on`: 주방 레버 올림과 줄의 긴장. `mechanism_lever_off`: 레버 내림, 줄 이완, 위층 걸쇠 복귀.
- `book_latch_unlock`: 책장 잠금 해제와 판의 이동. `book_latch_locked`: 걸쇠가 버텨 실제로 열리지 않음.
- `passage_exit_release`: 통로 안쪽 수동 손잡이. 주방 레버 상태와 독립적인 출구 조작임을 소리로도 구별한다.
- `door_forced_open`: 구조 장면에서 문틀 고정부가 뜯어짐. 평범한 문 닫힘과 같은 파일로 처리하지 않는다.
- 잠긴 기계장치 반응은 오답 벌점음과 분리한다. 낡은 나무·금속의 절제된 질감이며 큰 폭발/비명/과한 저음 충격을 추가하지 않는다.
- 마차·까마귀·말발굽의 이전 불만족 음원은 자동 재사용하거나 새 UI팩을 적용하면서 다시 켜지 않는다.

## 7. 새 대사 작성 시 제출 양식

원문과 표시 정보를 분리해 아래 내용을 함께 넘긴다. 이것은 데이터 계약 예시이며 현재 파서가 이 필드를 읽는다고 주장하지 않는다.

```json
{
  "line_id": "기존의_안정적인_대사_ID",
  "speaker": "dad",
  "text": "기존 원문 그대로",
  "mode": "thought",
  "presentation": {
    "emphasis": [
      {"text": "원문에 실제로 있는 핵심어", "occurrence": 1, "role": "important"}
    ],
    "expression": "thinking",
    "pose": "thinking"
  },
  "audio_note": "없음 또는 이미 정의된 사건 이벤트와 그 근거"
}
```

- 획득·제시·성공 여부는 이 대사 객체가 결정하지 않는다. 상태 시스템에서 판정하고 그 결과를 표시하는 이벤트에 연결한다.
- 특정 음원을 요구할 때는 파일 경로를 원문에 쓰지 않고 기존 이벤트 ID를 선택한다.
- 새 음원·새 색상·새 창 스타일을 도입하려면 공통 목록에 먼저 등록한다. 임시 값이 장면마다 퍼지지 않게 한다.

## 8. 모든 후속 작업의 완료 조건

1. 중요어 범위가 원문에 존재하고 스포일러·과도한 강조가 없는가.
2. 독백 창/속마음 라벨/표정이 맞고 다음 대사에 상태가 새지 않는가.
3. 획득·제시·잠금·해제·추론·모순이 서로 다른 실제 사건을 알리는가.
4. 스킵·연속 클릭·취소·롤백·저장/불러오기·수첩 재열람에서 재생이 중복되지 않는가.
5. 효과음을 꺼도 의미가 동일하고, 켜면 BGM 속 타이핑과 핵심 이벤트를 실제로 들을 수 있는가.
6. 작은 화면/큰 글씨/긴 증거명/색상 식별 어려움/기록 보기에서도 읽을 수 있는가.
7. 새 자산의 출처·라이선스·변경 내용·해시와 실제 빌드의 크레딧 포함 여부를 확인했는가.

## 9. 규칙을 잊지 않게 유지하는 방법

Claude가 구현 작업을 시작할 때 이 문서를 읽도록 저장소의 기존 `CLAUDE.md`와 개발 인수인계 문서에서 링크한다. 대사 PR 체크리스트에는 위 8절을 넣고, 자동 검증은 존재하지 않는 강조 범위·미등록 이벤트·미등록 표현 토큰을 실패시킨다. 기존 `VOICE_RULES.md`의 인물 말투 규칙은 그대로 함께 사용한다. 이 패키지는 저장소를 수정하지 않았으므로 해당 링크 추가와 검사 연결은 Claude의 후속 작업이다.

기술 참고: [Ren'Py 텍스트 태그](https://www.renpy.org/doc/html/text.html), [Ren'Py 오디오 채널과 볼륨](https://www.renpy.org/doc/html/audio.html). 구체적인 필드와 런타임 구현은 프로젝트에 설치된 Ren'Py 버전에서 다시 확인한다.
