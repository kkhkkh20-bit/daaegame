# Claude에게 넘기는 음원과 표현 구현 계획

기준: 0.16.2 / main `5e6c2c53ae067b7fc2eb9d10075320587a342f0e` / 소스 ZIP blob `2f0215fcd3acd54b14590ffff6feaba9ab5fe31d`.

## 작업 경계

이 묶음은 검토용 음원·데이터 규격·지속 작성 규칙이다. 게임 실행 코드, 대사 원문, 사건 판정, 원격 저장소, 배포본을 수정하지 않았다. 19종은 청음 후보이며 최종 채택 전 실제 기기 청음이 필요하다. 사용자가 요구한 중요어 빨강/굵게, 독백의 파란 대화창, 배경음 속 타이핑, 증거 등장 효과음을 구현하는 담당은 Claude다.

## 바로 볼 파일

- `preview/index.html`: 사용자 조작으로 듣는 19종 및 타이핑 A/B/C 믹스
- `docs/AUTHORING_RULES.md`: 이후 모든 대사 작성자가 따를 공통 규칙
- `sound_events.json`: 시점·레벨·채널·중복 억제 규격
- `sound_manifest.json`: 19종 WAV/OGG, 길이·피크·해시·출처
- `docs/AUDIO_AUDIT.md`, `existing_runtime_audio.json`: 현재 연결과 누락
- `provenance_license_manifest.json`: 신규 원본과 기존 참조의 권리 구분
- `qa/digital_validation.json`, `qa/mix_comparison.json`: 객관 검사와 검증 한계

## 현재 코드에서 확인한 사실

1. `game/room13_rules.rpy:100-118`의 `r13_grant()`는 이미 `source_fx("found")`와 새 카드 호출을 한다. `room13_tool_discovery.rpy:145-147`도 새 기록에 found를 쓴다. 이 동작을 두 번 추가하지 않는다.
2. `game/room13_screens.rpy:265-269`의 `r13_material_corner`는 `on "show"`에서 `source_fx("page")`를 호출한다. 증거 제시음 역시 이미 존재하므로 교체/개선 연결이다.
3. `room13_dialogue_rhythm.rpy:76-96`은 실제 글자 표시를 따라 `type.wav` 첫 25ms를 틀지만, 모든 재생에서 첫 음만 사용한다. 새 자산은 이미 38ms 원샷이므로 다시 25ms로 자르지 않는다.
4. `screens.rpy:90-102`의 독백은 본문색만 바뀐다. 창 자체와 이름표가 구별되도록 바꿀 대상이다. `room13.rpy:36-43`의 `r13_thought_active` 계약을 존중한다.
5. 중요어 공통 토큰/범위 계약은 현행 room13 소스에서 확인되지 않았다. 기존 읽음·히스토리 문자열을 유지한 별도 표시 경로가 필요하다.
6. `room13_revision.rpy:13-71`: 주방 레버 on/off는 같은 tap, 책장 해제는 door, 잠긴 책장/안쪽 출구는 별도 효과음이 없다. 상태별 5종으로 구별한다.
7. `room13.rpy:478-481`: 문틀 강제 개방은 impact다. 사건 확정 직후 장면 전환이 `scene_fx`를 정지하므로 새 660ms 소리를 무조건 같은 위치에서 재생하면 잘릴 수 있다. 강제개방 화면과 소리가 일치하는 연결점을 잡고, 장면 전환 잔향 보존을 검증한다.
8. `source.rpy:71-79`는 마차 관련 roll/carStop/carDepart/letter/tick2를 비활성화했다. 유지한다.

## 권장 구현 순서

### 1단계 자산과 중앙 매핑

선정한 WAV를 `game/assets/sfx/` 같은 새 하위 경로에 둔다. 원본 파일명을 덮어쓰기보다 `sound_events.json`의 논리 ID를 중앙 매핑해 구버전 복원을 쉽게 한다. 짧은 타이핑·UI음은 PCM WAV 우선, OGG는 대안이다. 현재 엔진/웹 빌드에서 실제 로드 가능성과 프리로드를 검사한다.

### 2단계 단일 사건 디스패처

채널은 typing / ui_sfx / scene_fx / transition_sfx처럼 의미별로 분리한다. 기존 `scene_fx` 한 채널에 typing을 붙이지 않는다. 하나의 정상 채널은 한 번에 한 파일을 재생한다. 모든 새 이벤트는 mute·skip·menu·load 상태, 이벤트 ID 등록, 반복 억제, 같은 프레임 우선순위 검사 후 발행한다. 타이핑보다 증거/모순 신호가 우선이지만 중요 이벤트가 끝난 뒤 밀린 타이핑을 재생하지 않는다.

### 3단계 실제 상태 커밋과 연결

획득은 `added`가 비어 있지 않을 때 한 번. 제시는 명시적인 확정 이후 한 번. 읽기·선택만으로 정보 공개를 하지 않는다. 추론 성공·모순은 시스템의 검증 결과를 받아 사용자가 그 결과를 보게 되는 지점에 연결한다. 표정·색·소리 때문에 추론 판정과 인물 지식이 바뀌면 안 된다.

### 4단계 표시용 메타데이터

기존 `r13_lines` 패킷의 세 번째 메타데이터와 명시적 thought를 확장하되 원문·읽음 ID는 유지한다. 중요어 metadata를 검증한 뒤 표시 토큰으로 변환한다. 새 필드를 무시하는 안전한 기본값과 old-save 호환 처리를 둔다. 구두점 리듬 변환과 강조 태그가 서로 중복 태그를 만들지 않는지 테스트한다.

### 5단계 믹스와 설정

시작값: 사용자가 선택한 기존 music/sfx 값은 유지하고, 대사 중 music 채널에만 0.5(-6dB) 계수를 곱한다. 타이핑 channel_gain 1.0, 증거 획득 0.70. 이것은 최종 정답이 아니라 청음 시작값이다. 코드가 사용자의 볼륨을 0.75/0.7로 매번 덮어쓰면 안 된다. duck의 원래 값을 보관하고 가장 강한 활성 요청을 사용한 후 정확하게 복귀시킨다.

## 반드시 확인할 회귀 테스트

- 동일 증거를 2회 획득 시도: 새 획득음/획득 카드 중복 없음
- E07/E08/E14처럼 다건 획득: 한 번의 음, 카드 순환 때 반복 없음
- 제시 선택 후 취소: 취소만, 자료 공개/제시음/추론음 없음
- 제시 확정: 일반 확인음과 제시음이 겹치지 않음
- 틀린 증거: 벌점·거절과 ‘모순 발견’을 혼동하지 않음
- 잠긴 책장, 레버 on/off, 안쪽 출구: 소리와 실제 상태 일치
- 문 강제 개방 → 구조 장면: 소리가 전환 직후 잘리거나 다음 줄에 늦게 나오지 않음
- 첫 클릭 전체 텍스트 표시, 빠른 연속 클릭, 스킵, instant text: 타이핑 즉시 종료
- 수첩/기록/저장/불러오기/메뉴: 새 탭이 나오지 않으며 복귀 후 과거 탭 누적 없음
- 생각 → 발화 → 생각, 선택지/불러오기: 파란 창 상태 누출 없음
- 강조어가 2번 나옴, 한글 조사, 보간, 중괄호, 구두점 휴지기, 줄바꿈: 원문·읽음 ID 동일
- PC/모바일 가로·세로, 기본/큰 글씨, 헤드폰/휴대폰 스피커, 음악·효과음 0: 접근성과 믹스 검사
- 실제 빌드의 크레딧 접근: `options.rpy:95`의 `build.classify("**.txt", None)` 때문에 소스에 있는 `.txt` 라이선스가 배포물에서 제외될 가능성이 있다. 최종 ZIP/웹 크레딧을 직접 확인하고 필요한 라이선스를 명시적으로 포함한다. 현재 감사는 배포 ZIP 내부 존재 여부를 검증하지 않았다.
