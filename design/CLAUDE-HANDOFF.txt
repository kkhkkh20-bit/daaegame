다람 탐정 사무소 — 디자인 연결 안내 v3

작업 대상: 원작 game.html. 35명 캐릭터, 16:9 메인 화면, 원작의 82개 조사 장소, 증거를 포함하는 5개 확대 조사 배경을 제작했다. 이 자료는 원작의 사건·대화·증거·잠금 조건에 연결하는 그림과 좌표다.

먼저 확인할 화면
/design/             캐릭터 35명·표정 및 82개 장소의 증거 클릭 미리보기
/design/play.html    현재 원작 game.html을 읽어 새 배경·NPC 그림·좌표를 적용한 실제 게임 미리보기
원작 파일은 수정하지 않았다. play.html은 원작 코드의 실행 사본에 어댑터를 연결한다.
미리보기 저장은 daram-art-preview-v3: 접두어를 사용해 원작 저장과 분리된다.
ZIP만 받았을 경우 /design/ 미리보기는 동작한다. play.html은 상위 폴더의 원작 game.html이 필요하다.
HTML은 file:// 대신 로컬 HTTP 서버에서 열 것: 프로젝트 폴더에서 python -m http.server 8070

다운로드
캐릭터·코드: daram-design-pack.zip
배경: daram-backgrounds-pack.zip
두 ZIP을 같은 프로젝트 폴더에 풀면 design/ 안으로 합쳐진다. 파일을 임의로 등분하거나 경로를 바꾸지 않는다.

캐릭터
원작 CAST/BIO/PERSONA를 기준으로 다람이를 제외한 본캐릭터 35명이다.
CAST의 37개 ID 중 luka와 shadow는 nero의 변장/정체 표시이며 별도 인물로 세지 않는다.
이 두 외형도 각각 제공한다. 검은 망토는 초반 정체를 숨기도록 얼굴을 가렸다.
뭉치(mungchi)는 판다이며 백 부인(madam)의 아들이다. 기존 다람이 그림은 그대로 유지했다.
표정 0=기본, 1=생각/의심, 2=감정. 경로와 표정 영역은 manifest.json의 characters[id]를 사용한다.
frames=[x,y,width,height]는 원본 PNG 픽셀 좌표다. 인물별 투명 영역이 달라 등분 좌표를 추정하지 않는다.
PNG의 alpha를 유지한다. 검은 배경으로 재합성하지 않는다.
기존 플레이어 아바타 det0/det1은 원작 pf를 유지한다. DaramArtKit.character(...,'daram')은 기존 다람이 그림 표시용이다.

배경·증거
16:9 그림을 장소별로 제공한다. 실제 조사 키는 cake-kitchen, window-under 등의 원작 SCENES 키다.
manifest.json의 locationOrder 82개 + main + forest-path는 서로 다른 84개 기본 배경이다.
zoomBackgrounds의 5개는 서랍/상자 안 증거용 확대 배경이다. 총 89개 그림이다.
cake, window 등 15개 사건 ID는 대표 장소를 가리키는 호환 별칭이며, 별도 그림이 아니다.
PNG 아틀라스는 2×2다. 배경 좌표는 manifest.json에서 읽는다. SVG clipPath로 인접 장면이 섞이지 않게 표시한다.
조사 화면은 전체 그림을 맞춰 넣는다. object-fit:cover나 SVG slice로 바닥·창틀을 잘라내지 않는다.
메인 화면 포스터는 의도적으로 slice를 쓸 수 있지만 조사 화면에는 쓰지 않는다.

scene-map.json
원작의 15개 사건, 82개 장소, 실제 증거 250개를 추출했다.
각 증거에는 spotId, evidenceId, 원작 설명/검사 정보, point, sourcePoint, uv, inZoom이 있다.
point는 새 그림 속 물건 중심을 검토한 좌표다. sourcePoint는 비교용 원작 좌표다.
좌표계는 원작 HOTS와 같은 360×200이다. left=point[0]/360*100%, top=point[1]/200*100%로 표시한다.
배경의 16:9 화면 안에서 같은 백분율로 배치한다. 픽셀 좌표와 혼동하지 않는다.
244개는 현장, 6개는 5개 확대 조사 내부에서 발견된다. 자외선 대상 14개는 자외선 켰을 때 표시한다.
노란 조사 표시는 증거만. 증거 아닌 관찰은 파란 표시다. 서랍 속 증거를 현장 바닥 위에 중복 배치하지 않는다.
zoomBackgrounds가 없는 원작의 나머지 15개 확대 관찰은 기존 ZART와 조사 조건을 유지한다.
디자인 작업실은 그림·설명 확인용이다. 증거 획득, 대화, 암호, 결합, 대결의 진행 검증은 play.html의 원작 코드에서 한다.

원작 통합 코드
<head>에 연결:
<link rel="stylesheet" href="design/game-scenes.css">
<script src="design/art-kit.js"></script>
<script src="design/scene-bridge.js"></script>

원작 IIFE 안에서 모든 CASES/HOTS/SCENES/ZART 패치가 끝난 다음 실행:
DaramSceneBridge.install({
  cases: CASES,
  scenes: SCENES,
  hots: HOTS,
  zooms: window.__ZOOM,
  zoomArt: ZART,
  portraitSetter: function(fn) { pf = fn; },
  portraitFallback: pf,
  refresh: function() { if (G) render(); }
}).then(function() {
  document.body.classList.add('daram-art-preview');
});

이 어댑터는 배경 함수, 증거 좌표, 관찰 좌표, 확대 조사 좌표·그림, NPC의 pf 표시를 연결한다.
대화·증거 설명·암호·증거 결합·추리 조건은 실행 중 원작 CASES를 그대로 사용한다.
원작의 동적 아빠 이름도 실행 중 원작에서 읽는다. scene-map.json의 정적 설명으로 원작 이름을 덮어쓰지 않는다.
증거 ID 불일치 시 오류를 내므로 시나리오를 수정했다면 scene-map.json도 대조한다.
공용 drawer ZART 키를 덮어쓰지 않고 daram-art-drawer1 등 개별 키를 붙여 서로 다른 서랍 그림이 섞이지 않게 했다.
portraitSetter를 생략하면 배경과 좌표만 연결할 수도 있다. 기존 플레이어 그림·알 수 없는 인물 ID는 fallback을 사용한다.
원작은 SVG를 자동 도트 변환한다. 새 인물 PNG는 이미 도트 그림이므로 어댑터의 g id와 nodot 표시를 유지할 것. 이 표시를 지우면 PNG가 하얀 네모로 재변환될 수 있다.
원작 스크립트 밖에서는 CASES 등 지역 변수를 직접 읽을 수 없다. play.js의 연결 훅 위치를 참고할 것.

개별 그림 표시
DaramArtKit.ready.then(function() {
  DaramArtKit.background(document.getElementById('scene-art'), 'cake-kitchen');
  DaramArtKit.character(document.getElementById('actor-art'), 'mungchi', 0);
});
부모에 크기를 정하고 .daram-art {width:100%;height:100%;display:block} 적용.
SVG 문자열이 필요한 경우 sceneMarkup(id), characterMarkup(id,expression)을 사용한다.
