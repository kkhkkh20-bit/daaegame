# 다람 탐정 · 그림과 개발 공유 폴더

현재 사용자가 확인한 제작 범위는 **등록된 미완료 요청 전체**입니다. 이번 납품은 D02, H01, F01, C02 정면 얼굴, T01, I01–I04, U01의 새 그림 65장입니다. R-005 다람 전신 수정 제안은 보류합니다. 첨부 문서의 미등록 전체 목록은 이번 범위에 포함하지 않습니다.

## 지금 읽을 자료

- `../production/index.html`: 얼굴 96px, 아이콘 22·32·36px, 언덕 조사 위치, 세로·가로 첫 화면, 나무 반복 바탕을 확인하는 미리보기.
- `../production/completion.json`: 이번 65장 생성 완료 여부와 묶음별 ZIP.
- `../production/HANDOFF-ALL.txt`: 전체 인계서. 묶음별 HANDOFF와 manifest에 실제 크기·공통 crop·투명도·SHA256·생성 프롬프트를 기록했습니다.
- `ready-assets.json`: 실제 존재하는 그림 파일 목록. 기존 승인 그림과 이전 납품도 함께 포함합니다.
- `requests.md`, `review.md`: Claude가 관리하는 새 요청과 실제 게임 화면 검토 결과. 생성 완료와 실제 게임 적용 완료는 구분합니다.
- `CONTEXT.md`: 승인 이유와 이야기 톤의 요약. `art-brief-original.docx`, `art-brief-reference.txt`, `briefs/`는 원본 작업지시서와 참고 목록입니다.

## 완료된 그림과 원본 보존

B01·B02 배경과 D01 정면 얼굴은 이전에 납품했습니다. 이번 D02를 더하면 다람 얼굴은 총 8표정입니다. C01·C02 전신 시트 6명은 다른 채팅 브랜치의 PNG를 바꾸지 않고 `../chars/`에 보관했습니다. 아빠·레이·까로·부리·왕구·도토의 정면 얼굴은 별도 파일로 추가했습니다.

승인된 기준은 `../star-hill-enriched.png`, `../daram-matched.png`, `../stickers/`입니다. 새 그림도 같은 단순한 덩어리와 네모 픽셀 표현을 참조했습니다. 이전 `design/characters/v4/`는 역사 자료입니다. 생성 원본은 정확한 26색이나 128×128 납품으로 검증된 파일이 아니므로 실제 크기는 manifest를 읽습니다.

그림은 `design/retro/`에 사본으로 전달합니다. `game.html`, 루트 `index.html`, `dot.html`, `sw.js`, `art/`와 승인 PNG는 이 작업에서 변경하지 않습니다. 게임용 축소·색상 정리·반투명 가장자리 정리와 실제 적용은 Claude가 게임용 사본에서 수행합니다.

## 같은 그림체와 이야기 설정

다람의 성장과 관찰·판단 과정을 중심에 두며 과장된 유아용 표현을 피합니다. 머리는 동물 머리, 손은 동물 앞발이나 날개 끝, 눈은 같은 방식의 둥근 눈과 작은 하이라이트로 맞춥니다. 전신은 방향이 있어도 되지만 대화창 얼굴은 두 눈이 보이고 시선이 플레이어를 향해야 합니다.

다람과 엄마는 일반 다람쥐로 확정되어 비막을 추가하지 않습니다. 엄마는 접이식 천 활공 장비를 쓰는 과학자입니다. 솜이는 날다람쥐입니다. 등불지기는 수달이며 문서에 남은 토끼 문구를 사용하지 않습니다. 아빠는 너구리이고 이름은 게이머가 선택합니다.

## 작업 전달과 병행

Claude는 저장소 최신 버전을 받은 뒤 `ready-assets.json`과 전체 인계서를 읽으면 됩니다. 파일을 하나씩 채팅에 첨부할 필요가 없습니다. `claude-ack.json`은 읽은 Claude가 기록하는 파일이며 이번 새 납품의 수신 확인을 대신 표시하지 않습니다.

각 채팅은 담당한 `parallel/<묶음>.json`과 결과 파일을 관리합니다. 상대 묶음 JSON, Claude의 요청·검토 기록, 원본 게임은 덮어쓰지 않습니다. 공용 목록은 최신 원격 자료에 기존 항목을 보존해 병합합니다. 채팅별 worktree를 사용하고 강제 푸시는 하지 않습니다.

폴더는 실시간 채팅 연결이 아닙니다. 다음 작업 대화에서 새 요청을 읽어 이어갑니다. 오래된 `status.json`이나 계획 목록의 초기 상태 대신 납품 manifest, 묶음 JSON, 실제 게임 검토 기록을 함께 확인하세요. 이후 미등록 캐릭터·배경은 새 요청에 따라 진행합니다.
