다람탐정 장면 실행 구조 점검 / 2026-10-12

현재 연결 구조
- chapter-source.json: 캡처한 원본 사건 데이터. 직접 변경하지 않는다.
- chapter-dialogue.json: 원본 섹션에 적용하는 현재 대본.
- village-story.json: 마차, 마을 탐색, 여관 도착의 별도 대본.
- source_scenes → source_lines: 장면 목록과 대사/명령을 순서대로 실행.
- source_picture/source_bg: camera, background, night 상태로 실제 그림 선택.
- source_face: 발화자 별칭, 표정, 인터뷰 인물 배치. CG에서는 visitor 숨김.
- options.text_audio: Character 콜백으로 얼굴 식별자와 타이핑 효과음 관리.
- source_score/source_fx/source_pulse: BGM, 단발 효과, 긴장 채널.
- arrival_place/source_roam: 장소 진입과 조사 화면. 대화 종료 뒤 호출 화면으로 복귀.
- village-state/timeline/village_people: 시간, 발견, 관계, 증언 조건.
- council_issue/source_rounds: 여론 쟁점과 기존 회의·대결. 화면 실행과 증거 판정은 분리.

확인한 반복 오류의 원인
1. 장면 진입, 대사 중 camera 명령, 장소 이동에 암전/음악/초기화 코드가 중복됨.
   일부 경로는 음악을 암전 전에 변경하고 일부는 뒤에 변경한다.
2. source_face가 narr의 얼굴을 None으로 정해도 source_thought의 cb_who_id=dad가
   Character 시작 콜백에서 이를 덮어썼다. 이제 무명 나레이션은 cb_who_id=None.
3. visitor, 증거 오버레이, 타이핑, pulse, 단발 효과의 종료 책임이 분산되어 있음.
4. source_lines에는 특정 대사 문자열을 조건으로 솜솜 CG/심장음이 작동하는 예외가 남음.
   문장을 고치면 연출이 빠질 수 있다. 이번에는 사건 연출을 무리하게 전환하지 않았다.
5. 데이터 명령은 elif 우선순위이므로 dir와 대사가 한 객체에 있으면 dir만 실행된다.
   파일 작성 시 명령과 대사를 별도 항목으로 둬야 한다. 향후 스키마 검사 대상.

첫 적용 범위와 공통 계약
- scene_runtime.rpy의 scene_present(spec)를 마차 진입, 마차 카메라 전환,
  탐색 장소 진입에 적용. 기본 시작은 부녀의 마차 대화. 범죄 인트로 label은 보존.
- spec: sid/title/sub, camera, bg 또는 loc, night, who, music.
- 순서: 대화창/visitor/증거 숨김 → 이전 소리/얼굴/표정 상태 정리 → 암전 완료
  → 목적지 BGM 선택 → 0.3초 선행 → 그림 등장 → 호출자에게 복귀 → 대사.
- 같은 BGM이면 재시작하지 않는다. pulse와 typing은 이전 장면에서 이어오지 않는다.
- 표정은 각 대사의 source_face가 선택한다. 장면 기본 표정은 neutral.
- 진행은 Ren'Py label/call과 store의 직렬화 가능한 dict/list만 사용.
  별도 JS 타이머, 비동기 이미지 교체, 저장되지 않는 외부 진행 객체를 만들지 않는다.
- 위치/시간/증거/관계 판정은 기존 담당 함수 유지. 실행기는 증거를 부여하지 않는다.
- 저장/불러오기는 Ren'Py 실행 위치, 화면, 음악 복원 사용. after_load에서 장면을
  처음부터 재생하지 않는다. 그러면 대사/효과/분기 보상이 중복될 수 있다.

UI
- 기존 얼굴 리소스 유지, 130px → 196×204 표시 영역.
- 169px 대화창보다 높은 210px 초상화 카드, 윗부분 59px 돌출.
- 텍스트는 얼굴 오른쪽 910px 영역, 얼굴이 없는 문장은 1120px 영역 사용.
- 크림 글자/황동 테두리/짙은 갈색 패널로 대화창과 카드 통일.
