# 0.18.56 — 실제 원탁·제단 회의 캡처

`dev/qa_meeting.py`로 배포할 웹 게임을 열어 실제 레이블·화면 액션을 실행했다. 새 게임을 시작한 뒤 날짜, 소유 자료, 회의 시작 위치를 명시적으로 준비한 장면 검사다. 14일 전체 완주 검사나 신규 증거의 획득 경로 검사로 해석하지 않는다.

- 7일째 시작 대사 → 원탁 전체 → 논점 선택 → 중앙 화자와 양쪽 이웃.
- 대사 도중 자료창을 열었다 취소: 입증 상태가 변하지 않고 원래 대화의 다음 부분을 계속함.
- 되묻기 마지막 대사에서 드러난 숨은 주장을 E05로 즉시 반박: 원래 대화 커서·읽음 ID를 복원하고 원래 질문 완료로 정상 복귀.
- 제시 도구/물건을 재판 근거에 섞지 않고, 소유한 증거·증언만 제출.
- 발언 기록 재선택, 가로 모바일 844×390, 큰 글씨.
- 잘못된 결론은 입증되지 않고 다시 공방으로 돌아감. 맞는 결론 뒤 기존 r13_prove가 입증하고 주민들의 현재 표를 공개함.
- C1에서 입증한 통로가 C2에서 다시 반론으로 돌아옴. 잘못된 답변은 해당 발언이 깨지지 않으며, 주방 레버 조건으로 답하면 기존 관문에 따라 입증됨.
- 회의 중단 확인 취소로 진행 유지.
- 14일째 실제 제단 논점 화면·화자 구도. 나무 탁자·의자 없이 석판 둘레에 서 있음.
- F3 인력 준비는 자료를 내는 것만으로 생기지 않음. 실제 준비 플래그와 기존 증언 동의·집행 조건을 유지함.

투표는 결론에 대해 아빠가 밝힌 의견과, 입증으로 바뀐 기존 주민 입장을 기록·공개한다. 과반수로 증거 부족이나 동의·집행·구출 관문을 대체하지 않는다.

단위 161개, Ren’Py compile/lint, 위 실제 브라우저 검사 통과. 카메라 함수는 화자 변경 때만 시각 상태를 바꾸며, 같은 화자·아빠의 답변·효과 정지에서는 반복 이동하지 않는 것을 검사했다. 최종 UI의 잠긴 논점 사유도 별도 화면으로 확인했다.

대사 중 제시는 별도 UI 실행 문맥에서 처리한다. 취소 뒤 같은 문장·페이지·화자·읽음 ID가 유지되는지, 자료창을 연 상태로 저장·불러온 뒤에도 원래 상호작용으로 복귀하는지를 실제 브라우저에서 추가 확인했다. 제시 직후 아빠가 말할 때는 반박 대상자를 비춘다.
