다람탐정 — Ren'Py 8.5.3 웹 엔진 검증 시제품
================================================

목적
현재 HTML 게임의 공개본과 v2를 보존하고, Ren'Py가 우리 게임의 조사·증거·회의를
감당하면서 제작 구조를 단순하게 만드는지 확인한다. 첫 장 전체 이식이나 확정
시나리오 재작성은 아니다. 실제 기존 승인 자산을 사용한 약 5분의 제한된 구간이다.

테스트 주소
https://kkhkkh20-bit.github.io/daaegame/preview/renpy-ch1-test/

플레이 범위
- 부녀 마차 대화와 마을 접근 CG
- 사건 직후 열세 번째 침대 조사: 베개, 이불, 침대 아래
- 증거 획득, 중복 획득 방지, 증거 수첩
- 핵심 증거 두 개가 없으면 회의 진입 제한
- 회의 되묻기, 관련 없는 증거에 대한 반응
- 주머니 → 털 자국 또는 털 자국 → 주머니 모두 허용하는 비교
- 확인된 접촉과 입증되지 않은 범행을 구분하는 결론 선택
- 엔진 기본 저장/불러오기, 조사 및 회의 중간 복귀
- 원래의 봉인·붉은 자국 소재를 사용한다. 이 구간에서는 범인을 확정하지 않는다.

조작
대사 화면을 클릭/터치해서 진행한다. 조사에서는 배경의 베개, 흰 손자국,
침대 아래를 누른다. 우측 상단은 증거 수첩 / 저장 / 메뉴이다.
작은 휴대폰은 가로 화면을 권장한다. 브라우저 확장 메뉴에서 저장 파일을
가져오거나 내보낼 수 있다. 일반 웹 저장은 같은 브라우저·같은 사이트의
IndexedDB에 보관된다. 브라우저 저장 데이터를 지우면 웹 저장도 사라진다.

제작 구조
game/story.rpy       : 장면 순서, 대사, 증거 반박과 추론 흐름
game/screens.rpy     : 대화창, 조사 핫스폿, 증거창, 회의, 저장 UI
game/options.rpy     : 설정, 저장 가능한 상태, 증거 목록, 이미지 선언
prepare_assets.py    : 기존 승인 자산의 원본 복사 및 한글 폰트 형식 변환
build_web.py         : 공식 SDK의 웹 빌드 + 게임 톤의 HTML 로딩 화면
qa_web.py            : 실제 WASM을 포인터로 플레이하는 Playwright 회귀 검사
progressive_download.txt : 이 작은 시험에서는 자산을 초기 파일에 포함

준비 및 재빌드
1. Ren'Py 8.5.3 SDK와 같은 버전의 web/ 지원 파일을 설치한다.
   공식 배포: https://github.com/renpy/renpy/releases/tag/8.5.3.26051504
2. python3 -m pip install -r experiments/renpy-ch1/requirements.txt
3. python3 experiments/renpy-ch1/build_web.py --sdk /absolute/path/to/renpy-8.5.3-sdk
4. 저장소 루트에서 python3 -m http.server 8093
5. http://127.0.0.1:8093/preview/renpy-ch1-test/ 에 접속한다.
6. python3 experiments/renpy-ch1/qa_web.py
   기본 QA는 시스템 chromium을 사용한다. 없다면 Chromium을 설치하거나
   qa_web.py의 실행 경로를 설치한 Playwright 브라우저에 맞춘다.

PC에서 실행
prepare_assets.py를 먼저 실행한 뒤, Ren'Py Launcher에서 이 프로젝트를 열거나
SDK의 renpy.sh /absolute/path/to/experiments/renpy-ch1 를 실행한다.
원격 작업 환경의 빌드 도구는 SDL dummy 드라이버를 사용한다. PC 플레이는 일반
그래픽 드라이버로 실행해야 한다.

자산과 사운드
원본 이미지·음악은 교체/수정하지 않는다. assets/provenance.json에 원본 경로와
SHA256을 남긴다. 표정은 기존 PNG atlas를 Ren'Py Crop으로 실행 중 표시한다.
Galmuri는 기존 OFL 폰트를 woff2에서 ttf로 형식 변환했고 라이선스를 동봉한다.
기존 여행/조사/심각한 상황 음악을 각각 연결했다. 새 음악 제작·품질 개선을
평가하는 빌드는 아니다. 음성 채널은 사용할 수 있으나 실제 캐릭터 더빙 파일은
이번 시험에 포함하지 않았다. 보유하지 않은 TTS 녹음을 생성했다고 표시하지 않는다.

검증 기준
단순 대사 클릭뿐 아니라 조사 → 증거 획득 → 회의 → 반박 → 결론까지 완주한다.
1280×720 마우스와 844×390 터치에서 증거를 반대 순서로 제시한다.
조사 전 연타, 회의 진입 제한, 재방문 중복 획득, 오답 반응, 과잉 결론 거부,
조사 및 반박 중간 저장 복귀, 페이지 새로고침 뒤 저장 유지까지 확인한다.
WASM 상태는 SDK의 renpy_exec를 통해 읽기만 하며 테스트가 증거나 진행을
주입하지 않는다. 엔진의 스크립트 린트도 실행한다.

현재 평가 범위의 한계
브라우저 자동 검사는 실제 iPhone Safari 실기기나 청취 검사를 대신하지 않는다.
첫 접속에는 엔진과 자산을 다운로드해야 한다. '처음부터 로딩 없음'을 약속하는
실험이 아니다. 전체 1장, 10인 회의, 대규모 자산, 모바일 스토어 빌드는 별도 검증이
필요하다. 이 프로젝트의 저장은 기존 HTML/v2 저장과 호환되지 않는다.
작은 시제품을 완주했다는 사실만으로 전체 이전을 확정하지 않는다.

실제 시험에서 찾은 구현 문제
- 게임 메뉴는 조사 화면과 HUD보다 높은 순서에 표시해야 한다.
- 전환 중에는 엔진이 입력을 받지 않으므로 QA도 전환 완료 후 클릭해야 한다.
- config.save_directory는 literal define으로 지정해야 저장 경로 계산에 반영된다.
  init python 안에서만 지정하면 game/saves에 저장해 웹 새로고침 시 사라졌다.
이 문제들을 수정한 뒤 최종 QA 결과를 QA_REPORT.json에 기록한다.
