# 화면 픽셀 1칸 통일 제안 (2026-10-16, 결정 전)

- 요청(소유자): 최종 화면에서 인물마다 픽셀 1칸 크기가 달라 다른 세계 사람처럼 보인다. 디테일을 살리면서 통일한다.
  - 원본이 2×2라는 것만으로는 완료가 아니다.
  - 키를 일괄 ±20% 바꾸거나 부드럽게 뭉개지 않는다.
  - 배경은 그대로 두고 캐릭터를 먼저 맞춘다.
- 이 문서는 **제안**이다. 게임 동작은 바꾸지 않았다.
  - 미리보기를 위한 시험 스위치 두 개만 넣었다. 기본값에서는 아무 효과가 없다.
  - `store.r13_pixel_k_preview`(기본 None), `R13_CLOSE_PIXEL_GRID` 실행 중 교체
- 비교 캡처는 실제 엔진에서 찍었다(화면 테스트 `pixel_unify_preview`): `reports/pixel-unify-20261016/`
  - `now_vs_k4_1280.jpg`: 1280×720에서 지금(위)과 제안(아래)
  - `now_vs_k4_zoom6.png`: 얼굴을 6배 확대한 것
  - `*x15_*.png`: 1920×1080 창(1.5배)
- 측정 도구: `dev/qa_pixel_grid.py`. 근거 수치: `docs/PIXEL_GRID_CHECK_20261016.md`

## 지금 상태 (실측)

| 화면 | 인물 | 1칸 크기 (1280×720 창) |
|---|---|---|
| 대화 | 2×2 묶음 인물 중 다람·밤이·나비·초롱·부리 v7 | 5px |
| 대화 | 2×2 묶음 인물 중 아빠·톡·서리·까로 등 | 4px |
| 대화 | 고해상도 그림 인물 46명(사자·너울·네로·콩이 등) | 3px 격자 |
| 조사 | 모든 인물 | 2px 격자 |
| 1920×1080 창 | 묶음 인물 | 4px가 6px로, 5px가 7·8px 섞임으로 바뀜 |
| 1920×1080 창 | 3px 격자 인물 | 3px 그대로(창 배율을 따라가지 않음) |

- 마지막 줄의 원인: 격자 인물은 저해상도 텍스처를 '실제 창 해상도'로 굽는다(`Flatten` 기본값 `drawable_resolution=True`). 그래서 창이 커져도 블록이 3px로 남고, 묶음 인물(6px)과 차이가 더 벌어진다.

## 제안 1 — 대화: 2×2 셀 하나 = 화면 4px로 고정

- 지금은 인물마다 '그림 키를 화면 880px에 맞춘 뒤 가장 가까운 정수배'를 고른다. 그래서 4px와 5px가 섞인다.
- 제안: 모든 2×2 그림을 **같은 4px**로 그린다. 그러면 화면 키는 그림의 셀 수가 정한다.

| 인물 | 키(셀) | 지금 화면 키 | 4px 고정 |
|---|---|---|---|
| 아빠 | 222 | 889 | 889 |
| 돌목 | 218 | 873 | 873 |
| 서리 | 220 | 879 | 879 |
| 톡 | 204 | 818 | 818 |
| 다람 | 190 | 951 | 761 |
| 나비 | 189 | 947 | 757 |
| 부리 v7 | 184 | 920 | 736 |
| 밤이 | 165 | 827 | 661 |
| 초롱 | 167 | 837 | 670 |

- 바뀌는 것은 5px 인물 5명뿐이다(−20%).
  - 이것은 일괄 축소가 아니다. 지금이 오히려 아이(다람·밤이·부리 소년)를 어른보다 크게 보이게 하고 있다.
  - 4px로 고정하면 아이가 어른보다 작게 나와서, 그린 사람이 정한 체급(공통 캔버스)대로 돌아간다.
- 머리 위치는 지금처럼 위쪽 정렬을 유지한다. 키가 작은 인물은 다리가 더 보인다.
  - 원하면 아래 정렬(발 바닥선 공통)로 바꿀 수 있다.
- 초롱(167셀)은 어른인데 짧게 그려져 있다. 체급을 맞추려면 그림을 다시 받아야 한다(엔진에서 늘이지 않음).

## 제안 2 — 셀이 없는 고해상도 그림 46명

| 방법 | 화면 | 디테일 | 비고 |
|---|---|---|---|
| A. 지금(3px 격자) | 3px 블록 | 지금 수준 | 4px 인물과 섞임 |
| B. 4px 격자로 바꿈 | 4px 블록(통일) | 블록 수 25% 감소, 얼굴이 거칠어짐 | 비교: `now_vs_k4_zoom6.png` 사자·네로·콩이 |
| C. 2×2 대화 그림을 새로 받음 | 4px(통일) | 그린 대로 보존 | 제작 필요 |

- 추천은 C다. C가 오기 전까지는 A를 유지한다. B는 디테일을 잃으므로 추천하지 않는다.
- C의 제작 기준: 2×2 셀, 공통 캔버스, 키를 셀 수로 지정한다.
  - 어른 약 205~222셀(410~444px)
  - 청소년 약 185~190셀
  - 어린아이 약 165셀
- 사자 선생님·너울은 통합68 원본(1024×1536)이 이미 2×2다. 다만 키가 약 710셀(사자)·750셀(너울)이라 4px로 그리면 화면의 세 배가 넘는다(1칸=1px여야 화면에 들어감).
  - 1.095배 보정과 1/2 축소는 둘 다 정수배가 아니라서 셀이 합쳐지거나 빠진다.
  - 디테일을 보존하려면 GPT가 목표 셀 수(약 210셀)로 다시 그려야 한다. 엔진 축소로는 보존할 수 없다.
  - 두 사람은 옷 결정이 대기 중이므로, 결정된 옷으로 함께 요청하는 것이 좋다.

## 제안 3 — 조사 화면

- 지금도 모든 인물이 2px 격자(측정 0.98~1.00)다.
- 원본을 0.5배로 들여올 때 매끄럽게 줄이던 방식은 2×2 원본에 한해 0.19.0부터 '셀마다 1점'으로 바꿨다(부리 v7 동작 3종, 토실, 실룩).
- 자리마다 키가 달라서(230~360px) 블록 하나에 들어가는 원본 셀 수는 인물마다 다르다.
  - 완전히 맞추려면 자리별 키에 맞춘 조사 전용 그림(예: GPT 화면용 174/248px 후보)이 필요하다.
  - 우선순위는 대화 다음이다.

## 제안 4 — 창·모바일 배율

- 화면 전체 배율을 0.5 단위(0.5, 1, 1.5, 2, 2.5…)로만 쓰고, 남는 곳은 레터박스로 채운다.
  - 이렇게 하면 4px와 2px 블록이 어느 창에서도 정수로 남는다. 4×1.5=6, 2×1.5=3, 4×0.5=2.
  - 3px 격자는 1.5배에서 4.5px가 되어 정수가 아니다. 제안 2-C가 끝나야 완전해진다.
- 예

| 창 | 쓰는 배율 | 레터박스 |
|---|---|---|
| 1920×1080 | 1.5 | 없음 |
| 2560×1440 | 2.0 | 없음 |
| 1366×768 | 1.0 | 가장자리 |
| 844×390(모바일 가로) | 0.5 | 640×360으로 작아짐 |

- 모바일에서 0.5가 너무 작다고 판단하면, 모바일만 지금처럼 꽉 채우고 '정수 아님'을 받아들이는 선택이 있다.
- 함께 고칠 것: 격자 인물의 `Flatten(..., drawable_resolution=False)`. 저해상도 텍스처를 논리 해상도로 구워야 창 배율을 같이 따라간다. 1280×720 창에서는 결과가 같다.
- 구현 위치
  - `config.adjust_view_size`: 창 안 보기 크기를 0.5배 단위로 고름
  - `game/room13_acting.rpy`의 `r13_pixel_scale`
  - 브라우저판도 같은 Ren'Py 경로를 쓴다.
