# 이동·조사 UI 사용성 개선 기획

상태: **조사·기획 완료, 게임 코드 미수정**. 기준0.19.47 / ec6acca9. 사용자의 기준은 직관성·편의성·미관이며, 조사 대상이나 현재 시점을 놓치는 일이 없어야 한다.

근거: [실제 화면·재현 결과](../reviews/investigation-usability-20261018/README.md). PC1280×720와844×390 터치·큰 글씨에서 제한적인2일차 UI fixture를 사용했다. 새 전체 스토리 플레이 리뷰나 실제 휴대폰 하드웨어 테스트는 아니다. 처음 보는 이용자의 성공률은 별도 플레이 테스트로 확인해야 한다.

## 판단

공통 부품의 규격만으로 현장 사용성을 보장할 수 없다. 실제 조작에서는 **이동 버튼과 조사 대상의 충돌**, **시야와 선택 대상의 불일치**, **화면 모드와 조사 행동의 구분 부족**이 남아 있다. 디자인 장식을 추가하기 전에 이 세 가지를 먼저 해결한다.

## 확인한 문제와 우선순위

| 번호 | 우선순위 | 실제 관찰 | 이용자에게 생기는 문제 |
|---|---|---|---|
| U01 | P0 | 여관 열쇠의 화면 좌표 중심(1105,221)이 ‘여관 밖으로’ 버튼 안이다. PC/터치 모두 열쇠 중심을 누르면 지도가 열리고, 아래쪽을 눌러야 열쇠가 선택된다 | 물건을 조사하려다 이동 메뉴가 열려 무엇을 눌러야 하는지 신뢰하지 못함 |

| U03 | P0 | ‘주변 살피기’는 모드 전환, ‘살펴보기’는 조사 실행인데 이름과 돋보기 아이콘이 매우 비슷하다. 조사 지점 버튼도 돋보기다 | 화면 전환과 실제 행동을 혼동함 |
| U04 | P1 | 대화 모드로 여관에서 나가면 복도·13호실도 대화 모드를 이어받는다. 이때 물건 버튼은 비활성이고 선택 안내도 사라진다 | 새 장소의 배경을 눌러도 반응하지 않아 조사할 것이 없다고 생각할 수 있음 |

| U06 | P1 | 13호실에서 마을 지도를 열면 상단 현재 위치는13호실이지만 여관 건물에는 현재 위치 표식이 없다. ‘현재’ 판정이 마을 노드와 방 이름을 직접 비교한다 | 방이 어느 건물 안인지 지도로 파악하기 약함 |
| U07 | P1 | 지도 선택 강조는 얇은 밑줄, 현재 위치는 작은 글씨다. 지도 하단은52/56px 높이로 현장 큰 글씨80px보다 작다. 비활성 모임 시기에도 선택 장소에 회의 종류가 붙는다 | 목적지·현재 위치·행사 정보가 섞이며 지도 조작의 중요도가 약함 |

U01은 공통 부품을 인접 이동 행에 적용하면서 배경과의 겹침을 놓친 회귀다. 이를 먼저 정정한다. U05는 물리적 크기와 정보 표시 방식의 위험 평가이며, 특정 이용자가 반드시 실패한다는 뜻은 아니다.

## 1차 구현: 눌렀을 때 예상한 일이 일어나게 한다

### 이동 UI를 조사 공간에서 분리 — U01

현장 중앙의 상시 인접 이동 행과 중복된 지도 버튼을 정리한다. 하단은 같은 공통5칸을 유지한다.

`주변 조사 | 사람과 대화 | 조사하기 | 이동 | 기록`

현재 하단 ‘더보기’를 ‘이동’으로 교체하고 메뉴는 이미 있는 우측 상단 공통 메뉴에 둔다. 이동을 누르면 현재 장소와 인접 목적지를 보여주는 짧은 패널을 연다. 각 항목은 ‘13호실로 이동’처럼 행동을 명시하고, 누르면 이동한다. ‘전체 지도’도 이 패널에서 제공한다. 인접 목적지는 숨은 스크롤 없이 모두 보이게 한다.

목표는 **인접 이동2탭 이내**, 배경을 덮는 상시 이동 행 제거다. 기존1탭 바로 이동에 비해1탭이 늘어나는 비용이 있으므로 실제 시안에서 빠른 왕복과 배경 가림을 함께 평가한다. 전체 지도까지 반복 진입하게 만드는 방식은 피한다. 지도·인접 이동은 같은 장소 해금/이동 가능 판정을 사용한다.

완료 기준: 열쇠의 대표 터치점을 누르면 열쇠가 선택된다. 이동 패널이 닫혔을 때 어떤 인접 이동 버튼도 조사 영역을 가로채지 않는다. 모든 장소·시간대의 표시 가능한 조사 대상에 대해 대표 터치점과 UI 겹침을 점검한다.

### 선택 대상과 시야를 묶는다 — U02

물건을 고르면 배경의 그 물건에 얇은 먹색 모서리 표식을 유지한다. 표시 위치는 이름 안내·조사 실행과 같은 대상 ID를 사용한다. 배경을 움직여 물건이 시야에서 완전히 사라지면 선택을 해제하고 조사 버튼을 비활성으로 돌린다. 다른 장소로 이동할 때도 선택을 해제해서 돌아왔을 때 오래된 선택이 되살아나지 않게 한다.

자동 카메라 이동으로 이용자의 시점을 빼앗지 않는다. 조사·기록을 닫을 때는 기존에 잘 작동하는 장소별 카메라 위치 복귀를 보존한다.

완료 기준: 코트를 화면 밖으로 밀면 코트 조사 버튼이 켜져 있지 않는다. ‘화면 표식 / 이름 / 실행 대상’이 항상 일치한다. 지도·기록을 취소하면 원래 시점으로 돌아온다.

### 모드·선택·실행의 말을 나눈다 — U03

‘주변 살피기’를 **‘주변 조사’**, 실행 버튼 ‘살펴보기’를 **‘조사하기’**로 구분한다. 선택 전 안내는 ‘물건을 고르면 조사할 수 있어요’, 선택 후에는 실제 물건 이름을 보여준다. 최초 한 번은 ‘물건 선택 → 조사하기’의 짧은 설명을 제공한다.

모드 선택은 차분한 선택 표시, 실행 가능한 조사 버튼은 금색 강조로 구분한다. 같은 크기·재질 안에서 현재 상태와 주요 행동의 표현을 나눈다. 대상에 붙는 표식은 작은 먹색 표식으로 통일하고, 큰 노란 테두리·점멸·반짝임·노이즈는 추가하지 않는다.

완료 기준: 호버 없이도 현재 모드, 고른 대상, 다음 행동을 화면만 보고 확인할 수 있다. 선택만으로 조사 대사나 시간 진행이 시작되지 않는 안전한2단계를 보존한다.

## 2차 구현: 놓치지 않고 돌아다니게 한다

### 첫 방문과 재방문 모드 — U04

처음 들어간 장소는 주변 조사로 시작한다. 재방문은 그 장소의 마지막 모드·카메라를 복원하는 안을 우선 시안으로 검토한다. 한 장소에서 선택한 대화 모드가 새 장소의 물건 조사를 막는 전역 상속은 정리한다.

대화 모드에서도 ‘지금은 사람과 대화 중’이라는 짧은 상태를 유지해서, 물건을 보려면 어디를 눌러야 하는지 알 수 있게 한다. 새 UI 상자를 계속 추가하지 않고 기존 대상 안내 자리를 활용한다.

완료 기준: 여관에서 대화하다 처음13호실로 이동해도 물건 조사를 놓치지 않는다. 대화를 닫고 같은 장소의 다른 인물에게 말 거는 흐름도 늘어지지 않는다.

### 표식·터치·살펴봄 상태 — U05

첫 실행에서는 조사 표식을 켠 상태를 기본으로 검토하고, 이용자가 끈 설정은 기억한다. ‘조사 지점’ 버튼은 켬/끔 상태를 명시한다. 숨겨진 물건이나 아직 조건을 만족하지 않은 대상은 표시하지 않는다.

작은 표식의 시각 크기와 실제 누르는 영역을 분리한다.844×390 기준으로 약43~46픽셀 수준이 되도록 게임 좌표80~84px의 터치 영역을 검토하되, 인접 대상과 겹쳐 잘못 선택되지 않게 실제 좌표를 함께 검사한다. 드래그는 화면 이동, 짧은 탭은 선택으로 분리하고 스와이프 끝에 조사가 실행되지 않게 한다.

‘살펴봄’은 ‘해결 완료’와 구분한다. 기존 체크를 유지하되, 조건 변화로 실제 읽을 내용이 달라졌을 때 새 내용을 어떻게 표시할지 별도 점검한다. 미발견 개수나 전체 완료율로 숨은 단서·미래 사건을 노출하지 않는다. 이 부분은 이번 재현에서 검증한 버그가 아니라 후속 점검 항목이다.

### 지도에서 현재·목적지·행사 정보 분리 — U06/U07

마을 지도에서 여관 방 안에 있을 때는 여관 건물을 현재 위치로 표시하고, 문구는 ‘마을 › 여관 ›13호실’처럼 상세 경로를 유지한다. 현재 위치와 선택 목적지는 서로 다른 모양과 문구로 표시한다. 색 하나에만 의존하지 않는다.

선택한 목적지 이름은 이동 버튼 가까이 명시한다. 지역 전환·이동 실행·현장 복귀를 구분하고, 터치·큰 글씨에서도 충분한 높이와 같은 내용 정렬을 사용한다. 지도 그림과 글씨를 가리지 않는 위치는 실제 시안에서 검수한다.

회의 종류는 해당 장소·시기에 알려진 모임이 있을 때만 보조 정보로 보여주는 안을 검토한다. 목적지 이름을 다른 방이나 미래 행사 정보로 오해하지 않게 한다. 왕복 편의가 더 필요하면 기존 지도/이동 패널 안에 ‘최근 방문’ 최대3개를 검토하며, 상시 버튼을 추가하지 않는다. 이용 가능한 장소만 표시한다.

## 유지할 동작

실제 확인에서 지도 선택·취소는 전체 진행 상태와 카메라를 보존했다. 여관→복도→13호실, 터치 지도13호실→학교→13호실 이동이 동작했고, 장소별 시점도 복원됐다. 기록 창을 닫고 돌아오는 흐름도 이야기 상태를 보존했다. 실제 터치 스와이프는 카메라를 움직이고 진행 상태를 바꾸지 않았다. 이 동작은 리팩터링 시 회귀 기준으로 유지한다.

## 검증 범위와 순서

1. P0의 이동 가림·선택 시야·동사 구분을 한 시안으로 만든다. 실제 PC/휴대폰 크기 캡처로 조작 위계를 확인한다.
2. 조사 대상별 대표 터치점, 이동 버튼, 모달 복귀, 스와이프를 실제 브라우저에서 검사한다. 여관 열쇠·13호실 코트 사례를 필수 회귀로 둔다.
3. P1의 모드·지도·터치 표식을 같은 시안에 적용한다. 숨은 장소와 비활성 단서를 노출하지 않는지 확인한다.
4. 신규 이용자3명 이상에게 ‘새 장소 조사 / 특정 물건 조사 / 옆방 이동 / 다른 장소 왕복 / 원래 시점 복귀’를 설명 없이 맡긴다. 첫 시도 성공 여부, 엉뚱한 이동 발생, 어디를 눌러야 할지 멈춘 구간을 기록한다. 수치는 측정 후 판단하며 미리 성공률을 약속하지 않는다.

이번 요청은 조사와 기획이다. 게임 코드·대사·시간 규칙·증거 판정·배경 그림은 수정하거나 배포하지 않았다.
