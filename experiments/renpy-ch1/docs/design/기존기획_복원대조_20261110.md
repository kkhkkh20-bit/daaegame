# 1부의 기존 인과 연결을 보존하고 경제·후반 도움은 현행 정본에 맞춰 복원한다

2026-11-10. `CHAIN_DESIGN.md`, `PUZZLE_GRAMMAR.md`, `FUTURE_KNOWLEDGE_KEYS.md`, `PRICE_DESIGN.md`를 현재 게임과 대조했다. 최초 확인 기준은 커밋 `016f2aaa8`의 작업 트리다. 이 문서는 복원 작업 전의 대조표이며 제품 구현·SDK 실행·빌드·커밋을 포함하지 않는다.

**초기 설계 전체가 사라진 것은 아니다.** 피코 생존 뒤 그림 증언, 식당 실제 입실, 꼬미의 깡통 준비와 학교 인수, 등 복구의 온기 기억은 실행 코드에 연결돼 있다. 반면 톡·보리의 11일 수레 도움 등은 원안의 인물 연결이 없으며, 상점·일당의 옛 코드가 있다는 사실을 현행 V111에서 사용할 수 있다는 뜻으로 읽으면 안 된다.

## 도달 여부와 분류를 읽는 기준

- **1부**: 공개 설정 `R13_PART1_PUBLIC=True`에서 실행 가능한 1~7일 낮. `meeting:fire` 결과와 `D07_S02_handover_completed`, `D07_S02_message_completed`를 마친 뒤 `free_day7`에서 닫는다. 근거는 `game/room13_part1.rpy:3`, `r13_part1_ready`, `r13_part1_finish`다.
- **후속**: 7일 밤 이후 본편 코드에 연결돼 있으나 현재 1부 종료선 뒤에 있는 내용. 1부에서 준비값을 만들 수 있어도 그 결과까지 플레이했다고 세지 않는다.
- **미연결**: 제안한 사람·물건·비용이 현재 판정이나 실행 진입에 연결된 근거를 찾지 못한 상태. 비슷한 대사나 다른 캠페인의 함수가 있는 것만으로 구현 완료로 세지 않는다.
- 표의 **보존**은 현행 연결 유지, **복구**는 이미 있는 연결의 진입·표시·재방문 회수 보완, **재설계**는 현행 정본·조작과 맞추는 작업, **후속판**은 1부 종료선 뒤에서 다룰 작업을 뜻한다. 이 분류는 구현 완료 표시가 아니다.
- 도달 여부는 호출·대기·조건을 읽은 정적 판정이다. 해당 분기의 실제 클릭·화면·자연 완주는 이번 담당이 확인하지 않았다.

## 복원 작업의 순서와 완료 기준

1. **1부에 이미 연결된 행동을 먼저 보존한다.** P1/K1/K2/K6/K7/K8과 O1을 기준으로, 관찰·부탁·물건 사용·완료·후속 반응을 실제로 누를 수 있는지 확인한다. 메인 밖 148 생활 연쇄는 이 연결의 대체 증거가 아니라 추가 생활 정보다.
2. **기존 사람 도움을 생활·재방문에 회수한다.** 톡이 수리공이고 부리가 작업을 이어가는 사정, 나비·도토의 실제 차용·운반, 보리의 화재 뒤 돌봄을 먼저 사용한다. 소설·별편에 이미 있는 실제 행동을 기준으로 부탁을 설계한다.
3. **V111의 거래 기반을 독립적으로 복원한다.** 상점 진입, 수입 근거, 소유·빌림·소비, 도움과 대체 조달, 거절해도 진행 가능한 경로를 정의한 뒤 개별 거래를 붙인다. 옛 캠페인의 아이템·증거 ID와 명단 규칙을 복사하지 않는다.
4. **후속 사건의 인과 연결은 종료선 뒤에서 완성한다.** P3~P13의 미연결 도움과 O2·상점의 후반 사용처는 각 날의 실제 목격·생활 행동·동의·인수 절차를 갖춰 검토한다. 새 진상·생사·정답을 이 문서의 제안만으로 변경하지 않는다.
5. **진엔딩 강화는 마지막에 별도 대조한다.** 현재 `r13_nw_true_ending_ready`는 아침·상실 수·장부·회의·대승리를 직접 확인한다. `outcome13='all_rescued'`와 `current_transport_chain_stopped`는 실행 중 기록되지만, 이 둘을 직접 추가한 판정은 그 함수에 없다. 상류 경로의 사실상 제약과 명시 조건을 구분해 후속판에서 검증해야 한다.

완료 보고에는 ‘문서에 있음’, ‘코드에 라벨 있음’, ‘현재 1부에서 준비 가능’, ‘결과까지 실제 플레이함’을 나눠 적는다. 주민 반응 별편의 존재나 상태를 강제로 준비한 테스트를 1~7일 자연 완주로 보고하지 않는다.

## 검토 범위

이번 대조는 네 설계 문서, 현행 V111 실행 코드·신세계 대사·필드 바인딩·자료 효과·1부 종료선, 구 생활·상점 체계를 읽은 결과다. 기존 정본 소설과 주민 반응 별편의 날짜·인수·정보 경계를 함께 적용했다. SDK·빌드·실제 클릭·화면 촬영·전 경로 완주는 하지 않았다. 현재 소설을 잊은 독자의 재미 평가나 포가튼 시티와 같은 체감이 완성됐다는 판단도 포함하지 않는다.

한국어 문장은 `slop-rewrite`의 사용자 지시 우선·새 사실 금지·조건 보존 원칙을 따른다. 자동 문장 검사를 통과해도 도달성·캐논·재미가 보증되지 않으므로 표의 파일·값·실제 진입을 근거로 판단한다.

문서의 P1~P13·O1~O5·K1~K14 누락과 `r13_*` 참조명을 정적으로 확인했으며, 빠진 항목과 찾지 못한 참조명은 없었다. 상점 네 물건은 별도 표로 대조했다. `slop-rewrite --guide 없음 --bundle`의 본문 검사에서는 원칙 S1 0 / S2 0, 취향 규칙 0이었다. 사람 판단에서 보고서 제목은 복원 방향을 담은 것으로 보았고, 표를 찾기 위한 안내용 소제목은 유지했다. 검사 결과를 게임의 실행 검증으로 세지 않는다.

## 149 적용 범위 메모

이후 149 작업은 위 복원 전 대조표 전체를 구현하는 대신, **물건을 얻고 현장에서 시험한 방법을 다른 조사에 쓰는 연결**을 먼저 붙였다. 적용 소스는 `game/systems/room13_exploration149.rpy`, `room13_exploration149_model.rpy`, `game/v111/exploration149.json`과 V111 본편 대기 화면의 연결이다.

- 최종 범위에서 돈·가격·할인·노잣돈 지급을 제거했다. 은호가 남은 끈을 건네고, 표준추는 실제 빌려주며 직접 돌려받는다. 과거 개인 물품으로 가진 추를 새 대여품으로 소급하지 않도록 실제 대여 표시를 확인한다. 구 경제 전체를 되살린 것으로 세지 않는다.
- 2~7일의 안전한 방문창에서 시장을 열고, 실제 재실·생존·업무 조건을 충족한 은호·까로와만 진행한다. 필수 인물 대화·본편 물건 조사에서는 선택해 든 물품을 해제하고 기존 진행을 우선한다.
- 배달은 큰 상자를 두 손으로 들어 **집 문 앞까지 함께 옮길 목적**으로 정리했다. 두 짐표와 작은 상자 밑면을 살펴보고, 그냥 얹으면 미끄러지는지 시험한 뒤 묶는다. ‘같은 수레에 따로 싣는 것이 왜 틀렸는가’라는 억지 오답은 선택지에서 제거했다. 까로가 실제 여분 끈을 건네고, 묶은 짐을 함께 확인한 뒤 `knot_method`를 기록한다.
- 저울은 서로 다른 두 추의 높이 차이만으로 오차를 단정하지 않는다. 은호와 **빈 접시의 영점**을 실제 확인하고, 맞춘 뒤 같은 추를 양쪽에 번갈아 올려 본다. 추를 저울에서 챙기는 행동과 은호에게 돌려주는 행동은 구분한다. 범죄자·기존 E03/E04·옛 저울 범죄 플래그를 새로 확정하지 않는다.
- 2일 저녁에는 기존 걸쇠 관찰과 실제 소유 끈, 까로와 배운 방법을 함께 확인해 등 현장에서 사용한다. 새 코드는 물품을 소비하고 기존 끈 준비로 연결하며, 기존 본편의 반환값 3과 `lamp_bound2` 처리가 원래 결과를 결정한다. 피코 생사·회의 정답·결말을 별도 판정하지 않는다.

독립 검토에서 필수 클릭 가로채기, 재관찰을 실패로 취급하는 반응, 끈 교환의 시점, 저울 위에 올려 둔 상태와 관찰 이력의 혼용, 개인 추의 대여 소급, 비교 대상 무게를 모르는 저울 추론, 배달의 운반 목적을 지적했고 담당자의 수정 소스를 다시 읽었다. 본 담당의 확인은 코드·문안·배달 배경 원본 이미지의 정적 대조다. SDK·빌드·실제 클릭·모든 경로 완주는 별도 담당 기록을 따른다.

149는 CHAIN의 상점 네 물건·후반 P 항목·정보 가격표를 모두 복구한 판이 아니다. 위 표의 미연결·후속판 항목은 별도 완료 근거가 생길 때 갱신한다. 메인 대사 전체의 150 수정 제안도 이 메모의 검토 범위에 포함하지 않는다.
