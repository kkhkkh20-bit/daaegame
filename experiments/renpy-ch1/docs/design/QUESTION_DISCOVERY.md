# 질문은 알아낸 내용에서 생긴다 (0.19.51)

소유자 지시(2026-10-18): 질문지를 처음부터 채우지 않는다. 현재 목적에서 시작하고 대화·조사를 거치며 후속 질문이 늘어나야 한다. 할 말과 관련 자료가 없는 인물은 확대하기 전에 현장에서 안내한다.

## 질문 조건

정본은 `game/systems/room13_question_discovery.rpy`다. 기존 `r13_available`의 날짜·사건·상태·need 조건은 그대로 적용한다. 그 뒤 공통 `r13_question_discovered`가 질문의 근거를 확인한다. 날짜는 가능 시기이며 지식을 부여하지 않는다.

| 질문 | 필요한 계기 |
|---|---|
| 방 부탁 | 현재 숙박이 필요할 때. lodging을 얻은 뒤에는 다시 제안하지 않는다 |
| 아내 소식 | 현재의 아내 찾기 목적에서 시작하는 질문 |
| 손님 수 | 아내가 나간 날짜를 묻는 대화에서, 장부를 확인하자는 답과 함께 손님이 늘었다는 말을 실제로 들은 뒤 |
| 밤에 잠그는 문 | 실제로 표시된 대사·조사에서 빗장이나 안쪽 문 잠금 언급을 접한 뒤 |
| 첫날 밤 행적 | 칼바람에게 아내를 찾는 질문을 해 아이 목격담을 듣거나, 토실에게 그 밤의 숲 이야기를 들은 뒤 |
| 생활·이후 걱정 | 각 주민과 주제에 대해 지정한 실제 대사·관찰 구절을 접한 뒤. work/after/crisis를 날짜만으로 열지 않는다 |

칼바람의 아내 찾기 질문은 기존 첫날 밤 알리바이의 덫·숲·아이·보온병 목격담을 재사용한다. 원래 2일부터 접근할 수 있던 목격담을 늦은 토실 이벤트에만 종속시키지 않는다. 질문을 마치면 원래 알리바이 플래그를 남겨 교차 확인과 수첩 조건을 보존한다. 이미 들은 같은 내용을 ‘첫날 밤 어디에 있었는가’로 다시 묻도록 중복 생성하지 않는다.

## 제작 방법

- 새 질문에 `discover_any=["J02", "read:앞선질문ID", "heard:주제ID"]`를 지정할 수 있다. 이 중 하나가 계기다. 반드시 모두 필요한 조건은 기존 `need`에 둔다.
- `R13_QUESTION_LEADS`는 기존 질문의 계기를 연결하는 공통 표다. 생활 질문의 구절은 `R13_WORK_CUES`, `R13_LATER_CUES`에서 관리한다. 질문 제목을 분석해 임의로 지식을 추정하지 않는다.
- `r13_before_line`은 표시할 줄의 출처를 보관한다. `r13_remember_line`에서 모든 페이지를 마쳤을 때만 실제 화자의 줄을 학습한다. 대화 통째 건너뛰기, 아빠의 추측·질문, 수첩 재생, 메뉴 생성, 호버, 예측은 새로운 사실로 쓰지 않는다. 실제로 완료한 질문의 기존 read/flag 규칙은 유지한다.
- 구절을 수정하면 그 구절과 연결된 해금 테스트도 확인한다. 이 층은 증거를 지급하거나 시간을 진행시키지 않는다. 계기 출처는 현재 회차 `question_cues`에 남는다.

## 빈 대화 진입

`r13_contact_has_content`는 미확인 질문, 관련 자료 제시, 첫 인사에서 실제로 열릴 주제가 있는지 읽기만 한다. 전부 없으면 `r13_person_action`이 확대/화면 전환 대신 짧은 알림을 표시한다. 기록 재확인만 남았다는 이유로 새 대화를 강요하지 않는다.

이벤트·생활 그룹·아이의 기존 상호작용과 입구 전용 대화는 기존 디스패처를 유지한다. 상점과 물건 전달도 기존 수신자·소유·진행 조건을 확인한다. 판정하려고 `r13_present`를 실행하면 자료를 미리 보여준 셈이 되므로 호출하지 않는다. 선언된 `ROOM13.presentations`와 별도 반응의 `R13_CONTACT_RECORDS`를 읽는다. 별도 반응을 추가하면 해당 표와 필요한 미완료 조건도 함께 관리한다.

이미 보여준 자료도 나중에 새로운 용도가 생기면 진입을 허용한다. 예: 3일째 초롱에게 메모를 다시 보여주기, 기록실 위험을 알린 뒤 이전 자료로 설득하기, 가족/복도 증언 재확인. 판정 단계에서는 제시 이력·만남·증거·플래그·시간을 바꾸지 않는다.

## 기존 저장과 검증

이전에 실제로 읽은 질문·알리바이는 보존한다. 과거에 메뉴에 노출됐다는 `topic_order`만으로 질문을 배웠다고 간주하지 않는다. 남아 있는 현재 회차의 실제 `topic_transcripts`만 이관한다. 전역 읽음 이력과 지난 회차 자료는 해금 근거로 사용하지 않는다.

`dev/test_question_discovery.py`는 선행 정보, 부분 읽기/건너뛰기, 기존 저장, 새 용도가 생긴 자료, 진입 판정 무변경을 확인한다. `dev/qa_question_discovery.py`는 실제 웹 렌더에서 첫 질문 → 답을 들은 뒤 후속 질문, PC·터치의 확대 없는 현장 안내, 칼바람의 기존 목격담 연결을 확인한다. 전체 이야기를 다시 플레이한 검수는 아니다.

## 첫 사건의 추가 논증 질문

0.19.58의 Q1 새 규칙은 `room13_q1_arguments.rpy`에서 다음 계기를 사용한다. 일반 질문 목록에 날짜만으로 추가하지 않는다. 기존 회의 도중 저장은 구형 규칙으로 이어진다.

| 질문 또는 제시 | 조건과 얻는 내용 |
|---|---|
| 초롱에게 등 안 확인 | L06을 들었고 아직 사건이 끝나지 않았을 때. 첫 순찰의 직접 관찰 L15 |
| 초롱에게 다음 순찰 | L15를 실제로 얻은 뒤. 얼굴을 보지 못한 반출 관찰 L16 |
| 부리에게 밤 목격 | 톡 고발을 보았거나 L16을 들은 뒤. 얼굴·관찰 연속성과 손 안이 안 보인 범위를 함께 기록한 L17 |
| 실룩에게 빵값 출처 | 4일 아랫길의 실룩과 아이들 장면을 본 뒤. 본인이 내놓은 정산 쪽지 L19 |
| 백 부인에게 L09 제시 | 실제 소지한 이름표 조각을 직접 보여 준 뒤. 매입 원장 L18. 이전 제시 이력과 무관하게 원장을 아직 얻지 않았으면 대화 진입 가능 |

창고 조사에는 L19도 계기로 인정한다. 현장 끈을 못 얻은 거래 경로를 막지 않는다. 회의 중 정정된 실룩의 말 L20은 해당 질문을 실제로 마친 뒤에만 기록한다. 질문 목록 생성·화면 예측·되듣기만으로 자료를 지급하지 않는다.

## 슬링 편지 사건: 관찰과 지시자 확인을 분리하는 새 난이도 개정

이 절은 기존 설정을 설명하는 것이 아니라, 조기 실명 폭로를 늦추는 새 집필·해금 설계다.

- 첫 만남의 소개 → 김에 들리는 봉투 접착면 → 허락 없는 개봉 확인은 유지한다. 누구 부탁인지 물을 수 있지만, 슬링은 일자리를 잃을까 두려워 이름을 말하지 않는다. 이때 얻는 것은 sling_job_pressure_heard뿐이며 H9나 know_granny_reads가 아니다.
- 무료 중단·초상 보호·경비 신고·선택적 하루 몫 3냥 지원은 남는다. 돈은 명시적 선택에서 한 번만 줄어들고 편지 보호를 얻지만, 지시자에 대한 신뢰나 H9를 사지는 못한다. 무료 보호는 비유료 신뢰를 남긴다. 유료 경로도 별도의 ‘들은 사정을 퍼뜨리지 않겠다고 한다’ 약속으로 비유료 신뢰를 쌓을 수 있다.
- 새 지시자 대면(sling:letter_requester)은 실제 슬링에게 제시한 J06, 또는 실제 제시한 E18과 J08 두 자료가 필요하다. 소지·열람·제시 가능한 자료 목록·NPC가 한 과거 증언만으로 ‘보여 줬다’고 추정하지 않는다. 이 제시 근거와 비유료 보호/화해가 모두 있어야 한다.
- 실제 제시 반응은 기록을 보았음을 확인할 뿐 실명이나 H9를 주지 않는다. 열린 대면에서 ‘편지 일을 끝까지 듣는다’를 선택하고 대사를 마친 뒤에만 H9, know_granny_reads, sling_confession_heard를 남긴다. 시작 전 취소·조건 실패·호출이 정상 반환하기 전 실제 중단은 이 결과를 주지 않는다. 기존 게임의 명시적 대화 건너뛰기나 빠른 출력은 완료 계약을 그대로 따른다. 고백은 편지 필사의 지시와 일자리 위협까지만 말하며 최종 목적이나 다른 범행을 확정하지 않는다.
- 신고 뒤 사정 질문은 이름을 거절하는 답으로 끝난다. 사과와 경비에게 재검토를 부탁하는 화해는 H9 없이 가능하고, 지시자를 짐작해서 대신 주장하지 않는다. 비유료 화해가 신뢰로 인정되므로 H9와 순환 조건이 생기지 않는다.
- 기존 저장의 H9·know_granny_reads·sling_confession_heard는 지우지 않고, 이미 들은 이름을 다시 모르는 척하지 않는다. 실제 실명 지식만 있고 H9가 빠진 저장은 기존 지식을 확인하는 추가 대면을 완료해 기록을 회복할 수 있다. 열람·미리보기·자료 제시만으로 H9를 자동 복구하지 않는다.
- 실명을 실제로 안 뒤의 가짜 약속 쪽지는 사건 전 다시 부탁할 수 있다. 기존 할머니 눈치챔 실패, 사건 당일 저녁 유인, 따라가기/아이와 남기, 예방·목격·E17 보상과 이미 심은 쪽지를 보존한다. 후반 독립 직접증거와 할머니를 직접 추궁하는 기존 경로에는 슬링 제시·신뢰 조건을 추가하지 않는다.

정본은 systems/room13_sling_confidence.rpy의 최종 provider와 순수 gate다. R13_CONTACT_RECORDS에 E18/J08/J06을 등록한다. dev/test_sling_choice_flow.py와 dev/test_sling_earned_disclosure.py는 실제 source helper·분기·후반 provider를 검사하며, Ren'Py 화면·브라우저 검수를 대신하지 않는다.
