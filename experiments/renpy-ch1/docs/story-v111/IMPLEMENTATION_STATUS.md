# V1.1.1 연결 현황 — 0.19.85

기존 main 0.19.84의 시스템·자산·최근 마차/대화 UI 작업을 보존하고 3일 종료 지점에서 14일까지 이어지는 native Ren'Py 장면을 연결했다. 새 게임·새 런타임 해석기를 만들지 않았다. 원본 82씬·3162레코드·113개 개별 requires는 그대로 보존한다.

## 연결 방식

- 현장 물건 클릭, 인물 질문, 지도 이동, 수첩/증거 제시는 기존 Room13 화면과 입력 경로다.
- 씬/블록의 분기는 보통 `label/if/jump/call`, 개별 발화 조건은 명시적 콜백이다. 자연어 조건을 runtime eval하지 않는다.
- 생존·구금·실제 위치·맡은 역할과 수령/사용·명부/실제 탑승·정지/실제 인수는 구분한다. 기존 Room13 신병·사망 상태에도 결과를 반영한다.
- 대사/자료 재열람은 증거·물자·시간 효과를 반복 지급하지 않는다. 기존 인물 위치는 유지하고 실제 사망·신병·이동 결과만 우선한다.
- 1~3일 파일은 재생성하지 않았다. 첫 3일 뒤 종료 안내를 제거하고 4일로 잇는다. 초기 마차·현재 승인 UI/글꼴·표정 자산은 보존한다.

## 검증 및 제한

실제 진행과 스크린샷은 [4~14일 검수 보고](verification414/PLAY_REPORT.md), 최소 연결 보완의 근거는 [연결 설명](verification414/INTEGRATION_NOTES.md)에 구분했다. 감사 21건은 `AUDIT_21_STATUS.csv`에 코드 대조·변경 지점·실제 확인 범위를 기록한다. 단위 검사 통과를 모든 조합의 실제 플레이 완료로 계산하지 않는다.

첫 3일의 이전 실제 검수는 `verification/`에 보존한다. 과거 보고의 “3일까지만 공개”는 이전 버전의 범위다. 0.19.85에서는 그 경계가 14일로 이어진다.

저장/로드/스킵 기본 동작의 별도 중복 행렬은 만들지 않았다. 실제 클릭으로 만든 저장에서 재개해 변경한 분기·인수·증거·대사 정합성을 검사했다. 이야기 상태를 주입해 완료 화면만 호출하지 않았다.

새 이미지·음원 생성은 0건이다. 기존 승인 자산을 우선 사용했다. 장면별 확대 그림/동작·공간 일치가 남은 항목은 `RESOURCE_REQUESTS.md`에 분리했고 토리와 중복 제작하지 않는다.
