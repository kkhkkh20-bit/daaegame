# 상점과 주민 도움 연결 계약

상점 구현은 최신 main의 별도 작업을 보존한다. 현재 엄마 찾기 PoC는 완료한 주민 도움 기록을 읽어 후속 질문을 연다. 구매 자체로 증언을 지급하지 않는다.

## 플레이 흐름

주민의 필요를 대화에서 파악 → 물건 구매 또는 다른 방법으로 마련 → 해당 주민에게 보여주기 → 대화 안에서 건넬지 선택 → 도움 수락 → 관련 질문 개방 → 답변을 읽은 뒤 증언 기록.

상품 설명에는 물건의 용도를 적되, 정답 증언이나 범인을 미리 알려 주지 않는다. 주민이 직접 본 일과 추측은 구분한다. 물건 도움은 일하기 외의 대안이며, 초기 엄마 찾기에 필수 구매를 추가하지 않는다.

## 상태 인터페이스

상점 측은 전달을 수락한 시점에 현재 회차 상태의 `resident_help` 목록에 다음 형태를 기록한다.

```python
room13.setdefault("resident_help", []).append({
    "person": "nabi",  # 실제 NPC 식별자. 까로는 karo
    "kind": "gift",   # 물건 전달 gift / 심부름 errand
    "item": "requested_item",  # 상점 측 실제 아이템 식별자
    "day": room13["day"],
    "completed": True,
})
```

구매만 했거나, 잘못된 물건을 줬거나, 주민이 거절했거나, 심부름이 미완료라면 완료 기록을 남기지 않는다. 상점 측이 결제·재고·소지품·수락 여부를 처리하고, 중복 전달로 반복 보상되지 않도록 관리한다. 새 게임은 현재 회차 기록을 초기화한다. 기존 저장에 이 목록이 없어도 질문 시스템은 정상 작동한다.

`r13_poc_helped(person)`은 실제 일거리 완료 또는 이 기록의 완료된 도움을 읽는다. 물건 전달을 일한 것으로 위조하여 `livelihood.jobs`에 넣거나 작업 전용 플래그를 만들지 않는다.

## 현재 연결 대상

- 나비: 엄마 메모를 제시하고 도움을 완료하면 봉투에 관한 질문이 열린다.
- 까로: 엄마 메모를 제시하고 도움을 완료하면 초롱의 보관함에 관한 질문이 열린다.

두 경우 모두 질문 답변을 읽어야 증언을 획득한다. 상점의 기존 상품·구매·소모·반납·보증금 처리는 유지한다. 0.18.54부터 별도 전달 질문 대신 통합 자료창의 보여주기를 사용하고, 실제로 건네겠다는 선택 뒤에 기존 완료 함수를 호출한다. 보여주기만 하거나 거절하면 물건·보상·도움 기록은 변하지 않는다. 나비·까로용 새 상품은 추가하지 않는다. 다른 주민은 그 인물의 필요와 증언에 맞춰 별도 질문 조건을 추가한다.

## 확인

단위 검사: 구매만 한 상태, 미완료 도움, 수락한 도움, 관련 메모 제시 전후, 기록 조회의 상태 불변성을 검사한다. 실제 상품 전달 경로는 상점 구현 후 통합 플레이 검증이 필요하다.
