# 분기별 대사 작업

명령 실행 위치: 저장소의 `experiments/renpy-ch1/` 폴더.

이 폴더는 게임 원본에서 생성하는 편집 모듈이다. 실제 게임의 정답·생사·분기 조건을 편집하는 도구가 아니다.

1. 프로젝트 폴더에서 `python3 dev/dialogue_modules.py build`로 최신 모듈을 생성한다.
2. `python3 -m http.server 8788` 후 `http://localhost:8788/docs/story-workbench/`를 연다. 대사 페이지 자체는 외부 서비스 없이 작동한다.
3. 날짜·장면·조건을 골라 앞뒤 대사와 함께 읽는다. 조건이 다른 줄은 서로 이어지는 대사로 읽지 않는다. 원문 위치와 정확한 조건은 각 행에서 펼쳐 본다.
4. 문장을 수정하고 검수 상태를 미검수/수정 필요/검수 완료로 표시한다. 브라우저 임시 저장은 해당 기기에만 남으므로 편집 JSON을 내려받아 보관한다.
5. 다른 채팅이나 작업자에게 **편집 JSON**을 보낸다. CSV와 검토 문서는 비교·읽기용이고 자동 반영 형식은 JSON이다.
6. 받은 파일은 먼저 `python3 dev/dialogue_modules.py check 수정본.json`으로 검사한다. 원본이 바뀌었거나 서로 다른 수정이 충돌하면 적용하지 않는다.
7. 검사 후 `python3 dev/dialogue_modules.py apply 수정본.json --write`로 명시적으로 반영한다. `--write` 없이 원본을 수정하지 않는다. 실제 적용 후에는 관련 대사 검사와 필요한 화면 확인을 거쳐 커밋한다.
8. 최신 모듈을 다시 생성해 반영된 문장과 검수 상태를 확인한다. 검수 상태는 `review-status.json`에 저장되어 다음 생성에서도 유지된다.

분기별 편집 JSON은 `branches.json`의 file 경로로도 받을 수 있다. 전체 목록은 `inventory.json`, 안전한 편집 지원 범위와 읽기 전용 수는 coverage 항목을 확인한다.

## 수정할 수 있는 것

- `text`: 해당 문장의 내용.
- `review_status`: `draft`, `reviewed`, `needs_work`.

ID·출처 경로·조건·화자·원문 기준 해시 등 나머지 메타데이터는 유지한다. 읽기 전용 행의 문장 교체는 지원하지 않으며 상태만 기록한다. 읽기 전용 출처가 있다면 생성 결과의 coverage에 명시된다.

## 검수 기준

아빠가 모르는 것은 먼저 보고 묻고 상대의 답을 듣는다. 다람은 유쾌한 아이로, 아빠도 생활감 있는 익살로 받아친다. 주민의 개성은 각자의 고집과 행동에서 나온다. 죽음·상실 장면에 억지 농담을 넣지 않는다. 자료 이름·정답을 힌트에서 노출하거나 실제로 없는 물건·인물을 대사로 만들지 않는다.

분기별 묶음은 대사의 정확한 조건과 호출 위치를 보존하는 편집 단위다. 가능한 모든 게임 상태의 조합을 자연 플레이한 결과를 뜻하지 않는다.

대사 안의 Ren’Py 보간식과 제어 태그는 문장 편집에서 추가·변경하지 않는다. `[변수]`와 태그를 바꾸면 실행 화면이 깨질 수 있어 검사에서 거부한다. 원본이 바뀐 임시 수정은 자동 반영하지 않고 복구 파일로 받을 수 있다.

## 순서대로 읽기

날짜를 고른 뒤 「날짜별 대본 읽기」를 누르면 기존 합본 대본을 한글 웹 문서로 연다. 대사 ID를 누르면 해당 날짜·문장 검색이 적용된 편집기로 돌아온다. 원문 TXT도 내려받을 수 있다. 서로 다른 조건의 줄은 나란히 표시되므로 하나의 연속 장면으로 읽지 않는다. 「분기 링크 복사」는 선택한 날짜·분기·검색을 공유한다.
