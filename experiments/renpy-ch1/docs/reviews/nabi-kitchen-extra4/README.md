# 나비 추가 주방 동작 4종 — 연결 후보 조사 (미적용)

이 네 동작은 기존 27컷/KI-1 당근 썰기와 별도다. 원본 전달 전이며 원본 제작 완료·게임 적용 완료로 세지 않는다. 기존 흰 고양이/남색 교복 알바 소녀 디자인을 유지하고 조사 파생본만 도트, 대화용 원본은 smooth로 분리한다. 내부 ID `nabi`와 세이브 키를 바꾸지 않는다.

## 실제 코드 조건

- `game/room13_rules.rpy:r13_where`: 첫 주 나비는 `dining`.
- `game/room13_week2_rules.rpy:r13_w2_where`: 둘째 주 아침 할머니 구금이면 `inn`, 대피소 준비 시 `school`, 그 외 `dining`. 주방 조사 주민 일정은 없다.
- **현재 사용 가능한 설거지 대사 후보**: `game/systems/room13_no_livelihood.rpy`의 `help:nabi`. 2~3일, `nabi_helped`가 없을 때, “그릇이라도 같이 닦을까?” 뒤에 둘이 그릇을 닦고 장작을 부엌 안으로 나르는 서술이 있다. 해당 기존 대화 줄에 smooth 설거지 그림을 연결하는 것이 가장 직접적인 후보다. 대화가 주방으로 장소를 바꾸지는 않으므로 주방 맵 상주·출현으로 취급하면 안 된다.
- `R13_JOBS['kitchen']`는 이름만 kitchen이고 장소는 `dining`이다. 더구나 `r13_job_allowed`는 False이고 init168에서 `job:` 주제가 제거된다. 과거 `life:kitchen:start`, `r13_life_meal`, 수프/쟁반 클로즈업은 **현재 접근 가능한 이벤트가 아니다**. 이를 재활성화하거나 새 사건을 만들지 않는다.
- `nabi_food`도 옛 수프 제공 대사만 읽으면 안 된다. init103 `room13_episodes.rpy`에서 3~6일/`nabi_secret`/`not kids_fed` 아이들 식량 대화와 `r13_ep2_food`로 바뀐다. 옛 정적 JSON을 근거로 자동 연결하지 않는다.

## 배경 접점 후보 — 아직 새 원본과 맞춘 최종 좌표 아님

`background-contact-grid.jpg`는 현재 오전 주방을 실제 world 크기 2160×720으로 읽은 참고 그림이다. 아래는 월드 좌표이며 뷰포트 좌표가 아니다. 시간대별 배경과 원본 손/소품 접점을 받은 뒤 단일 배율로 다시 검증한다.

주방 조사에는 여전히 나비가 없으므로, 추가 4종도 원본을 받은 뒤 등록·미리보기까지 진행할 수 있다. 실제 주방 출현은 별도 일정/장면 결정이 필요하다. 0.19.33에는 새 일정·사건·추가 4종 원본을 포함하지 않았다. 이후 사용자가 일상 주방 슬롯까지 적용하도록 승인했으므로, 후속 작업에서 기존 서빙·중요 대화·피난 우선순위를 보존하며 일정을 연결한다. 기존 제한은 승인 이전 조사 기록이며 현재의 승인 대기를 뜻하지 않는다.
