# 0.19.51 실제 질문 해금·현장 진입 검증

소유자 지시: 질문은 현재 목적에서 출발하고, 대화·조사에서 단서를 접한 뒤 늘어나야 한다. 대화/제시할 내용이 없는 인물은 확대하기 전에 현장에서 짧게 알려야 한다.

## 바뀐 동작

할머니에게 방을 이미 받은 상태에서는 아내를 찾는 질문으로 시작한다. 손님 수, 잠그는 문, 첫날 밤 행적은 미리 나열하지 않는다. 아내가 나간 날짜를 묻는 답에서 장부와 늘어난 손님 이야기를 듣고 나면 손님 수 질문이 추가된다. 이 부연은 기존 여관 생활 대사의 사실을 옮긴 것으로, 사건의 결론이나 범인을 새로 알려주지 않는다.

숲의 칼바람에게 아내를 보았는지 물으면, 기존에 작성된 첫날 밤 목격담으로 이어진다. 그 말을 들은 뒤 그날 밤을 다른 사람에게 확인할 수 있다. 원래 알리바이 플래그와 교차 확인은 그대로이며, 칼바람에게 동일 목격담을 별도 행적 질문으로 다시 묻도록 하지 않는다. 따라서 단순히 질문을 숨겨 단서 발견 경로를 지우지 않는다.

생활 질문의 work/after/crisis에도 공통 계기를 연결했다. 현재 회차에서 실제로 완료한 대사·관찰을 읽을 뿐, 날짜나 다른 회차의 읽음 기록으로 지식을 부여하지 않는다. 기존 실제 대화 기록과 이미 읽은 질문은 이관하고 메뉴 노출 이력만으로는 해금하지 않는다.

미확인 질문과 관련 자료 제시가 없으면 인물을 눌러도 현장에 머물고 짧은 알림만 나온다. 새 질문·이벤트·생활 그룹·아이 대화는 유지한다. 자료를 미리 제시해 보면서 판정하지 않는다. 이미 제시했던 자료의 새 용도(초롱의 메모, 기록실 설득 등)도 별도로 보존한다.

## 검증 범위

- `dev/check.sh`: 단위 테스트423개와 Ren’Py lint. 신규13개는 인과 조건, 부분/건너뛴 대사, 기존 저장, 읽기만 하는 진입 판정, 새 용도의 자료를 확인한다.
- 동적 대사 인벤토리에 새 부연과 연결 대사의 문맥 검토를 추가했다. 기존 검토 내용은 보존하고 새 소스 위치에 맞췄다.
- 공식 웹 빌드를 Chromium에서 실행했다. PC1280×720, 터치844×390/큰 글씨를 사용한 제한된 UI fixture 검증이다. 전체 이야기 플레이나 실제 휴대폰 하드웨어 검증은 아니다.
- 실제 질문 선택과 대사 진행으로 후속 질문이 추가되는지, 실제 인물 클릭이 확대/대사 없이 현장에 머무는지, 그 과정에서 이야기 상태가 바뀌지 않는지 확인한다.
- 미확인 관련 자료가 있으면 진입을 허용하고, 판정만으로 제시 이력·증거·시간·플래그를 쓰지 않는지 확인한다.
