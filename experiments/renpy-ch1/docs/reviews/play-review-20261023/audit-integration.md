# 독립 통합 코드 검수

2026-10-23. 구현 담당과 분리한 에이전트가 진행 중 diff와 실제 플레이 보고서 U01~U13을 대조했다. 이 문서는 정적 코드 검수이며 네이티브·브라우저 시험의 통과 보고서가 아니다. 실행 결과는 최종 통합 검증 기록을 따른다.

## 발견과 처리

- 설정 탭 `textbutton name` 안에 `ysize` 속성이 두 번 들어간 것을 발견해 현장 담당에게 전달했다. 중복 속성을 제거한 것을 다시 확인했다.
- 초기 검수에서 지도 하단 높이 80이 844×390 기준 44 CSS px 목표에 못 미치는 것을 전달했다. 최종 소스는 지도·공통 하단·질문·자료·설정 주요 터치 영역을 88로 맞췄다. 이는 844×390에서 약 47.7 CSS px, 740×360에서 44 CSS px다. 지도에서는 실제 버튼과 바깥 배치 영역 모두 같은 높이를 쓴다.
- 현재 변경에서 새로운 진행 불가, 판정 조합 변경, 자료 획득 조건 변경은 정적으로 발견하지 못했다. 실제 조작으로 확인하지 않은 경로까지 정상이라고 단정하지 않는다.

## 자료 그림과 이름 확인

- 현재 catalog는 원본 `records.json`에 일별 `evidence` 덮어쓰기와 `new_evidence`를 합친 80종을 기준으로 확인했다.
- 단독 Python 확인에서 모든 현재 이름을 174px 폭·24px 크기·최대 3줄 헬퍼에 넣었다. 공백/줄바꿈을 제외한 문자열이 원래 이름과 같았으며 글자 손실 사례는 없었다. 실제 폰트 렌더링은 별도 화면 검증 대상이다.
- 목록은 큰 그림과 같은 `r13_evidence_picture`를 쓰므로 기존 전용 원화, 상태별 초상·보따리·담요, 명시된 증언 화자의 얼굴을 재사용한다. 임의 새 그림으로 단서 상태를 바꾸지 않았다.
- 정렬을 바꾸더라도 선택 키와 제출 argument 키는 그대로다. 최종 `r13_record_restore_page`는 기억된 선택 키가 있으면 새 페이지 크기에서 그 키의 페이지를 계산하고, 키가 없으면 숫자 페이지를 유효 범위로 제한한다. 기록/제시 양쪽에서 최초 한 번만 복원하므로 이후 페이지 이동을 되돌리지 않는다. 필터 변경 때는 기존 초기화 동작을 유지한다.
- 한 페이지의 자료 수를 12/8에서 5로 줄인 것은 전체 이름과 터치 영역 확보의 대가다. 보고서의 탐색 피로가 완전히 해결됐다고 주장하지 않고, 실제 후반 이용에서 페이지 이동 부담을 계속 확인한다.

## 판정·상태 보존 대조

- 자료 선택은 기존 argument 추가/제거 동작을 쓴다. 제출 판정 호출·성공/실패 분기·정답 자료 조합은 변경되지 않았다.
- 지도 잠김 클릭은 선택 목적지·이동·시간을 바꾸지 않는다. 숨은 장소의 발견 조건과 이동 허용 목록도 그대로다.
- 새 상태값은 질문 읽음과 최초 입실 안내의 UI 상태다. 기존 증거 보유·생사·결말 플래그를 대체하거나 해금하지 않는다.
- 증언 화자 등록의 사용처를 검색했다. 아이콘/출처/관계 자료 목록/읽기 안내에 쓰이며 이번 변경으로 정답 판정 조건을 추가한 부분은 발견하지 못했다.

## 0.20.14 최종 소스 재검수

- 최종 추가 변경을 읽기 전용으로 다시 대조했고 새 중요 결함을 발견하지 못했다. 단위 시험·네이티브·웹 빌드는 이 에이전트가 중복 실행하지 않았다.
- 대사 터치 조작은 중심 y660, 높이88로 y616~704에 놓인다. 일반 모바일 대사의 기준 하단은608로 바뀌어 조작 영역 앞에8px 간격을 남긴다. 현장 읽기는 조작을 숨기는 기존 경로를 유지한다.
- 자료 목록 다섯 행은 y140~580, 모바일 페이지 조작은 y582~670이므로 두 영역은 겹치지 않는다. 글씨 크기·폭·최대 줄수는 앞서 전체80종을 검사한 조건과 같다.
- 지도 하단 조작은 y613~701로 판 y602~712 안에 들어간다. 작은 제목·안내 판은 12px 모서리의 `panel_small.png`를 써 소형 영역에서 큰 패널 모서리가 잘리는 문제를 피한다.
- 최종 메모 터치 영역은 월드 배율을 반영해 최소88이 되도록 올림 처리한다. 첫 입실 맥락은 한 번만 나오고 기존 감정 장면이나 자료 선행 조건을 건너뛰지 않는다.
- 최종 코드 검수 결과는 정적 범위의 통과이며, 진행 중인 전체72개 화면 시험과 실제 브라우저 검증의 결과를 대신하지 않는다.

## 최종 보완 세 항목의 독립 재검수

- `r13_record_icon` 우선순위를 다시 확인했다. 물건/도구는 기존 전용 경로로 먼저 반환하고, 증언은 명시된 발언자 초상을 유지한다. 그 다음 현재 V111 전용 원화를 찾아 사용하며, 없으면 기존 상태별/기존 번호 매핑으로 돌아간다. E09·E30·E13_MENDING은 정적 evidence 파일이 없음을 파일시스템에서 확인했으므로 초상 진행 상태·보따리·수선 담요 동적 경로가 새 우선순위로 가려지지 않는다. 일반 목록 외의 공통 자료 아이콘도 같은 원화를 사용하게 된다.
+- 마차 선택 화면은 master 레이어에 `r13_visitor`가 없을 때만 다람을 화면에 다시 그린다. 기존 마차 함수와 같은 그림 함수·배율, x850 중심·y96을 사용하며 이미 있는 인물과 겹쳐 두 번 그리지 않는다. `r13_carriage_seat_shown`은 기존 착석 표정 키를 쓰고 값이 없으면 현재 표정으로 안전하게 계산한다. 표시 추가는 이야기 상태나 선택 결과를 수정하지 않는다.
+- 이름표 하단 제한은 고정 월드 y676 대신 `720 / zoom - tag_height - 8`을 쓴다. 따라서 0.75배 입구에서도 화면 아래로 빠지지 않으면서, 낮은 머리 위치의 까로 이름표가 불필요하게 두 줄 위로 밀리는 원인을 제거한다. 일반 1.0배 장면도 전체 이름표 높이가 화면 안에 들어간다. 카메라 x오프셋·HUD 좌표 변환·겹침 점수 계산은 함께 유지된다.
+- 위 세 항목의 최신 diff에서 새 중요 결함을 발견하지 못했다. 이 검수에서는 게임 소스를 수정하거나 실행 시험을 중복 수행하지 않았으며, 최종 릴리스의 네이티브72개·웹 재검증 결과는 별도 기록을 따른다.

## 지도 드래그 뒤 첫 터치 보완 검수

- 마지막 변경은 `room13_worldmap_v5.rpy`의 열린 건물 버튼과 이름 버튼 두 곳에서, 터치 모드일 때 `hovered`/`unhovered` 콜백만 `None`으로 만드는 것이다. 선택 action, 잠김 안내, 이동 허용 조건, 좌표·focus mask는 변경하지 않았다.
- PC에서는 기존 `SetScreenVariable("map_hover", ...)`가 그대로 실행된다. 건물 강조 조건도 `key==selected or key==map_hover`를 유지하므로 PC hover와 터치 선택 후 강조가 모두 남는다.
- `map-audit.md`는 0ms/120ms 접촉 비교, 실제 CDP 손가락 드래그 뒤 첫 탭 실패, 런타임 hover 콜백을 끈 대조 성공을 구분해서 기록했다. 도구 계측 오류와 게임의 첫 터치 누락을 별개로 분류하고, 최종 수정 빌드에서 다시 검사한다고 명시한 설명은 코드 변경과 맞는다. 이 독립 검수자가 런타임 대조를 직접 재실행한 것은 아니다.
- `qa_map_review.py`는 터치 모드의 지도 스크롤을 CDP 드래그로 수행한다. 이름/실내 장소 클릭은 첫 입력 한 번 직후 선택값을 assert하며, 재탭이나 마우스 fallback은 없다. 최하단 빨래터→솜이네는 서로 다른 선택을 연속 검증하므로 직전 선택이 남는 실패를 놓치지 않는다.
- 이 변경에서 중요 부작용을 발견하지 못했다. 최종 새 빌드의 첫 터치 재현 시험과 PC hover 검증 결과는 릴리스 검증 기록을 따른다.
