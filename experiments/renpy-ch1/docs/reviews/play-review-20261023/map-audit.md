# 지도 UI 및 U09 반영 기록

## 변경

- 마을·산길 제목과 하단 판, 지역 탭, 여관 안내 목록·선택 카드에 자료/설정의 기존 `ui-night` 갈색·금색·버건디 부품을 적용했다. 지도 원화, 건물 윤곽, 마우스 강조 연출은 유지했다.
- 기존 이동 가능 윤곽의 뜻을 한 줄로 설명하고, 그림 속 일반 장소를 눌렀지만 현재 갈 수 없을 때 `수리점 · 지금은 이곳으로 갈 수 없습니다.`처럼 안내한다.
- 잠긴 장소 클릭은 화면 안내만 바꾼다. 이동 목적지 선택, 시간, 현재 위치, 사건 조건은 바꾸지 않는다. 이동 가능한 장소 선택 및 지역 전환 때 안내를 비운다.
- 별칭 사건 장소와 숨은 장소는 잠김 안내 대상에 추가하지 않는다. 같은 건물에 사건 별칭 목적지가 열린 경우 기본 장소의 잠김 입력을 겹쳐 넣지 않는다.
- 지도 탭·이동·복귀·여관 목록 터치 높이를 88로 맞췄다(740×360에서 44 CSS px). 마을 지도 맨 아래 장소를 안내 띠 위로 끌어올릴 수 있도록 스크롤 끝 여유를 60만큼 늘렸다.

## 구현 파일

- `game/room13_navigation.rpy`: 공통 밤 UI, 잠김 대상 계산, 상태 안내.
- `game/room13_worldmap_v5.rpy`: 기존 그림·이름 영역을 사용하는 잠김 클릭, 허용 장소 선택 시 안내 해제.
- `dev/test_map_affordance.py`, `dev/test_worldmap_v5.py`: 비밀 장소·별칭·현재 상태 보존 회귀 검증.
- `game/qa_tests/map_review.rpy`: 신규 첫 입구에서 실제 수리점 이름 클릭과 상태 보존을 확인하는 `map_review_locked` 화면 시험.

## 검증

- 지도 조작성 단위 시험 11개 통과.
- 지도 원화·발견 규칙 시험 5개 통과.
- 여관 이동 데이터 시험 3개 통과.
- 최종 웹 빌드의 브라우저 검증과 캡처 시각 검수까지 완료했다. 네이티브 전체 회귀 결과는 메인 개발자의 통합 검증 기록을 따른다.

## 통합 검수 요청

- `map_review_locked`와 기존 `cartography` 네이티브 시험.
- PC 1280×720, 가로 터치 844×390에서 마을·산길·여관 화면 캡처. 잠긴 수리점 안내 후 허용 장소를 누르면 안내가 초기화되는지, 이동 확정 전 상태가 보존되는지 확인.
- 큰 지도 맨 아래 솜이네·빨래터를 안내 띠 위로 끌어올려 클릭할 수 있는지 확인.

지도 원화가 원래 가진 밝은 종이색은 여행 지도의 재질로 유지했다. 사용자가 요청한 다른 화면과의 톤 일치는 주변 UI 부품에 적용했다.

## 브라우저 검수에서 추가로 발견한 첫 터치 누락

- 프로그램으로 지도 스크롤을 이동한 뒤 첫 터치가 누락돼 처음에는 검수 도구 경합을 의심했다.
- 접촉 0ms를 120ms로 바꿔도 재현했고, 실제 CDP 손가락 드래그 뒤 솜이네 첫 탭에서도 이전 빨래터 선택이 남았다. 두 번째 탭은 정상이라 게임의 첫 터치 문제로 분류했다.
- 지도 버튼의 `hovered`/`unhovered` 화면 변수 변경을 처음부터 런타임에서 비활성화한 대조에서, 실제 드래그 후 빨래터·솜이네의 첫 탭이 연속 성공했다.
- 따라서 터치 모드에서만 해당 hover 콜백을 끄는 최소 수정을 적용했다. PC 마우스 강조와 터치 선택 후 건물 강조는 유지한다.
- `dev/qa_map_review.py`에 모든 장소 선택 직후 선택값을 검사하도록 보강했다. 터치의 지도 이동은 실제 손가락 드래그로 바꾸었으며, 재시도·마우스 대체 없이 첫 탭 하나의 결과를 검사한다.
- 기존 브라우저 스크립트의 화면 직접 열기, 계측 API 및 textbutton focus 계측 오류는 게임 결함으로 세지 않는다. 최종 결과는 수정 뒤 새 빌드에서 다시 검사한다.

### 입력 조건과 검증 범위

새 게임의 첫 입구 진입 후 검수 fixture로 지도 화면을 직접 열었다. 전체 지역 외형 검수에 공개 장소 목록 fixture를 사용하고 검사 후 복원했다. 실제 여행 실행이나 사건 전체 플레이를 검증하는 시험은 아니다. 장소 선택과 지도 드래그는 실제 브라우저 입력으로 수행했으며 전후 진행 상태가 같음을 검사했다.

PC 검증은 포인터 접근 후 180ms hover가 표시된 상태에서 첫 클릭 한 번으로 선택했다. 별도 진단에서는 프로그램으로 지도를 스크롤한 직후 포인터 순간 이동과 클릭을 대기 없이 합성하면 첫 선택이 누락될 수 있었다. 이 0ms 합성 입력 조건의 누락까지 해결됐다고 주장하지 않는다. 정상 포인터 접근 조건은 통과했으며, 실제 손가락 드래그 후 첫 탭이 누락되던 터치 결함은 소스 수정 뒤 같은 조건으로 해결을 확인했다.
