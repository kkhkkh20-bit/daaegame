### 유지할 장점

1. **동기의 일관성.** 과자·잠자리·엄마를 찾는 말이 같은 감정으로 연결된다. 아이를 단서 설명 기계로만 쓰지 않는다.

2. **입구 사건의 보상.** 문서와 규칙을 맞춰서 아이의 이름을 등록하는 결과가 가족 이야기와 연결된다. 작은 행정적 승리도 감정적으로 의미가 있다.

3. **일반 질문의 읽음 표시.** ‘왜 제 신청이 일꾼으로 됐습니까?’는 읽은 뒤 체크·취소선으로 바뀐다. 이 방식은 반복 탐색을 줄여 준다.

4. **자료의 큰 그림과 짧은 관찰 요약.** 방의 메모에는 작은 그림 단서가 실제로 보인다. 요약에서 답을 먼저 말하지 않고 그림을 보게 하는 방향을 유지할 만하다.

5. **실내 이동 목록과 저장 정보.** 층, 현재 위치, 장소 미리보기, 저장한 날짜·장소·최근 문장·버전 호환 표시가 실용적이다.

## 5. 문제별 재현·영향·개선·확인 기준

### U01 · ‘그만두기’가 선택을 유지하는 복귀 버튼이다 — P1

**재현:** 입구에서 돌목 → 자료를 함께 제시한다 → 근거를 내놓는다 → 초대 편지 선택 → 근거에 추가 → 그만두기. 결과는 자료 선택 화면을 닫고, 방금 추가한 자료가 남은 제출 화면으로 복귀한다. 두 자료를 추가했을 때도 유지됨을 확인했다.

**느낌:** ‘그만두기’는 지금까지 한 선택을 취소하거나 사건을 포기하는 말처럼 읽힌다. 내가 고른 자료를 보존하려면 X로 나가야 하는지, 별도 완료 버튼이 있는지 찾게 된다. 실제로는 정상 기능이지만 처음 사용하는 사람에게 불필요한 불안을 준다.

**개선:** 자료를 고르는 문맥에서는 ‘선택 마치기’ 또는 ‘선택한 자료로 돌아가기’로 표시한다. 선택한 개수를 함께 보여 준다. 선택을 비우는 행동이 필요하면 별도 ‘선택 비우기’로 분리한다. 새로운 확인 팝업은 필수로 추가하지 않는다.

**확인 기준:** 0개·1개·여러 개 선택 후 복귀했을 때 문구가 결과와 맞고, 선택 유지 여부를 사용자가 설명할 수 있어야 한다. X와 하단 버튼의 결과도 일관되게 한다.

### U02 · ‘논리를 연결한다’의 즉시 판정과 기회 차감이 예상과 다르다 — P1

**재현:** 초대 편지와 초소 처리 명단을 선택 → 그만두기 → 논리를 연결한다. 곧바로 “맞는 것도 있소. 하지만 그것만으로는…”이라는 판정 대사가 나온다. 다시 제시 화면을 열면 남은 기회가 4/5다. 이후 다른 불충분한 조합에서도 기회가 줄었다.

**느낌:** 문구만 보면 연결 관계를 만드는 다음 단계가 열릴 듯하다. 실제 동작은 완성된 답을 제출하는 것이다. 선택 작업과 채점 작업의 경계가 흐리다. 초반 학습 중 실수의 비용을 이해하기 전에 기회를 쓴다.

**개선:** ‘이 자료로 주장하기’ 또는 ‘선택한 근거 제출’처럼 확정 동작임을 밝힌다. 바로 옆에 “잘못된 제출은 기회를 1회 사용합니다”라는 짧은 규칙을 최초 제시에 보여 준다. 선택·추가·빼기는 무료라는 점도 문맥상 알 수 있게 한다. 기존의 확인창 없는 빠른 조작을 유지할 수 있다.

**확인 기준:** 실제 제출과 단순 편집이 시각적으로 구분되고, 기회 차감은 제출 때만 발생한다. 실패 직후 감소한 수치가 보이거나 짧은 결과 표시가 남아, 재진입해야 차감을 알게 되는 일을 줄인다.

![16-combine](library-file:fde1_bGliZmlsZV85LUhrX2NCVklBcjlBcmxBOHluNVBB_FileDrive_b43f6d0c624c8191af129cece4e66aa5)

처음 열린 화면에는 남은 기회 5/5가 있으나 어떤 동작에서 줄어드는지 설명은 없다.

![26-proof-retry](library-file:fde1_bGliZmlsZV9vdWxEbUJDYUN2TG1uSGVmSmNEMkhB_FileDrive_b43f6d0c624c8191af129cece4e66aa5)

첫 실패 뒤 다시 들어간 화면은 4/5다. 초대 편지가 빠지고 처리 명단이 남은 상태도 확인된다. 자동으로 남긴 자료의 의미를 설명하면 더 이해하기 쉽다.

### U03 · 필수 조사 대상과 실패 피드백 사이의 연결이 약하다 — P1

**재현과 근거:** 돌목과 대화하고 창구의 방문 신청 원본을 조사했지만 게시판은 놓쳤다. 초대 편지+처리 명단, 원본+처리 명단을 제출했고, 비교·숙소 확인 대화를 본 뒤에도 원본+처리 명단은 실패했다. ‘힌트를 생각한다’는 “자료를 다시 살펴볼까?”라는 말로 끝났다. 게시판의 겨울철 입장 규칙을 확보해 원본·명단·규칙 세 자료를 제출하자 성공했다.

**해석:** 필요한 규칙을 읽어야 한다는 논리 자체는 납득된다. 문제는 내가 가진 자료를 잘못 읽었는지, 별도 문서가 남았는지 알 수 없는 상태에서 같은 피드백을 받았다는 점이다. 이것은 확인된 진행 불가가 아니라 **초반 이탈 위험이 큰 사용성 문제**다. 비교·숙소 대화를 반드시 해야 통과한다고 이 보고서에서 단정하지 않는다.

**개선:** 정답 대상에 화살표나 돋보기를 붙이기보다, 첫 현장 진입 때 “사람뿐 아니라 놓인 물건과 붙은 글도 직접 살펴볼 수 있다”는 조작 원칙을 한 번만 알려 준다. 실패 피드백은 ‘사실 증명’과 ‘그 사실로 입장할 수 있는 규칙’의 차이를 질문 형태로 짚는다. 예: “두 사람이라는 건 적혀 있다. 함께 들어갈 수 있다는 기준은 어디에 있을까?” 정답 자료명이나 클릭 위치는 직접 말하지 않는다.

**확인 기준:** 신규 테스트 참여자가 공략 없이 조사 가능한 대상을 발견하고, 실패 후 다음에 확인할 정보의 종류를 말할 수 있어야 한다. 완료 시간만 보지 말고 같은 조합 재제출 횟수와 힌트 후 행동 변화를 기록한다.

### U04 · 휴대폰에서 가로 회전만으로 조작 크기 문제가 모두 해결되지 않는다 — P1

**직접 확인:** 390×844 세로 화면은 중앙의 약 390×219 게임 영역으로 축소되고 상하 여백이 크다. “휴대폰을 가로로 돌리면…” 안내는 실제로 나온다. 844×390 가로에서는 읽을 수 있지만 질문 행이 내부 좌표 64px → 실제 화면 약 34.7px로 줄어든다. 하단 80px 버튼은 약 43.3px다. 설정의 52px 버튼은 약 28.2px다. 계산은 390/720 배율 기준이며 실물 기기의 물리적 크기를 측정한 것은 아니다.

**느낌:** 부모가 대신 조작하는 환경에서는 버틸 수 있어도 아이가 작은 질문·설정 버튼을 빠르게 누르기에는 여유가 적다. ‘크게’ 설정은 글을 키우지만 설정 버튼의 표시 높이는 여전히 작고 미리보기 일부는 스크롤 아래로 밀린다.

**확인 기준:** 844×390과 더 작은 가로 화면에서 질문·설정·닫기·증거 추가를 손가락으로 재검증한다. 큰 글씨에서 잘림·겹침·숨은 스크롤 여부를 확인한다. 이번 테스트는 화면 크기 모사이므로 실제 오터치율을 주장하지 않는다.

가로 화면: 읽기는 개선되지만 질문과 보조 버튼의 터치 여유는 별도 문제다.

큰 글씨를 켠 가로 설정창. 글자 확대와 조작 영역 확보를 따로 검증해야 한다.

### U05 · 입구 이름표가 인물과 떨어져 있어 잘못 연결해 읽기 쉽다 — P2

**관찰:** 입구에서 다람은 왼쪽 아래에 있지만 이름표는 훨씬 위·오른쪽에 있다. 까로 이름표는 까로의 머리 위 정중앙보다 왼쪽으로 치우쳐 다른 인물의 몸 앞에 놓인다. 돌목·보리 이름표에도 큰 세로 간격이 보인다. 이름표 클릭은 해당 인물로 연결되므로 기능 불능은 아니다.

**느낌:** 처음 만나는 인물이 여러 명일 때 이름을 외우는 부담이 커진다. 이름표와 그림을 번갈아 보고 연결해야 한다.

**개선:** 현장 축소·카메라 변환을 적용한 뒤의 머리 위치를 기준으로 이름표를 배치하고, 혼잡할 때만 최소 간격 보정을 한다. 기본 배치·hover·큰 글씨·모바일에서 같은 인물을 가리켜야 한다. 인물 크기 자체를 임의로 줄일 필요는 없다.

**확인 기준:** 다람·까로·돌목·보리·실룩 이름표를 각각 클릭해 대상을 확인하고, 캡처에서 다른 인물에게 더 가까워 보이는 사례가 없는지 비교한다. 소스 원인은 확인하지 않았으므로 좌표 변환 문제라는 설명은 가설이다.

![10-gate-first](library-file:fde1_bGliZmlsZV9WRjIxTW1oeDIzc2pzaU5HYjJhakRB_FileDrive_b43f6d0c624c8191af129cece4e66aa5)

입구의 이름표와 인물 간 거리. 다람과 까로를 우선 대조할 것.

### U06 · 자료 목록의 이름 생략과 순서 변화가 반복 탐색을 만든다 — P2

**관찰:** 자료 2개일 때도 ‘초소 처리…’가 생략된다. 7개가 된 뒤에는 ‘책상 아래…’, ‘정정된…’, ‘겨울철 입장…’, ‘방문 신청…’처럼 여러 이름이 잘린다. 새 자료가 앞에 들어오면서 기존 자료 위치도 바뀐다. 선택 전에는 전체 이름을 비교하기 어렵다.

**영향:** 대사가 말한 문서 이름과 목록을 대조하기 위해 여러 항목을 눌러야 한다. 자료가 더 많아질 때 비용이 커질 가능성이 있으나, 후반 목록의 실제 성능은 이번에 확인하지 않았다.

**개선:** 두 줄 제목에 필요한 폭을 확보하거나 목록 보기 선택지를 제공한다. 새 자료는 표시하되 안정적인 정렬 정책을 유지한다. 선택한 근거는 작은 체크·개수로 구분하고, 전체 이름을 펼쳐 볼 방법을 준다. 정답 자료를 자동 강조하는 방식은 제안하지 않는다.

**확인 기준:** 2개·7개·후반 대표 개수에서 실제 긴 자료명으로 점검한다. 처음 읽은 사람이 목표 자료를 불필요한 상세 열기 없이 찾는지 본다.

![55-room-evidence](library-file:fde1_bGliZmlsZV9qbFAzb1JhQzVPTEVHTjU4b0dVVmVR_FileDrive_b43f6d0c624c8191af129cece4e66aa5)

7개 자료 목록. 여러 자료명이 생략되고, 이전에 보던 입장 규칙이 상세에 남아 있다.

### U07 · ‘먼저 보여주고, 건넬지는 대화 후 결정’이 자기 비교에도 나온다 — P2

**재현:** 입구의 근거 선택, 13호실의 두 편지 비교 모두 자료 화면 오른쪽에 같은 안내가 나온다. 방에서 두 편지를 나란히 보는 단계에도 ‘보여주기’ 제목과 ‘근거에 추가’ 버튼이 함께 있다.

**느낌:** 자료를 실제 인물에게 넘기는 행동인지, 혼자 고르는 행동인지, 근거 목록만 만드는 행동인지 구분이 어렵다. 제목·안내·버튼이 서로 다른 절차를 설명한다.

**개선:** 상대에게 제시 / 근거 선택 / 자기 자료 비교의 세 문맥에 맞게 제목과 한 줄 안내를 바꾼다. 예: ‘비교할 자료 고르기’, ‘자료를 골라도 아직 제출되지 않습니다’. 실제 인계 여부를 결정하는 안내는 해당 대화에서만 사용한다.

**확인 기준:** 입구·방·일반 인물 제시에서 제목과 안내가 실제 후속 행동을 설명하는지 비교한다. 기능을 복제하기보다 공통 화면에 문맥 값을 전달하는 방향을 우선 검토한다.

### U08 · 비슷한 질문이 중복되고 읽음 표시가 일관되지 않다 — P2

**관찰:** 일반 질문 ‘왜 제 신청이 일꾼으로 됐습니까?’는 읽음 표시가 붙었다. 이후 다음 질문 페이지에 ‘왜 일꾼으로 적혔는지 묻는다’가 같은 읽은 질문과 함께 보였다. 후자는 너울의 지시라는 추가 내용을 주지만, 선택 전에는 무엇이 새로 밝혀질지 구분하기 어렵다. ‘두 종이의 항목을 비교한다’, ‘숙소 확인 칸을 본다’는 실행 후에도 점 표시가 남았다. 마차의 편지 조사도 다시 같은 모습으로 나온다.

**개선:** 반복 실행 가능한 조사와 일회성 대화의 완료 상태를 구분한다. 추가로 열린 질문은 ‘너울이 왜 그렇게 지시했는지 묻는다’처럼 새 질문의 범위를 드러내되, 플레이어가 아직 모르는 사실을 먼저 노출하지 않도록 해금 조건을 함께 검토한다. 선택지 길이 제한도 유지한다.

**확인 기준:** 실제 읽은 항목과 새 항목을 같은 화면에서 구별할 수 있어야 한다. 동일 의미 질문의 두 경로가 의도된 것인지 확인하고, 하나를 없앨 경우 추가 정보가 사라지지 않는지 검사한다.

![31-next-topics](library-file:fde1_bGliZmlsZV9zUWlXNlRFQjFEZmhHeGRsZnVDazF3_FileDrive_b43f6d0c624c8191af129cece4e66aa5)

새 질문과 읽은 질문이 매우 비슷한 내용으로 나란히 있다.

### U09 · 마을 지도는 이동 가능 여부를 설명하지 않는다 — P2

**재현:** 입구 해결 후 지도에서 수리점 그림을 눌렀으나 선택·목적지·안내가 변하지 않았다. 여관은 선택하면 이동 버튼이 활성화됐다. 여관 내부 지도는 13호실을 명확한 목록으로 보여 준다.

**개선:** 지도 분위기는 보존하면서 현재 이동 가능한 장소, 아직 갈 수 없는 장소, 단순 배경을 구분한다. 잠긴 장소를 누르면 스포일러 없는 짧은 상태 안내를 준다. 예: ‘지금은 이곳으로 갈 수 없다’. 기존에 없는 이동을 임의로 해금하자는 제안은 아니다.

**확인 기준:** 클릭 가능한 장소와 장식의 차이를 신규 유저가 이해하고, 잠긴 장소를 눌렀을 때 무반응으로 오해하지 않아야 한다. 현재 위치·선택 위치·이동 확정의 세 상태도 유지한다.

![35-map](library-file:fde1_bGliZmlsZV81T0w3aF9ERzZjOVdXUWZySjVVUFN3_FileDrive_b43f6d0c624c8191af129cece4e66aa5)

예쁜 지도에 여러 장소가 보이지만, 당시 실제 선택 가능한 이동지는 입구와 여관이었다.

### U10 · 13호실에서 주요 진행과 일반 소품 반응의 위계가 약하다 — P2

**관찰:** 방에 들어가면 바로 조사 화면이다. 침대를 눌러야 ‘방은 바깥보다 차가웠다’와 엄마를 찾는 장면이 진행된다. 큰 책상은 여행 필기함을 펼칠 책상이라는 짧은 설명, 수첩은 관찰과 들은 말을 구분한다는 설명을 준다. 핵심 메모는 책상 위 작은 종이에 있다. 보따리를 먼저 누르면 “책상 위 종이부터 보고 열어 보자”라고 알려 준다.

**느낌:** 소품 반응이 많아 방을 만지는 즐거움은 있지만, 처음에는 어떤 클릭이 핵심 흐름인지 알기 어렵다. 큰 가구를 눌러도 일반 설명만 나올 수 있다. 반면 보따리의 선행 조건 안내는 유용했다.

**개선:** 돋보기 표식을 다시 추가하기보다, 최초 입실의 짧은 감정 장면과 자유 조사의 연결을 검토한다. 핵심 종이는 배경 속 위치·대비·클릭 여유를 확인하고, 일반 소품의 짧은 반응은 진행을 방해하지 않는 수준으로 유지한다. 관찰 가능한 물건 자체는 강조할 수 있지만 정답 여부를 표시하지 않는다.

**확인 기준:** 처음 들어온 사람이 엄마를 찾는 맥락을 이해하고, 책상·수첩·종이를 다른 대상으로 인지하는지 본다. 작은 종이의 모바일 터치 영역도 따로 검증한다. ‘그림과 히트박스가 어긋난 버그’는 이번에 입증한 것이 아니다.

방 전체. 큰 책상, 수첩, 작은 종이, 보따리가 각각 다른 반응을 낸다.

**사실:** 소스 options.rpy는 0.20.12, 실행 화면과 저장 슬롯은 0.20.11이다. 이것만으로 배포 사고나 기능 누락을 단정할 수는 없다. 아직 빌드하지 않은 변경일 수도 있다.

**확인 기준:** 최종 검수 대상의 타이틀·저장 슬롯·빌드 기록을 대조하고, 배포 후에는 공개 파일의 SHA까지 확인한다. 이번 작업에서 게임 코드를 수정하거나 배포하지 않았다.

## 7. 실제 유저 체감에 대한 정리

**재미:** 첫 사건은 단순한 서류 문제가 아니라 아이가 함께 들어갈 수 있는가의 문제여서 관심을 유지한다. 다람이 자신의 이름을 요구하는 장면이 특히 좋다. 방에서 가족 그림이 남아 있는 것을 확인하는 장면도 추리와 감정을 연결한다.

**피로:** 같은 의미의 실패 문장과 다시 들어가야 하는 자료 선택 흐름에서 피로가 생긴다. 대사를 더 줄이는 것보다 ‘내가 지금 무엇을 하고 있으며, 어떤 정보가 더 필요한가’를 잘 보이게 하는 편이 우선이다.

**난이도:** 확인한 범위에서는 추리 자체보다 시스템의 자료 수집·제출 규칙을 배우는 난도가 더 크게 느껴졌다. 입구의 규칙 문서를 알고 나면 해결 논리는 명확하다. 두 번째 비교는 목표가 ‘두 편지’로 좁혀져 있어 훨씬 수월했다. 후반까지 쉽거나 어렵다고 일반화하지 않는다.

**부모와 아이가 함께 할 때:** 부모는 글을 읽고 조작을 설명하는 역할, 아이는 인물과 그림 단서를 보는 역할을 자연스럽게 나눌 수 있다. 다만 휴대폰의 작은 버튼과 행정 문서의 표현은 아이 혼자 진행할 때 추가 부담이 될 가능성이 있다. 실제 연령별 테스트로 확인해야 한다.

**시각 품질:** 타이틀·마차·여관의 분위기와 자료 일러스트는 강점이다. 현장 이름표와 선택지 겹침처럼 작은 배치 문제를 정리하면 기존 자산의 장점이 더 잘 보인다. 방의 대사가 ‘기름이 반쯤 남은 등’을 말하는데 침대 옆에는 갓을 씌운 스탠드처럼 보이는 그림이 있어, 소품의 시각적 의미도 한 번 대조하면 좋겠다. 이는 명확한 설정 오류로 확정한 항목은 아니다.

## 8. 다음 작업 순서와 수정 후 테스트

1. **기준 빌드를 고정한다.** 0.20.11 캡처와 0.20.12 소스를 혼동하지 않는다. 이미 수정된 항목부터 제외한다.

2. **제시 흐름 문구를 정리한다.** U01·U02·U07을 묶어 ‘선택 → 완료 → 제출 → 결과’의 의미를 일치시킨다. 새 팝업을 무조건 추가하지 않는다.

3. **첫 현장 학습을 검토한다.** U03·U05·U10을 묶어 인물과 물건을 직접 조사하는 원칙을 전달하고, 실패 뒤 질문이 정보의 빈틈을 가리키게 한다. 정답 위치 표시로 대체하지 않는다.

4. **모바일을 실제 기기로 확인한다.** U04는 픽셀 수 확대만으로 완료 처리하지 않는다. 질문·설정·자료 선택·확정까지 손가락으로 검사한다.

5. **반복 탐색을 정리한다.** U06·U08·U09·U11을 통해 자료 이름, 읽음 상태, 지도 상태, 자연어 출처를 개선한다.

6. **후반은 별도 플레이한다.** 기회 0 실패 경로, 일차 전환, 후기 회의, 서로 다른 결말, 재시작, 캐시·저장 호환을 새 세션으로 확인한다.

수정 후에는 같은 경로만 자동 성공시키는 검사가 아니라, 일부러 게시판을 놓치는 신규 플레이, 틀린 자료 하나를 끼워 넣는 제출, 자료 선택 중 취소·복귀, 큰 글씨에서 긴 제목, 세로→가로 전환, 저장 후 다른 장소로 이동했다가 로드하는 검사를 함께 수행한다.

## 10. 증거와 해석을 사용할 때

캡처는 실제 플레이 화면이다. 과거 보고서의 캡처나 생성 이미지를 대체 사용하지 않았다. 버튼에 잡힌 텍스트·좌표와 대사 상태를 함께 기록했지만, 계측에 나타난 Ren'Py 마크업은 유저 화면의 문자 깨짐으로 취급하지 않았다. 화면 크기를 바꾼 직후 자동 진행 스크립트가 예전 좌표를 눌러 대사가 반복된 구간이 있으며, 이는 테스트 도구의 좌표 문제로 게임 버그 목록에서 제외했다. 진행용 클릭 도중 글자 표시를 먼저 완료한 경우도 있으므로 반복된 로그를 중복 대사 버그로 계산하지 않았다.

이 보고서의 핵심은 ‘게임 전체가 나쁘다’는 판정이 아니다. 이미 좋은 가족 이야기와 분위기를, 처음 온 사람이 조작을 해석하느라 놓치지 않도록 만드는 구체적인 수정 목록이다.
