# Room13 웹 배포 검토 (읽기 전용, 2026-10-17)

대상: `experiments/renpy-ch1/dev/build_web.py`, `preview/room13-dev/*`, 루트 `sw.js`·`index.html`·`manifest.webmanifest`.
확인 방법: 정적 대조 스크립트(전송 파일·매니페스트 sha 재계산), `python3 -m http.server 8799` + Playwright(node, chromium) 시나리오. 끝난 뒤 서버는 껐다.

## 이상 없음으로 확인한 것
- `game-transport.json`: part01 크기·sha와 archive sha 일치. preload 511개 모두 있고 sha 일치. prefetch 51개, 원격(progressive) 274개 모두 실제 파일 있음. 그림 원격 파일의 `_placeholders`가 zip 안에 모두 있음. preload·원격 파일이 core zip에 중복으로 들어가 있지 않음.
- `build-manifest.json` 816개, `pwa_catalog.json` 816개 모두 디스크와 크기·sha 일치. 디스크에 있는데 목록에 없는 파일 없음. `game/` 아래 참조 안 되는 파일 없음.
- zip 안 `.rpy` 211개 모두 `.rpyc`가 같이 있음. saves·cache 없음.
- 정상 로딩(SW 허용): 실패 요청 0, 콘솔 오류 0(WebGL 경고만), 약 15초에 시작. 버전 0.19.6.
- `seed_previous_rpyc`: Ren'Py 8.5.3 `script.py`를 확인했다. `compile` 명령이면 강제 재컴파일하면서 같은 자리의 기존 `.rpyc`에서 `merge_names`로 이름을 이어받는다. 의도대로 동작하는 구조다.

| 높음 | `build_web.py` LOADER `loadGameZip`/`r13Fetch` | 내려받은 part·preload 파일의 sha256를 검사하지 않는다. `sha256`은 `?v=` 캐시 키로만 쓴다. part가 깨지거나 CDN·중간 캐시가 예전 내용을 주면 Ren'Py 안에서 알 수 없는 Python 오류가 나고 멈춘다. 다시 받지도 않는다. | Playwright에서 part01의 2바이트를 뒤집어 전달(`corruptpart`). 화면에 `Unpacking... / Error in sitecustomize / BadZipFile: Bad CRC-32 for file 'game/assets/room13-fullbody-…webp' / ./main: can't open file '//main.py'`가 뜨고 멈춤. | `crypto.subtle.digest('SHA-256')`로 part별(또는 합친 archive) sha와 `bytes`를 확인한다. 다르면 `cache:'reload'`로 한 번 다시 받는다. 그래도 다르면 "새로고침" 안내를 띄운다. preload는 최소한 `bytes`라도 확인한다. |
