## 어떻게 연결했나

- **기존 JSON 은 고치지 않았다.** `room13-pixel-acting.json`·`room13-map-action27.json` 등은 영수증·지문(semantic sha256) 시험이 묶여 있어, 한 칸만 바꿔도 시험 여러 개가 깨진다.
- 대신 교체표 `game/assets/room13-resident-poses-a.json`(자리 53개)을 만들고, 새 층 `game/systems/room13_resident_poses_a.rpy`(init 186, 모든 배치 층 176~182 와 회의 99 뒤)가 같은 spec dict 를 제자리에서 바꾼다. 행·`R13_ACTING`·`CAST` 가 같은 dict 를 가리키므로 기존 배치 함수가 그대로 새 그림을 그린다.
- 함수 덮어쓰기는 `r13_stage_people` 한 층(15층 중 12번째, init 186)뿐이고 할머니 접수대 보정만 한다(※7). `docs/OVERRIDE_MAP.md` 를 `dev/override_map.py --write` 로 갱신했다.
- 지금 자리의 그림이 이미 다른 그림으로 바뀌어 있으면(다른 작업) 그 자리는 건드리지 않는다.
- **발 위치·크기**: 새 그림은 옛 그림을 다시 그린 것이라 몸의 배치가 거의 같다. 옛 그림의 불투명 상자와 새 그림의 불투명 상자를 맞추는 축별 배율로 잘라내기·발·머리·손·가림 다각형(`foreground_parts`)·굴돌의 작업대 접점을 모두 옮겼다. 잘라내기 높이 안에서 몸이 차지하는 비율이 그대로라 화면 키와 발 자리가 같다. 화면 시험에서 옛/새 자리 상자를 비교하니 높이는 모두 같고 너비만 ±12px 안에서 달랐다(새 그림의 실제 몸 폭).
- **클릭 영역**: 잘라내기를 옛 그림과 같은 비율로 몸에 맞췄으므로 사람 상자가 넓어지지 않았다. 인물 누르기는 기존처럼 그림의 알파로 판정한다(`r13_actor_hit_mask`). 납품 그림의 사방 32px 투명 여백은 출력 그림에서 잘려 나갔다.
- **그리기 방식**: 고해상도 원화(`investigation-canonical-*`, 1024×1536)와 같은 `native_detail` 경로로 그린다. 픽셀 격자로 다시 거칠게 만들지 않는다.
- **파일**: `game/assets/resident-poses-a/*.webp` 46개(12MB). `dev/import_art.py` 와 같은 WebP q95 + 무손실 알파. 납품 원본(WebP·설명서·출처표, PNG·스크립트 제외)은 `art/resident-poses-a-20261024/intake/`(48MB)에 보관.
- 생사·떠남 걸러내기, 사건 표시 우선, 일정은 기존 층이 먼저 정하고 이 층은 그림만 바꾸므로 그대로다.

## 남은 일

- 확인 필요 8장: 마차 다람(표정 여러 장 중 하나만 있음), 1:1 대화 동작 7장(대화 표정 그림과 테두리 차이). 대화 그림 B안 묶음과 함께 정할지 소유자 확인이 필요하다.
- 쓸 자리 없음 2장: 피코 이젤(새 시안), 보리 회의 착석(쓰는 자리 없음). 새 자리를 만들려면 소유자 합의가 먼저다.
- 화면으로 직접 본 그림: 은호·무쇠·등지기·톡·나비·까로·할머니·따닥·여니·부엉이·종종(분류)·모모·아이 셋·회의 착석 다섯·슬링·부리·설·현이·도토 둘. 아직 눈으로 안 본 것: 강(꽉·물결), 숲(칼바람), 광장 저녁(바둑), 상점(뭉치), 학교(선생님), 여관 오전(누비), 토실 보온병, 사서, 보리 장작, 피코, 구슬, 달그락, 굴돌(이 날은 협동 무리 그림이 먼저), 솔방, 실룩, 종종 가방, 밤이·보듬. 그날 조건이 맞지 않거나 사건 표시가 먼저 떠서 이번 캡처에 없다. 같은 층·같은 계산을 타지만 소유자 검토 때 함께 보면 좋다.
