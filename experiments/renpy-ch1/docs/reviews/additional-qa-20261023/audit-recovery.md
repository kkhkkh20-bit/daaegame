# 추가 QA 아침 복구 회귀

## 원문에서 확인한 기준

0.20.11 실제 클릭 보고서가 통과한 것은 확인 취소 뒤 진행 유지, 2일 오전 13호실 복구, 1일 자료 7개 유지, 교환함·쪽지·경과 시간·이동 목표 복원이다. 전체 상태 동일성, 재진행, 수동 저장과 아침 저장 차이는 추가 검사 대상이었다. 생명 소진·후반·엔딩·실물 휴대폰은 이 검사 범위에 포함하지 않는다.

## 소스 검토

`systems/room13_polish3.rpy`의 아침 저장은 첫 자유 조사 시점의 실제 Ren'Py 저장이다. 확인 취소는 화면의 `asking`만 되돌리고 복귀 버튼은 화면만 닫는다. 확정은 이후 아침 목록을 정리한 뒤 `renpy.load`를 호출한다. 같은 회차 token과 같은 분기 id를 함께 확인하므로 다른 회차·버려진 분기의 아침은 목록에서 제외한다. 안내를 별도 저장하지 않고 현재 상태에서 계산하는 구현은 아침 복구 후에도 해당 시점의 안내를 계산한다.

이번 회귀 준비에서는 아침 저장·복구 게임 소스를 수정하지 않았다. 보고서가 통과한 기능에 새로운 구현이 필요하다는 근거는 발견하지 못했다.

## 재사용 검사

- `dev/test_additional_recovery.py`: 실제 아침 저장 함수에 메모리 저장소를 붙여 전체 상태 대체, 자료 유지, 읽기 전용 목록 조회, 동일 아침 덮어쓰기 방지, 수동 저장 시점 복원, 다른 분기 제외를 검사한다. 5개 통과. 이 검사는 Ren'Py 파일 직렬화 검사가 아니다.
- `dev/qa_additional_recovery.py`: 새 게임부터 실제 UI를 클릭해 2일 교환함 조사·도착 쪽지 전달까지 진행한다. 소스 기반으로 정답과 동선을 선택하는 자동 재현이며 신규 사용자 무공략 시험이 아니다. 상태·세이브를 주입하지 않는다. `renpy_exec`는 읽기 전용 계측과 대사 즉시 설정에만 사용한다.
- 브라우저 검사는 취소 전후 `room13` 전체·persistent 아침 메타데이터·목표를 비교하고, 복구 후 초롱·교환함을 다시 진행한다. 교환함 직전 수동 저장을 만든 다음 아침 복구와 수동 불러오기가 서로 다른 기준 시점을 정확히 복원하는지 대조한다.

브라우저 최종 결과는 실행 후 `recovery-report.json`에 버전, 검사 항목, 상태 스냅샷, 오류와 함께 기록한다. 최종 빌드에서 통과 기록을 확인하기 전에는 브라우저 검사를 완료로 세지 않는다.

## 이번 판 실행 결과와 중단 범위

사용자의 즉시 마무리 요청에 따라 긴 브라우저 재진행은 중단했다. 기존0.20.14에서 실제 UI로 새 게임→입구 대조 성공→여관→방 메모 획득까지 도달했으나, 보따리 조사에서 드라이버의 카메라·클릭 영역 계산 제한으로 멈췄다. 이 실행은 아침 복구 통과 증거로 세지 않는다. 복구5개 단위와 소스 검토만 완료했으며 원문의 복구 정상 판정과 구분한다. 복구 게임 로직 수정은 없다.
