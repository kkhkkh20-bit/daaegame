## 1. 범위와 판정 방법

기존 세션을 이어 1일차 밤, 2일차 마을 입구, 광장 초롱, 숲 교환함 조사와 도착 쪽지 전달까지 실제 화면을 클릭해 진행했습니다. 이후 ‘다시 시작할 아침’에서 취소와 2일차 복귀를 각각 실행했습니다. 상태를 강제로 바꾸거나 장면을 건너뛰는 개발자 명령은 사용하지 않았습니다. 버튼 좌표와 상태는 읽기 전용으로 관찰했습니다.

검토한 웹 빌드는 0.20.11이고, 체크아웃한 소스는 ef51b4f154fa87ca9e1704bb8a0335a7bb6034ce / 표기 0.20.12입니다. 따라서 소스 위치는 원인 조사 후보이며, 최신 메인에서 같은 현상이 남아 있는지는 재확인이 필요합니다. 화면 1280×720, Chromium, 글자 크게·대사 즉시 설정입니다. 이번 추가 검토에서 모바일 실기기 검증은 하지 않았습니다.

초롱 대화에서 막힌 뒤 소스의 lamp_rope 조건을 읽었습니다. 그 이후는 순수한 첫 플레이가 아니라 소스 안내를 받은 진행으로 구분합니다. 2일차 우체국 이후, 후반부, 엔딩, 모든 실패 분기, 생명 소진 후 복구는 이번에 확인하지 않았습니다. 지도 스크롤은 사용 중인 클릭 도구에 휠·드래그 지원이 없어 충분히 시험하지 못했습니다. 키 입력이나 클릭만으로 이동하지 못한 결과를 ‘지도 이동 불능 버그’로 판정하지 않습니다.

## 2. 플레이하면서 느낀 점

가족의 목적을 잊지 않게 만드는 대사가 좋습니다. 엄마에게 남겨 둔 과자가 밤 장면에 다시 등장하고, 마차를 부탁하며 ‘두 사람’, 곧이어 ‘아내를 찾으면 세 사람’이라고 정정하는 부분은 장황한 설명 없이 아버지의 마음을 보여 줍니다. 숲에서 아이가 ‘손 좀 놓아’, ‘아파’라고 말하는 장면도 아버지의 조급함을 행동으로 드러냅니다.

초롱이 ‘식량이 없어졌다’와 ‘누가 가져갔는지는 못 봤다’를 분리해서 말하는 점도 좋습니다. 수사 게임이 관찰과 추정을 구분하는 기준을 자연스럽게 가르칩니다. 이 구분은 이후 기록에서도 유지하는 것이 좋겠습니다.

가장 큰 마찰은 이야기의 목표와 화면에서 눌러야 하는 대상 사이의 간격입니다. 이야기는 초롱에게 아내를 물어보게 하지만, 초롱 클릭은 짧은 경고나 ‘물을 게 없다’로 끝납니다. 실제로는 등불을 조사해야 다음 대화가 열립니다. 대사를 기억하고 주변 사물을 찾는 설계 자체는 타당하지만, 막혔을 때 회복할 안내가 약해 추리보다 클릭 대상을 찾는 시간이 길어졌습니다.

## 3. 추가 이슈 및 수정 기준

### A01 · 우선순위 높음 — 초롱에게 가도 목적 대화가 열리지 않는 듯 보임

재현: 2일차 광장 입장 대사를 읽습니다. 초롱의 이름을 누르면 ‘등 아래는 서 있지 마세요. 점검 중이에요.’가 나옵니다. 대화 종료 후 초롱을 다시 누르면 ‘지금은 더 물어볼 게 없겠지.’가 나옵니다. 방의 메모를 확인하고 기록 화면도 열어 보았지만 이 행동만으로 진행되지 않았습니다. 광장 오른쪽 화면의 등불을 직접 누르자 점검 대사와 아내에 관한 본 대화가 이어졌습니다.

관찰: 인물 이름표는 명확한 클릭 대상인데, 필수 행동인 ‘덮개 지지 끈을 잡는다’는 선택 문구가 일반 대화 메뉴에 보이지 않았습니다. 초롱에게 아직 물어볼 핵심 내용이 있는데도 일반적인 대화 소진 문구가 나와 플레이어의 의도를 부정하는 느낌을 줍니다. 진행 불능은 아닙니다.

개선: 초롱을 다시 눌렀을 때 ‘등불 옆 지지 끈을 먼저 잡아 주자’처럼 현재 단계에 맞는 안내를 제공합니다. 등불에 포인터를 올리거나 한 번 누르면 ‘지지 끈’이라는 이름을 보여 주고, 필요하면 짧은 강조 표시를 추가합니다. 수사 정답을 알려 주는 것과 조작 대상을 알려 주는 것을 구분해도 됩니다.

완료 기준: 방의 메모를 보고 초롱을 찾아온 새 플레이어가 코드나 공략 없이 다음 조작을 설명할 수 있어야 합니다. 초롱 반복 클릭으로 대화가 이중 실행되거나 단서가 중복 획득되지 않아야 합니다. 등불 조사 후에는 안내가 다음 목적지로 바뀌어야 합니다.

소스 조사 후보: game/room13_v111_days123.rpy의 r13_v111_lamp_rope → r13_v111_chorong, game/v111/field-bindings.json의 lamp_rope(object: lamp). 현재 소스와 실제 빌드가 다르므로 그대로 수정하기 전에 빌드 일치 여부부터 확인하십시오.

### A02 · 우선순위 높음 — ‘생각’이 현재 막힌 행동을 안내하지 못함

재현: 마을 입구에서 돌아갈 마차가 없다는 대화를 마치고 광장에 옵니다. 초롱과 인사한 뒤 ‘생각’을 엽니다. 표시된 문구는 ‘오늘 마을을 떠날 길이 있을까?’이고 조사 메모의 의문은 0개입니다.

영향: 돌아갈 길이라는 장기 목표는 맞지만, 지금 초롱의 일을 도와야 하는 단계에 도움을 주지 못합니다. 일반 대화도 더 물을 것이 없다고 하므로 서로 다른 안내가 진행을 멈춘 듯한 인상을 줍니다. 의문 0개가 데이터 버그인지는 확인하지 않았습니다. 사용자 관점에서 정보가 부족하다는 판정입니다.

개선: 장기 목표와 당장 할 일을 함께 보여 줍니다. 예를 들어 ‘엄마가 남긴 메모를 초롱에게 확인하자 / 먼저 등불 점검을 도와주자’. 교환함 조사 후에는 ‘우체국에서 초대 편지의 발신인을 확인하자’로 바뀌도록 합니다. 물음표 개수를 새 단서 수와 혼동하지 않도록 의미도 분명히 합니다.

완료 기준: lamp_rope, go_box, box_inspect, box_note, 우체국 이동 단계별로 현재 행동과 목표가 일치해야 합니다. 아침 복귀 후에는 진행 전 안내로 되돌아와야 합니다.

### A03 · 우선순위 보통 — 대화의 목적지 이름과 지도 이름이 연결되지 않음

재현: 초롱이 ‘북쪽 물자 길의 교환함’으로 같이 가자고 말한 뒤 지도를 엽니다. ‘숲·산길’ 탭에서 선택되는 목적지는 ‘깊은 숲’입니다. 이 경로로 실제 교환함에 도착했습니다.

영향: 대사 속 장소와 지도 속 장소가 다르게 표기돼 처음에는 같은 곳인지 확신하기 어렵습니다. 숲에 입장하면 교환함이 화면 오른쪽 끝에 걸려 있고 화살표로 옮겨야 편하게 볼 수 있습니다. 장소와 오브젝트를 찾는 부담이 겹칩니다.

개선: 해당 단계에만 ‘깊은 숲 · 교환함’이라는 보조 표기를 붙이거나 초롱의 대사에 지도 이름을 함께 넣습니다. 지도 선택 정보에 현재 방문 목적을 한 줄 표시해도 좋습니다. 이동 버튼으로 최종 확인하는 현재 구조는 유지할 만합니다.

완료 기준: 대사에서 들은 목적지를 지도에서 확인할 수 있어야 합니다. 이후 다른 목적으로 숲을 방문할 때 오래된 교환함 안내가 남지 않아야 합니다.

### A04 · 우선순위 보통 — 고정 메뉴가 인물과 조사 대상을 가림

재현: 광장 오른쪽 화면 및 깊은 숲 오른쪽 화면을 봅니다. 오른쪽 아래 ‘생각·기록’ 영역이 다람 등 인물의 얼굴·몸 일부와 겹칩니다. 숲 첫 화면에서는 오른쪽 끝 교환함과 초롱 주변이 메뉴와 가까이 겹칩니다.

영향: 이름표와 캐릭터의 대응, 표정 감상, 사물 발견이 어려워집니다. 이번에는 잘못된 클릭이 게임 상태를 변경하는 사례까지 입증하지 않았으므로 클릭 판정 오류로 단정하지 않습니다. 초반 보고서의 인물 배치 문제를 다른 장소에서 재확인한 항목입니다.

개선: 고정 UI 영역을 배치 금지 구역으로 두고 인물 위치와 조사 대상의 기준점을 조정합니다. 메뉴를 잠시 접는 기능을 추가한다면 다시 여는 방법도 분명해야 합니다. 글자 크기 설정별로 이름표와 메뉴 크기를 함께 확인합니다.

완료 기준: 좌우 화면 모두에서 주요 인물 얼굴과 필수 조사 대상의 식별 가능한 부분이 항상 노출되어야 합니다. 1280×720과 모바일 가로 화면에서 확인하고, 메뉴를 눌렀을 때 뒤의 사물 행동이 실행되지 않아야 합니다.

### A05 · 우선순위 보통 / 추가 확인 필요 — 지도 이동 방법과 가려진 목적지의 발견성

관찰: 숲에서 마을 지도로 돌아왔을 때 지도가 북쪽에 초점을 맞춰 열렸고, 우체국 건물의 일부가 하단 고정 패널 뒤로 내려가 있었습니다. 화면에 스크롤·드래그 안내나 명확한 스크롤바가 보이지 않았습니다. 방향키·PageDown 입력으로는 관찰한 화면이 이동하지 않았습니다.

제한: 사용한 클릭 도구에 휠·드래그 기능이 없어 실제 휠과 드래그는 검증하지 못했습니다. 소스의 worldmap viewport에는 draggable/mousewheel 설정이 있습니다. 따라서 우체국에 갈 수 없는 버그라고 보고하지 않습니다.

개선 후보: 첫 지도 열기 때 ‘지도를 드래그해 둘러보세요’를 짧게 표시하거나, 현재 목적지 바로 보기 기능을 제공합니다. 이동 가능한 장소 목록을 보조 수단으로 제공하면 키보드와 작은 화면에도 도움이 됩니다.

확인 기준: 휠·드래그·터치로 우체국을 화면 안으로 옮길 수 있는지, 고정 패널 아래에 숨은 노드가 선택되는지, 지도 이동 중 실수로 장소가 확정되지 않는지를 수동 검증합니다.
