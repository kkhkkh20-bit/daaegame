# 두 구역 탐색 로컬 구현 · 2026-10-20

사전 확인: 저장소에서 `AGENTS.md` 및 관련 `.agents/skills`는 발견되지 않았고 `/workspace/.agents`는 비어 있었다. `README.md`, `ROOM13_GUIDE.md`, `CLAUDE.md`, 실행/검사 스크립트, override 지도와 현행 맵 코드를 읽었다. 이번 사용자 지시의 로컬 작업 한정이 기존 안내의 main/push 기본 규칙보다 우선한다.

기준 커밋 `f3093aed`, 격리 브랜치 `two-zone-exploration`. 이 작업은 미공개 소스 변경이며 `preview/room13-dev`를 수정하지 않았다. 전 맵 원화 제작 완료가 아니다.

## 실제 구현

- 기존 1280×720 뷰포트와 세계 좌표를 재사용. 배경·인물·소품·조사 버튼·이름표가 함께 이동하고 HUD/메뉴는 고정된다. 인물·가구 크기와 기존 배치·리소스는 변경하지 않았다.
- 파노라마 공통 조작을 좌우 끝 버튼으로 바꾸었다. 한 번 누르면 0 또는 `world_width - 1280`까지 0.65초 smoothstep 자동 슬라이드하고 정확히 멈춘다. 자유 드래그/가로 휠은 비활성화했다.
- 이동 중 두 번째 이동/역방향 요청을 버리고 조사·대화·도구 모음·메뉴/롤백을 잠근다. 완료 후 버튼과 클릭 판정을 복구한다. 기존 움직임 끄기/건너뛰기 설정은 애니메이션 없이 끝점으로 이동한다.
- 카메라만 저장한다. 진행 중에는 목적지를 기록하고, 복원 시 기존 애니메이션 객체를 제자리에서 취소하고 끝점에 정렬한다. 예전 중간 좌표는 가까운 끝점으로 정렬한다. 시간·증거·분기·주민 일정은 변경하지 않는다.
- 조사 클릭 보정: 기존 `r13_actor_hit_mask`가 이미 투명 여백 및 가구 가림을 제외한다. 투명 여백 전체가 사각형으로 클릭되는 것으로 단정하지 않았다. 확인된 문제는 `r13_objects_over_actors` 보정 버튼이 주민 버튼 **아래**에 있어 몸통에 가린 물건을 복구하지 못한 순서였다. 이 보정만 주민 뒤에 배치했다. 기존 얼굴 보호/나중 작은 소품 보호 마스크, 인물 이름표 우선순위는 유지했다. 새 조사 모드·목록·확대 UI는 추가하지 않았다.

모든 맵이 2560×720(1280 화면 두 장)보다 좁다. 1800px 맵은 760px, 1920px 맵은 640px, 2160px 맵은 400px가 부족하다. 현재의 두 정지 지점은 **겹치는 두 뷰**이며 공간을 두 배로 늘렸다는 의미가 아니다. 무파노라마 5개는 자동 이동을 억지로 켜지 않았다. `ms14_somi`/`ms14_guardroom`은 기존 입구 장면을 차용하며 독립 구역 배경이 아니다.

입구 원본은 마차·게시판·초소와 길이 이어진 한 장, 시장 원본은 가게·아치·옆 골목이 이어진 한 장이다. 이를 직접 확인했다. 슬라이드에 반복 타일/늘인 가로 그림/생성 시안을 넣지 않았다. 입구와 시장을 하나의 새 연결 원화로 합치지도 않았다.

최종 원화가 필요한 범위: 전 맵 최소 논리 2560×720의 연속 원화, 기존 인물/가구 비율을 유지한 실내 두 벽·바닥 깊이와 실외 건물 앞/옆면·길의 깊이. 오전·오후·저녁 및 복도/13호의 사건 전후 변형도 같은 구조와 좌표를 유지해야 한다. 기존 원화를 통째로 가로 늘이거나 그림을 반복하는 방식은 사용하지 않는다. 원화 확정 후에는 조사 rect/소품 가림/인물 발 위치를 새 공간에 맞춰 별도 검수해야 한다. 이 원화 및 재배치 작업은 미완료다.

## 클릭/모바일 한계

입구 `ledger`는 원래 126×30 논리 px(844×390 가로 화면에서 약 68×16px)이고 `booth`는 110×52px이다. 버튼 이동으로 배경의 작은 물건 자체가 커지지 않는다. 이번에는 지점 확대가 주변 물건·인물을 다시 덮지 않도록 조사 rect 크기를 임의 확장하지 않았다. 작은 지점의 모바일 사용성은 원화/배치 단계의 잔여 검수다. 알파 마스크·z-order 문제와 원화 폭 부족을 구분한다.

## 검증과 재현

- `python3 -m unittest discover -s dev -p 'test_*.py'`: 778개 통과(기존 위치 순서 테스트는 얼굴/이름표 보호를 유지한 새 클릭 순서로 갱신).
- `python3 dev/audit_two_zone_maps.py`: 25개 맵의 원본 치수와 기존 좌표를 읽는 재현 가능한 목록 생성.
- `python3 dev/override_map.py --write`: 함수 위치 문서 갱신; 새 override 층은 추가하지 않았다.
- 저장소 루트 `python3 -m http.server 8765` 후 `ROOM13_QA_OUT=/tmp/two-zone-qa python3 dev/qa_two_zone_camera.py`: 설치된 Chromium과 기존 로컬 Ren'Py 웹 런타임에 변경한 함수/화면 소스를 메모리로 적용하는 실제 렌더러 검사. 소스 파싱·화면 실행까지 하며 공개 빌드를 변경하지 않는다. `renderer-report.json`과 PNG가 해당 실행의 증거다.

렌더러 최종 결과: **통과**. 입구 0→640→0, 시장 0→880 이동에서 중간 좌표를 샘플링했고 전환 중 입력이 비활성화되며 완료 후 정확한 끝점/입력이 복원되었다. 시작·완료의 전체 `room13` 상태와 인물 세계 위치/폭/높이가 동일했다. 입구의 87개 겹침 표본 좌표에서 이전 인물 클릭이 올바른 물건 클릭으로 바뀌었다(예: `(488,541)`에서 까로→길). 844×390 실제 브라우저 터치 입력, 움직임 끄기, 진행 중 저장 목적지 복원 콜백도 통과했다. `gate-left.png`, `gate-right.png`, `gate-return.png`, `gate-mobile.png`, `market-left.png`, `market-right.png`는 실제 렌더러 캡처다. 모바일은 에뮬레이션이며 실기기 검사가 아니다.

미실행: 새 SDK 빌드, SDK lint, 데스크톱 Ren'Py 화면 테스트, 실제 저장 파일의 저장→앱 재시작→로드 및 전체 이야기 회귀, 실기기 모바일, 전체 25개 맵/모든 시간대·사건 상태의 클릭 전수 검사. 저장 복원은 단위 검사와 실제 렌더러의 복원 콜백까지이며 실제 저장 파일 회귀로 확대해 주장하지 않는다.

SDK 차단: `RENPY_SDK_HOME=/tmp/renpy bash dev/setup_sdk.sh`가 `https://www.renpy.org/dl/8.5.3/renpy-8.5.3-sdk.tar.bz2` 다운로드에서 `curl: (56) CONNECT tunnel failed, response 403`으로 실패했다. 다운로드는 완료되지 않았고 재시도/권한 우회하지 않았다. SDK가 없어 새 빌드 및 native lint/화면 테스트는 미실행이다. 기존 저장소 웹 런타임을 사용한 로컬 검사는 별도로 수행했다.

성능: 드래그 지연의 원인은 미확인이다. 검사에서 중간 카메라 좌표·입력 잠금·끝점·상태 불변을 측정했으며 GPU 프레임 시간, 모바일 실기기 지연, 전후 드래그 성능 비교는 측정하지 않았다. 더 빠르다는 보장은 하지 않는다.

원격 push·PR·main 병합·배포·유료 CI·업로드는 하지 않았다. 이번 실행에서 유료 CI를 사용하지 않았으며 이전 실행 포함 $1 잔액은 확인하지 않았다. 메인 배경 얼룩/다람 10종 원화에는 변경이 없다.
