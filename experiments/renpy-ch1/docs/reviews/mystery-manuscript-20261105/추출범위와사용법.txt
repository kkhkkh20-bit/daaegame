기존 본편 대사본 추출 범위와 사용법
기준일: 2026-11-05. 작업 디렉터리 스냅샷이며 게임 제품·원문 JSON을 수정하지 않았다.

파일 구분
- 원문_1-14일_조건분리.txt: 원문 ID와 재생 태그, 날짜·장면·화자·호출 라벨·조건 대체를 보존한 집필 검토 원문.
- 읽기본_1-14일_조건분리.txt: 같은 문장에서 기다림·색·굵기 같은 재생 태그만 숨긴 읽기용. 개작본이 아니다.
- 검토.txt: 1~3일차의 소설 편집 검토 의견. 제품에 적용한 대사와 구별한다.
- 추출정보.json: 기준 커밋, 입력 파일 SHA-256, 집계와 직접 호출 미확인 ID 목록.
- 추출.py: 원문·읽기본·추출정보만 재생성한다. 같은 폴더의 실제진행 대사와 소설식 개작 시안은 건드리지 않는다.

다시 만들기
experiments/renpy-ch1에서:
python3 docs/reviews/mystery-manuscript-20261105/추출.py
게임 소스가 확정된 뒤 한 번 더 실행하면 새 스냅샷에 맞춰 원문·읽기본·입력 해시를 갱신할 수 있다.

반영한 실행 자료
- game/v111/records.json의 본편 정본 중 r13_v111_lines의 직접 문자 ID 호출 2,343개.
- r13_v111_line의 R13_V111_CARRIAGE_TEXT 교체.
- 실행 로더와 같은 17개 overlay: d01~d14, hidden_pandol, hidden_base, lamp_attempt.
- replace의 우선순위·조건 없는 기본값, before/after, 조건 삭제·무조건 삭제, 전체 추가 blocks.
- 직접 r13_lines 목록에 쓴 대사, 등록된 현장 보기와 제목 overlay.
- greetings.json·reactions.json의 기본 인사·자료 반응·후속 질문, 최신 피코 사망 직후 piko_mourning 변형.
- 원문 요구 조건, 호출 라벨·주변 코드 조건, 조건 이름의 코드 식.

추출 도구를 그대로 사용하지 않은 이유
1. dev/dialogue_tool.py export는 .rpy 리터럴과 옛 room13-content/openings JSON이 중심이다. 테스트가 확인하는 대사는 잠금으로 제외하므로 현재 V111 전체 대사본이라고 부를 수 없다.
2. dev/dialogue_day.py show는 dNN의 교체·앞뒤 추가를 합쳐 보지만 정본 순서이며, 조건 대체를 기본 줄과 나란히 보여 준다. 보충 overlay 3개를 별도로 합치지 않는다.
3. dev/story_master.py는 라벨·분기·인물·생사·회의의 정적 제어표다. 대사 전체를 내보내는 도구는 아니다. 이번 추출기는 그 도구의 괄호·이름·조건 파서를 재사용한다.

읽을 때 주의
- 처음부터 끝까지 이어지는 소설이 아니다. 정본 ID 순서와 호출 라벨 묶음이며 실제 한 경로의 재생 순서가 아니다.
- 조건 대체 묶음에서는 위에서 처음 참이 된 한 줄만 재생된다. 생존/사망, 예방/발생, 승리/패배를 이어 읽지 않는다.
- 같은 블록에서 서로 배타적인 when 줄이 있을 수 있다. 조건 이름은 끝의 조건 표와 호출부를 같이 본다.
- 현재 표시하지 않는 정본은 표시 제외로 남기며, 그 앞뒤 추가 줄은 실행될 수 있다. 직접 호출하지 않는 관리·옛 정본을 현재 대사로 섞지 않았다.
- 추가 블록은 간접 호출·예비 블록까지 포함할 수 있다. 도달 가능성을 실행으로 증명하지 않았다.
- 동적 계산 호출 12곳은 미해석 목록으로 남겼다. 날짜 문자열·조건식·상수 표에서 런타임에 조합하는 공통 문구와 모든 UI 설명까지 완전 수록했다고 주장하지 않는다.
- 현장 질문의 동적 추가·필터·반환, 자료 본문의 런타임 변형, 소지·인물 위치·의미 해석은 실행하지 않았다.
- 실제 한 경로는 같은 폴더의 실제진행_1-3일차_피코보호_0.20.95.txt로 별도 확인한다. 원문과 실제 경로를 서로 대신하는 자료로 쓰지 않는다.
