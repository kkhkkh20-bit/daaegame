2. 공통 설계 원칙
기본 진행: 발언·의문 확인 → 현장 조사 → 보유 자료를 읽고 선택 → 근거 제시 → 상대 반응. 화면은 이 사고 흐름을 계속 보조한다.
사용자 화면에는 개발용 게이트·라벨·증거 ID·정답 집합을 표시하지 않는다. 이 문서의 ID는 개발 인계용이다.
항상 읽히는 정보는 현재 확인할 말, 사용자가 선택한 자료, 이번 조작의 효과다. 날짜·장소는 보조 정보로 내린다.
필수 제출 버튼은 화면당 하나다. 자료 추가·빼기·읽기·비교는 제출과 구별하고 기회를 소모하지 않는다.
조작 안내는 구체적으로, 추리 정답은 플레이어가 판단하도록 한다. “돌목에게 서류를 부탁하자”와 “E02·E03·E04가 답이다”를 구분한다.
전체 자료 목록은 이번 회차에 실제 확보한 자료만 사용한다. 정답만 앞에 배치하거나 특정 재사용 자료에 정답성 배지를 붙이지 않는다.
기존의 “나란히 놓기”, 오답 뒤 유효 자료 보존, 출처 펼치기, 단계별 힌트를 재사용한다. 없는 기능처럼 새로 중복 구현하지 않는다.
예방 물건의 숨은 사용처와 미래 결과를 목표 표시·지도·새 질문·정답성 강조로 노출하지 않는다.
큰 배경과 인물은 유지한다. 크림 종이·남색 글자·빨간 주 행동·Pretendard·기존 공통 부품을 사용하고 장식·테두리·모달 수를 늘리지 않는다.
유효 근거 보존과 무차별 전부 제출 방지 규칙은 그대로 유지한다. 정답 개수·내부 허용 상한은 보여 주지 않는다.

5. D02: 전체 자료와 체크 선택
시범 통합 화면의 기본 탭은 “전체”다. 기존 “이번 사건 / 지난 사건 / 사람별”은 선택 가능한 보조 분류로 유지한다. 일반 주민에게 자료를 보여 주는 화면과 옛 캠페인의 기본 동작은 이번 범위에서 일괄 변경하지 않는다.
전체 목록은 현재 회차에서 보유한 자료를 기존 catalog/presentation 적격성에 맞게 뽑는다. 판정 함수의 correct, R13_PROOF_ALTERNATES, R13_PROOF_EXTRAS를 자료 노출·정렬·검색에 사용하지 않는다. 미획득 자료 제목·개수·실루엣도 노출하지 않는다.
전체에서는 제출 가능한 자료가 사건 쪽지 접기 때문에 사라지면 안 된다. 제출 불가한 결과 쪽지는 기존 접기 규칙을 유지할 수 있다. 사람별 분류는 새 사실을 추가하지 않고 기존 출처·기록을 사용한다.
정렬은 실제 획득 순서(최신 먼저), 동률은 기존 목록 순서로 안정화한다. 필터·쪽·상세 전환 중에도 선택 목록은 유지한다. 선택 상태와 정답 여부를 같은 색 체계로 표현하지 않는다.
1차에서 검색창·즐겨찾기·자동 추천·독립 메모장까지 추가하지 않는다. 전체 탭과 체크 선택을 먼저 완성한다. 일반 근거 제시는 정답 개수와 무관하게 선택 수를 제한하지 않는다.

6. D03: 두 자료 비교와 제시 절차
구조 시안 B · 미구현. NPC 해설 전에 두 문서를 읽는다. 1차에서는 새로운 관찰 정답 판정을 추가하지 않는다.
기존 systems/room13_evidence_view.rpy의 r13_evidence_browser는 present=True일 때 live_pair를 None으로 만든다. 이 제약을 시범 workspace 안에서 해소하고, 기존 두 자료 표시 부품을 사용한다. 모든 주민 제시 화면에서 무조건 비교를 켜지 않는다.
읽기용 나란히 보기와 제출할 근거 묶음은 별개다. 일반 proof에서 3개 이상을 골랐더라도 임시로 두 자료를 읽는 동작이 나머지 선택을 버리면 안 된다. 비교할 두 개를 고르는 읽기 상태를 별도로 유지하고 arguments 전체를 덮어쓰지 않는다.
compare 모드에서는 두 자료가 있어야 나란히 보기와 비교 완료를 진행할 수 있다. 3번째 자료를 고르면 자동으로 처음 것을 버리지 않고 교체할 대상을 사용자가 정하게 한다. 일반 proof에는 이 2개 제한을 적용하지 않는다.
두 자료를 펼쳐 읽은 화면에서 “비교 마치기”를 누르면 기존 성공·재시도 판정으로 바로 이어진다. 기존 대조 화면으로 돌아가 다시 제출하게 하지 않는다. 잘못 고른 조합의 처리와 자기 비교의 무벌점 동작은 기존 라벨을 따른다.
첫날 두 편지 기준 기본 목표 조작은 체크 A → 체크 B → 나란히 보기 → 비교 마치기의 4회다. 추가 상세 열기·확대·출처 읽기는 자발적 조작이므로 별도로 센다. 이 목표는 아직 구현하거나 사용자 시험으로 검증한 수치가 아니다.
7. D04: 안전한 조사 복귀와 상태별 안내
미수집 상태에서도 입구 논증을 열 수 있으므로, 잘못 제출해야만 재조사할 수 있는 흐름을 해소한다. 1차의 “조사 계속”은 진행 조건을 우회하는 이동이 아니라 해당 대조를 열기 전의 기존 현장 라벨로 돌아가는 행동이다.
구현 제안: r13_v111_proof 시그니처 끝에 선택 인자 review_return=None을 추가한다. 기존 호출의 위치 인자와 결과 라벨 계약은 유지한다. 새 화면에서 "investigate"가 반환되고 review_return이 지정된 경우 그 라벨을 반환한다. 호출부의 기존 jump expression _return 흐름을 이용한다.
첫날 입구의 review_return은 r13_v111_gate_investigate, 화재 첫 추궁은 r13_v111_bori_witness7로 한정한다. 두 편지 비교는 바깥 이동을 새로 열지 않고 상세·쌍 보기에서 선택 목록으로만 복귀한다. 지정이 없는 다른 쟁점은 기존 종료 규칙을 유지한다.
조사 복귀 시 선택 자료, 남은 기회, wrong 횟수, meeting 결과, checkpoint, 획득 기록을 유지한다. 화면을 닫거나 다시 연 것만으로 시간을 추가하거나 체크포인트·회의를 초기화하지 않는다. 실제 새 조사에 드는 기존 시간은 유지한다.
수집 상태 판정은 가능한 정답 세트 중 하나라도 보유 자료만으로 구성 가능한지로 한다. 예: any(need <= owned for need in r13_v111_proof_sets(key, correct)). 이 결과는 내부 안내 선택에만 쓰고 필요한 자료 이름·정답 수를 화면에 출력하지 않는다.
안내 문맥은 오답 제출 시점에 계산한다. proof 라벨을 return하면 correct 인자가 더 이상 현재 문맥에 없을 수 있으므로, 판정 직전에 {issue: 현재 key, can_solve_from_owned: 계산값} 형태의 표시 보조 문맥을 캡처하고 wrong_queue에서는 issue가 일치할 때만 사용한다. 기존 r13_nw_wrong_pending의 (종류, 문구) 반환 구조는 유지한다. 구 저장에 문맥이 없거나 다르면 “가진 기록과 상대 말을 다시 확인하자” 같은 중립 문구로 폴백한다. 이 표시 보조 값은 정답·보유·기회 판정에 쓰지 않는다.
오답 직후의 대기 안내와 최종 실패 안내 모두 점검한다. r13_nw_wrong_queue, r13_nw_wrong_text, R13_NW_WRONG_FINAL이 미수집 상태에서 “다 있었다”고 말하지 않게 한다. 기존 오답 횟수·차감·실패 분기는 바꾸지 않는다.

8. D05: 현재 할 일과 진행 순서 안내
새로운 대형 퀘스트 목록을 만들지 않는다. 기존 생각 패널과 단계별 목표 표시를 재사용해, 지금 할 수 있는 행동을 한두 문장으로 표현한다. 소스의 실제 gate/scene과 이미 확인한 사실을 기준으로 한다.
초소 예시 흐름: 입장 명단 확인 → 원본 요청 → 원본·규칙을 현장에서 읽기 → 같은 화면에서 자료를 고르고 제시 → 기존 등록 결과. 원본과 규칙의 조사 순서는 기존 코드가 허용하는 범위에서 자유롭게 유지한다.
질문·물건을 눌렀는데 당장 진행할 수 없다면, 반응에 다음 가능한 조작을 포함한다. “지금은 먼저 할 일이 있다”나 “이 일부터 하자”만 단독으로 남기지 않는다. 조작 안내는 현재 진행 조건을 설명하되 반박에 쓸 정답 자료 묶음은 말하지 않는다.
인물에게 아무 질문도 없으면 빈 질문 목록을 열기보다 기존 인사·반응 동작을 사용한다. 읽지 않은 실제 질문이 있는데 빈 목록이 되는 경우만 결함으로 다루고, 모든 NPC에게 새 단서를 만들어 주지 않는다.
선생님 인수 확인과 아이 보호 행동은 삭제하지 않는다. 목표가 인수 확인으로 바뀐 시점과 빨래터에 돌아온 뒤 증인을 확인할 시점을 기존 단계 데이터에 반영한다. 보호 장면의 의미를 유지하면서 안내의 연결을 명료하게 한다.

9. D06: 휴대폰과 시각적 무게
구조 시안 C · 미구현. 844×390에서의 정보 순서 예시. 실제 Ren’Py 배율·터치 검수는 구현 뒤 필요하다.
PC의 세 영역을 휴대폰 화면에 그대로 축소하지 않는다. 휴대폰에서는 발언을 접고 펼치는 상단 영역, 자료 목록 또는 상세를 보여 주는 본문, 항상 같은 자리에 있는 선택·제시 바의 순서로 배치한다.
844×390 가로 화면에서 자료 목록은 두 열까지 허용한다. 공간이 좁거나 큰 글씨 설정이면 한 열로 전환한다. 상세는 본문을 대체하며 모달을 추가로 겹치지 않는다. 상세에서 돌아올 때 스크롤·선택·현재 발언이 유지된다.
나란히 보기에서는 두 자료를 읽을 수 있는 폭을 확보하고 그림 확대를 제공한다. 높이가 부족하면 각 자료의 관찰 영역만 스크롤한다. “비교 마치기/근거 제시” 버튼이 화면 밖으로 밀려나면 안 된다.
터치 목표는 최종 브라우저 표시 크기 기준 최소 44×44 CSS px, 본문은 기본 설정에서 약 16 CSS px 이상을 목표로 한다. Ren’Py 내부 좌표 44px를 그대로 터치 기준으로 쓰지 않는다. 기존 r13_touch_ui와 배율을 반영해 확인한다.
한 종이 바탕과 구획 여백으로 묶고 카드마다 이중 장식판을 두지 않는다. 주 행동만 빨강, 선택 상태는 체크+테두리로 표시한다. 정보가 많은 화면에는 추가 테이프·리본·움직이는 배지를 늘리지 않는다. 색만으로 선택·비활성을 구별하지 않는다.
10. D07: 화재 자료의 현장 관찰도
대상은 V111:E06_FIRE, 표시 제목 “등잔·천·발화 지점”이다. 현재 카드에는 등잔 그림이 크고 위치 관계가 글로만 있다. 기존 그림과 기록은 유지하면서 보조 관찰도를 읽을 수 있게 한다.
관찰도에 넣을 사실은 문 쪽 탄 자국과 기름 냄새 나는 천, 뒷벽 물통 옆 등잔, 닫힌 뚜껑과 남아 있는 기름이다. 현재 사건 현장 배경·조사 영역과 대조해 상대 위치를 표현한다. 글에서 확인되지 않는 정확한 거리·방향·발화 시각은 임의로 만들지 않는다.
관찰도는 사고 원인을 자동 판정하지 않는다. 범인 화살표, “여기가 진짜 발화점” 같은 정답성 색, 특정 증거만 맥동하는 강조를 넣지 않는다. 필요하면 “조사한 범위”와 불확실한 영역을 표시한다.
카드 안의 읽기 전환으로 기존 등잔 그림과 관찰도를 오갈 수 있게 한다. 새 도면을 보았다는 이유로 새 증거·대승리·예방 플래그를 만들지 않는다. 신규 그림이 아직 없으면 기존 그림을 유지하고 미구현으로 보고한다. 가짜 임시 그림을 공개 완료로 처리하지 않는다.
현재 자료 카드 근거. 위의 문·물통·천 위치 관계가 함께 보이지 않는다. 실제 재플레이 캡처.
11. 2차 D08~D09: 플레이어가 발견을 표현하는 순간
이번 1차 범위는 조작을 단순화하고 읽는 기회를 확보한다. NPC가 핵심 차이를 설명하는 구성 자체는 그대로 남는다. 이를 해결하는 후속 관찰·공방은 UI 작업에 몰래 끼워 넣지 않고 별도 시안으로 검토한다.
D08 제안: 올바른 두 문서를 나란히 놓은 뒤 “눈에 띄는 부분을 짚어 본다”로 문서의 끝부분을 직접 표시하게 한다. 모든 관찰 구역은 같은 방식으로 눌러 볼 수 있게 하고 정답 구역만 미리 강조하지 않는다. 다른 곳을 보면 관찰된 사실만 짧게 답하고 기회를 소모하지 않는다. 도움을 요청하면 현재 다람이의 설명으로 이어진다.
D08의 관찰 성공 뒤에는 현재 다람이의 “엄마는 쪽지 끝에 맨날 도토리 그리잖아”라는 가족 기억을 이어 준다. 도토리가 없다는 사실만으로 위조가 확정되는 새 결론은 만들지 않는다. 아빠의 “이 편지를 엄마가 직접 썼는지는 아직 모르겠어”를 보존한다.
D09 제안: E06_FIRE를 낸 뒤 “어떤 관찰 사실을 물을까”를 짧게 표현하게 한다. 문 쪽 흔적과 뒷벽의 등잔 상태를 플레이어가 함께 짚어 “문 앞의 기름 흔적을 설명해 주십시오”라는 질문으로 연결한다. 물증만으로 범행 의도를 확정하지 않고 상대에게 설명을 요구하는 단계로 둔다.
D09에서 누비가 새로 거짓말하거나 강하게 부인하는 대사는 확정하지 않는다. 현재의 배급 동기, 방화 인정, “죽이려고 했다고는 쓰지 마세요”, 아빠가 행동만 기록하는 태도를 유지한다. 새로운 유죄·살해 의도·실패·생사 판정을 추가하지 않는다.
후속 목표는 추가 버튼 수가 아니라 “내가 어느 사실을 문제 삼았는지 표현했다”는 경험이다. 모든 대조에 동일한 관찰 미니게임을 붙이지 않는다. 시범 두 장면만 검증하고 반복·클릭 증가가 크면 채택하지 않는다.

13. 상태·저장·판정의 변경 금지 계약
원래 proof key와 V111 증거 ID, room13["arguments"] 구조를 유지한다. E01/E06(편지 비교), E02/E03/E04(입구), E06_FIRE(화재 첫 추궁)는 내부 기준이며 UI에서 필요한 개수로 노출하지 않는다.
r13_v111_proof_accepts, R13_PROOF_ALTERNATES, R13_PROOF_EXTRAS, r13_v111_proof_kept의 의미를 유지한다. 정답 집합을 UI 단순화 때문에 1개짜리로 줄이지 않는다.
기회는 기존 r13_v111_proof_chances와 r13_nw_retry에서 읽고 차감한다. 회의마다 3회로 하드코딩하지 않는다. 읽기·체크·비교·복귀·빈 제출은 기회를 쓰지 않는다.
오답 횟수, 유효 근거 유지, 무차별 전부 제출 방지, gate_number 예외, 최종 실패 결과를 보존한다. 조사 복귀로 마지막 기회를 리셋할 수 없어야 한다.
일반 proof의 선택 묶음과 임시 읽기 쌍을 분리한다. 읽기 쌍은 순서가 있어도 기존 정답 판정의 집합 의미를 순서 판정으로 바꾸지 않는다.
미획득·다른 회차·숨은 보너스 자료를 부여하거나 노출하지 않는다. all 목록은 정답 함수에서 만들지 않는다.
새 UI 문맥과 화면 변수는 구 저장에서 빠져 있어도 기본값으로 열려야 한다. 기존 save의 arguments, tries, wrong, meeting 결과를 초기화하지 않는다.
탭·페이지·확대 같은 UI 기억은 현재 회차와 모드/쟁점 문맥을 구분한다. 다른 회차나 다른 인물의 선택·제시 대상이 섞이지 않아야 한다. 없는 자료가 기억돼 있으면 UI 선택에서만 정리하고 보유 사실은 건드리지 않는다.
called=True로 연 화면의 X는 호출자에게 Return해야 한다. Hide만 해서 배경만 남고 대기가 끝나지 않는 회귀를 만들지 않는다.
진엔딩·예방·대승리·인물 동기·생사·기존 분기 조건은 이번 UI 개편으로 바꾸지 않는다. 선택지의 문구·순서를 바꾸며 기존 index의 의미가 달라지면 안 된다.

15. 작업 순서와 인계 완료물
1. 현재 HEAD·작업 중 변경·가이드·override map을 확인하고 위 7개 필수 항목의 기존 반영 여부를 대조한다. 실제 파일과 의미가 달라졌으면 그 차이를 작업 기록에 남기고 현재 구조에 맞게 연결한다.
2. D04·D05의 상태 안내와 안전 복귀를 먼저 구현한다. 정답 엔진·기회·저장 계약이 유지되는 것을 확인한다.
3. D01~D03의 통합 화면·전체 자료·나란히 읽기를 첫날 두 장면에 적용한다. D06의 PC·휴대폰 배치로 확인한 뒤 7일차 첫 추궁을 연결한다. D07은 관찰 사실과 실제 현장 그림을 대조해 제작·연결한다.
4. 상태·판정 테스트와 관련 Ren’Py 화면 시험을 실행한다. 저장소의 dev/check.sh, 관련 dev/run_renpy_tests.sh 사례, 필요한 브라우저 조작을 사용한다. 웹 빌드와 화면 시험을 동시에 돌리지 않는다.
5. 원본 변경에 맞춰 가이드의 대사·리터럴·override map·dialogue binding 갱신이 필요한지 확인하고 실행한다. 공개 폴더 preview/room13-dev를 손으로 고치지 않고 dev/build_web.py로 생성한다. 공개·커밋·push는 해당 개발 채팅의 사용자 지시와 저장소 운영 규칙을 따른다.
6. 완료 보고에는 D01~D07 항목별 반영 상태, 실제 변경 파일·심볼, PC·휴대폰 전후 화면, 수행한 T01~T17과 미수행 사유, 구 저장 복원 결과를 넣는다. 미구현 도면이나 미실시 실기 시험을 완료로 적지 않는다.
D08~D09는 후속 시안이다. 첫날 모순을 스스로 알아챘는지, 자료함 조작에서 생각이 끊기는지, 화재 진술을 바꾸는 데 본인이 기여했다고 느꼈는지를 타겟 플레이어와 확인한 뒤 범위를 정한다. 5명 안팎의 형성 평가가 적절한 출발점이지만 통계적 성공률이나 판매 전망으로 해석하지 않는다.
최종 결과의 기준: 현재 발언과 자료를 함께 읽고, 선택을 유지한 채 비교하고, 필요한 경우 현장으로 돌아올 수 있다. 플레이어가 조작 규칙을 추측하느라 수사 내용을 잊는 상황이 줄어야 한다.
