# 실제 화면 픽셀 출력의 범위와 한계

0.19.33, Chromium, DPR=1에서 실제 WASM 장터의 은호 얼굴을 촬영했다. 새 카메라/정수 배율 시스템은 만들지 않았다.

- 입력 WebP의 2×2 격자는 파일 검사로 별도 검증한다.
- 원근 배치는 원본 768 높이를 은호의 경우 160으로 축소한다(160/768≈0.2083). 원본 픽셀이 최종 화면에 일대일 대응하지 않으며, 눈·코·입의 작은 선은 nearest 표본 선택에서 줄어들 수 있다.
- 기존 `r13_pixel_scale`은 축소 결과를 Flatten한 뒤 2배 nearest로 그린다. 1280×720 논리 화면에서는 인물 내부가 2px 셀이고, 홀수 너비는 1px 잘린다(이 사례 요청 너비107 → 실제106). 가구 가림 경계는 별도 다각형이어서 외곽 모든 픽셀이 동일 격자라고 보장하지 않는다.
- 실제 카메라 700→702 이동 후 같은 얼굴 영역(45×43)을 다시 잘라 비교한 결과 RGB 차이는 **0픽셀**이었다. 기존 카메라가 2px 단위로 맞춰지는 이 사례에서는 얼굴 도트 모양이 흔들리지 않았다. 모든 인물·카메라·기기 전체에 대한 보장은 아니다.
- 1024×576 뷰포트에서는 canvas도1024×576, 논리 화면 대비0.8배다. 논리2px 셀은 화면에서1.6px가 되므로 물리 픽셀에 동일 크기로 놓일 수 없다. `face-comparison.png`에서 눈과 외곽선의 표본 형태가 달라지는 것을 확인했다. canvas CSS의 image-rendering은 auto다.

따라서 현재 결과를 모든 화면에서의 “pixel-perfect”라고 부르지 않는다. **원근·얼굴 크기·가구 접점을 유지하고 지도 도트 톤을 맞춘 상태**이며, 분수 뷰포트 축소의 표본 손실은 남는다. 원근을 정수 배율로 강제하거나 전체 지도 스타일을 바꾸지 않았다.

`native.png`, `native-pan.png`, `fractional.png`는 실제 화면, `face-comparison.png`는 그 캡처의 nearest 5배 확대다. 배경을 다시 그리거나 얼굴을 편집한 자료가 아니다. 조사 결과만 기록했고 공개 렌더러 변경은 없다.
