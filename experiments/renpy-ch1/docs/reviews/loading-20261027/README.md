# 웹 로딩창 교체 검토 (2026-10-27)

소유자 지시: "로딩창 이미지 바꿔줘야지 예전 다람탐정 나오잖아. 배경음은 로딩 나올때부터 나와야한다고"

## 바뀐 점

- 로딩 그림: 예전 타이틀(`room13-title-winter020.webp`) 대신 지금 메인화면과 같은 구성
  (엽서 배경 + 로고 + 캐스트 포스터)을 한 장(1280x720)으로 합친 `game/assets/room13-loading-scene.webp` 를 쓴다.
  `dev/make_loading_scene.py` 가 `screens.rpy` `main_menu` 의 세 `add Transform` 줄과 같은 파일·배율·좌표로 합성한다.
  좌표를 바꾸면 두 곳을 같이 고쳐야 한다(`dev/test_update_title_loader.py` 가 대조한다).
- `dev/update_title_loader.py`: 새 그림을 먼저 찾고, 없으면 예전 타이틀로 떨어진다.
- 글꼴: 로딩 안내 줄을 Galmuri(도트) 대신 시스템 고딕(Pretendard 가 있으면 그것)으로 바꿨다. 글꼴 파일을 더 받지 않는다.
- 배경색: letterbox 를 엽서 뒤 남색 천과 같은 `#0a2252` 로 맞췄다.
- 배치: 안내 줄을 진행 막대 바로 위에 아래쪽 기준으로 쌓는다. 세로 휴대폰(가로보다 세로가 길 때)은 글을 그림 위에 얹지 않고
  그림 아래 남색 여백에 둔다.
- 음악 안내: 브라우저가 자동재생을 거부한 동안만 `화면을 한 번 누르면 음악이 켜집니다` 한 줄이 보이고,
  재생이 시작되면 사라진다. 처음부터 허용된 경우(재방문 등)에는 아예 보이지 않는다.

## 캡처

사본(`preview/room13-dev` 의 index.html·목록 파일만)에 `update_title_loader` 를 적용해 Playwright(Chromium)로 찍었다.
엔진(renpy.js)은 사본에 없어 진행 막대는 글만 넣어 자리를 봤다.

| 파일 | 상태 |
|---|---|
| `pc-1-blocked.png` | PC 1280x720, 자동재생 거부 상태(안내 줄 보임) |
| `pc-2-after-tap.png` | 한 번 누른 뒤(안내 줄 사라짐) |
| `phone-1-blocked.png` | 휴대폰 390x844, 자동재생 거부 상태 |
| `phone-2-after-tap.png` | 한 번 누른 뒤 |

겹침 측정(getBoundingClientRect): 1280x720 안내 줄 558~625 / 막대 631~670, 390x844 안내 줄 546~589 / 막대 597~628,
844x390 안내 줄 275~318 / 막대 332~363 — 모두 겹치지 않는다. 콘솔 오류는 file:// 로 열어 생기는 ServiceWorker 등록 거부 하나뿐이고
공개 주소에서는 나지 않는다.

## 자동재생 제한 (사실)

"배경음은 로딩 나올 때부터" 는 코드로 완전히 되지 않는다. Chrome·Safari·Firefox 모두 사용자가 그 페이지를 한 번 누르거나
키를 치기 전에는 소리 있는 `play()` 를 거부한다(자동재생 정책). 헤드리스 Chromium 도 같은 이유로 첫 `play()` 를 거부해
위 캡처가 그 상태다. 예외는 Chrome 이 그 사이트에서 소리를 자주 들었다고 판단했을 때(미디어 참여 지수)뿐이고,
그때는 로딩이 뜨는 순간부터 난다 — 이미 `title-loader-audio.js` 가 첫 줄에서 `play()` 를 시도한다.
그래서 할 수 있는 것은 거부된 동안 "누르면 켜진다" 를 알려 주는 것까지다. 소리 없는 영상·무음 트랙 같은 우회는
정책상 소리를 내지 못하므로 쓰지 않았다.
