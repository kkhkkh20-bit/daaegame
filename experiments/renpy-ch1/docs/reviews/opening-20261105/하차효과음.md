# 마차 하차 효과음 확인

## 원인

- `room13_arrival.rpy`는 즉시 반환하는 도착 연출 라벨이며 현재 소리를 재생하지 않는다.
- 옛 `carStop` 정지 소리는 이미 사용하지 않게 돼 있었지만, `v111/newworld/d01.json`의 하차 대사 `MS14_D01_S02_L0002`에는 `fx: jolt`가 남아 있었다.
- 이 대사 속성은 `r13_ep_line_art` → `r13_impact('jolt')`를 거쳐 `sfx-present.wav`를 `scene_fx` 채널에서 재생했다. 점프·착지라는 파일 이름으로 직접 연결된 소리가 아니라, 대사에 붙은 일반 충격 효과음이었다.
- 몸 반응(`r13_react`)은 예전 합성 반응음을 이미 제거한 상태이고, `winter_carriage`에서 입구로 넘어가는 이동음도 `r13_sound_move`가 `None`을 돌려준다.

## 현재 공유 코드의 조치

- 하차 대사의 `fx: jolt` 속성을 제거해 하차 대사 자체는 그대로 두고 충격 소리 호출을 없앴다.
- 메인이 관리하는 `r13_carriage_finish`는 하차 때 `carriage_ride`, `carriage_hooves`, `scene_fx`, `sound` 네 채널을 잔향 없이 종료한다. 타이핑을 허용하고 BGM·환경음·타이핑 채널은 종료하지 않는다.
- 주행 시작의 바퀴/말발굽 소리, 일반 대사 타이핑, 다른 장면의 놀람·반박·문·눈길 효과음은 유지한다. 공통 소리 함수나 도착 함수를 전역 무음으로 바꾸지 않았다.

이 담당은 게임 파일을 직접 수정하지 않았다. `d01.json`은 날짜 담당, `room13_carriage_direction.rpy`는 메인의 소유 변경을 독립 확인했다.

## 단위 검증

`PYTHONPATH=dev python -m unittest test_carriage_arrival_audio`: 4개 통과.

- 실제 하차 packet을 정상/건너뛰기와 움직임 켜기/끄기의 네 조합에서 충격 dispatcher로 전달: 하차 효과음 재생과 impact log 없음.
- 하차 외 일반 `jolt` packet: 움직임 설정과 관계없이 기존 효과음 재생을 유지.
- 마차→입구 이동음 없음.
- 실제 마차 종료 함수: 주행 채널 종료, 타이핑 복구, BGM·환경음·타이핑 채널 유지, 새 효과음 재생 없음.

별도로 이미 존재하는 `dev/test_carriage_disembark_audio.py`와 일부 목적이 겹친다. 그 시험은 하위 `r13_ep_line_art`의 직접 sfx 연결과 다른 장소 이동음까지 검사한다. 메인이 단위 파일 중복을 정리할 수 있다. 이 담당의 신규 시험은 네 설정 조합을 추가 확인한 독립 검사다.

실제 런타임 화면/오디오와 빌드는 메인이 일괄 확인한다. 위 결과는 코드 경로와 재생 호출 검증이며 실제 기기에서 청취한 결과로 보고하지 않는다.
