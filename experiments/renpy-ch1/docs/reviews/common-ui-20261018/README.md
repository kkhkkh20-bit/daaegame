# 공통 UI 부품 적용 검토 — 2026-10-18

사용자 지적: 화면별 네모 크기·불투명도·글씨 수직 위치·아이콘과 글씨 간격이 서로 다르며, 하단 기능의 위계가 일관되지 않았다.

## 완료한 구현

공통 규격은 [UI_COMPONENTS.md](../../design/UI_COMPONENTS.md). `R13_CONTROL`이 배치·크기·타이포그래피를, `R13ControlSurface`가 표면·상태를, `r13_control`이 아이콘과 글씨 조합을 담당한다. 하단은 `r13_footer_control` 하나로 배치한다.

- 같은 하단 줄은 **5칸 모두232px**. 보통64px, 큰 글씨80px. 간격16px, 밑변704px, 아래 여백16px.
- 글씨22/24, 아이콘28, 간격10, 내용 전체를 가로·세로 중앙 정렬한다.
- 모든 버튼은90% 불투명도, 같은 모서리·테두리를 공유한다. 기본/선택/주요/비활성/hover는 색으로 구분한다.
- 조사·일반 대사·주민 대화·회의에 적용했다. 기록은 공통 마지막 칸, 대화의 자료 보여주기는 그 위 같은 크기의 칸이다.
- 대상 이름 안내를 하단 버튼에서 분리했다. 안내 패널을 클릭 가능한 네모처럼 중첩하지 않는다.
- 질문 번호와 본문도 중앙 기준으로 맞추고, 자료 제시 윗줄을 침범하지 않도록 글자 높이와 페이지를 계산한다.
- 더보기는 작은 행으로 압축하지 않고 같은 높이의 2열 버튼으로 구성한다.
- 기존 `r13_antique_button`/`r13_strip_button`을 공통 부품으로 연결했다. 옛 `.75` 글씨 정렬과 작은44px 네모를 큰 클릭 영역 아래에 그리던 적용을 제거했다. 저장 호환을 위한 클래스 이름은 유지한다.
- 대사·발언 카드 아래는 버튼과16px 떨어진다. 큰 글씨에서 카드·피드백·하단이 겹치지 않도록 같은 기준을 사용한다.
- 지도·주변 이동·취침·저녁 할 일도 공통 조작 부품을 사용한다. 종이 기록 화면의 정보 패널과 탭은 역할에 맞는 종이 재질을 유지하며, 공통 글씨 중앙 정렬을 상속한다.

현재 브랜치 `design/investigation-meeting-ui`의 구현본이다. 새 디자인을 공개 main에 배포한 상태는 아니다. main의0.19.40 인물 배치 변경은 병합해 보존했다. 이야기·증거 판정·일정·시간 규칙은 수정하지 않았다.

## 캡처와 검증

실제 Ren’Py8.5.3 웹 빌드를 Chromium에서 실행했다. PC1280×720, 터치844×390·큰 글씨를 사용했다. 실제 휴대폰 하드웨어 검증은 아니다.

- `00-pc-components.png`, `00-mobile-components.png`: 실제 엔진에서 그린 부품표.
- `01`–`05b`: 조사/대화 보기, 대상 선택, 모바일 하단·생각 배치.
- `07`, `09`, `12`, `14`: 회의 듣기와 검토, PC·모바일.
- `07b`: 공통 더보기 메뉴.
- `questions-*`: 질문0/8/12개, 페이지와 실제 대화 화면.

검사는 UI에 한정한 fixture다. 회의는 정본10일차·보유 자료11개로 지정했다. 질문0/8/12개 fixture는 다른 이야기 단계의 제목을 조합한 시각 검사이며, 동시에 전부 해금된다는 뜻이 아니다. 전체 게임 플레이 리뷰를 중복하지 않았다.

자동 검사 결과는 `investigation-meeting-report.json`, `questions-report.json`에 저장한다. 물건 선택만으로 시간이 진행되지 않는지, 명시적 조사로 실제 증거를 얻는지, 자료/기록 취소 후 같은 발언·질문으로 돌아오는지, 읽은 질문 표시와 숫자키·페이지 이동이 동작하는지 확인한다. 하단 버튼의 실제 클릭 영역도232×64/80 및 같은 밑변·겹침 없음으로 검사한다.

개발 중 부품표의 줄바꿈 문자열에서 발생한 웹 실행 오류는 수정했다. 최종 웹 빌드·lint와 실제 실행 결과를 기준으로 검증한다.
